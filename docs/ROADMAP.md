# 로드맵

SlipKit의 현재 개발 단계와 앞으로 진행할 작업을 정리합니다.

완료된 설계의 배경은 [설계 결정 기록](./DECISIONS.md), 현재 기능 요구사항은 [요구사항](./REQUIREMENTS.md), 파일 형식은 [파일 형식 명세](./SPEC.md)를 참고합니다.

최종 갱신: 2026-08-27

## 현재 단계

SlipKit은 핵심 기능 구현을 마치고 첫 공개 전 품질 검토를 진행하고 있습니다.

> [!IMPORTANT]
> `@omdc-slipkit/*` 패키지는 아직 npm 레지스트리에 배포되지 않았습니다.
>
> 현재 파일 스키마는 공개 전 개발 버전인 `0.1.0`입니다. 공개 이후의 호환성 정책과 패키지 버전은 별도로 확정합니다.

| 영역 | 상태 | 현재 작업 |
|---|---|---|
| 핵심 기능 | 완료 | 공개 전 회귀 검증 |
| 사용자 인수 검토 | 완료 | 반영 결과 재확인 완료 (메시지 로케일화 포함) |
| 주요 문서 정리 | 완료 | 비가이드 문서 재검토 완료 |
| 데모 애플리케이션 | 진행 예정 | 현재 API와 사용 흐름에 맞게 재검토 |
| 소스 코드 검토 | 예정 | 가독성, 경계 조건과 오류 처리 검토 |
| 기본설계 문서 | 예정 | 화면·기능·데이터·인터페이스별 설계서 작성 |
| 공개 준비 | 예정 | 전체 검증과 배포 산출물 확인 |
| MCP·AI 연동 | 검토 대기 | 공개 준비 이후 범위 재정의 |

## 완료된 기반 기능

다음 기능은 구현을 완료했으며, 이후 작업에서는 기능 추가보다 정확성과 사용성을 우선해 검토합니다.

### 패키지와 공개 API

- DOM에 의존하지 않는 `@omdc-slipkit/core`
- Lit 기반 `@omdc-slipkit/elements`
- React와 Vue용 얇은 래퍼
- 공통 설정 진입점 `createSlipKit`
- 독립적으로 사용할 수 있는 파싱, 검증, 수식과 전표 조립 API

### 양식과 전표

- JSON 기반 `.slip` 파일 형식
- 양식과 전표 구분
- 전표에 양식 스냅샷 내장
- 파라미터와 목록 하위 필드 정의
- 다중 페이지 양식
- 전표 작성과 발행 후 입력 잠금
- `buildVoucher`를 이용한 전표 조립

### 디자이너

- 텍스트, 이미지, 선, 도형, 필드, 그리드와 바코드 요소
- 요소와 파라미터를 분리한 편집 구조
- 다중 페이지 편집
- 실행 취소와 다시 실행
- 복사와 붙여넣기
- 스냅과 정렬 보조
- 양식 미리보기
- 반복 그리드와 자동 병합
- 파라미터 또는 수식을 사용하는 값 소스

### 수식과 렌더링

- 임의 코드 실행을 사용하지 않는 자체 수식 파서
- 엄격한 값 타입과 명시적 형 변환
- 브라우저 PDF 생성
- 밀리미터 기반 용지 좌표계
- 반복 그리드의 페이지 분할
- PDF에 사용할 폰트의 호스트 공급

### 저장과 파일 보호

- IndexedDB 저장소
- 로컬 파일 저장과 불러오기
- AES-256-GCM 파일 암호화
- 저장소 어댑터의 자동 암호화와 복호화
- 현재 키와 이전 키를 이용한 키 교체

### 언어와 문서

- 한국어, 영어와 일본어 UI (기본 영어)
- 로케일에 따른 오류 메시지 언어 전환 (기본 영어)
- 로케일 언어로 생성되는 동봉 프리셋
- 한국어, 영어와 일본어 사용자 가이드
- 기본 한국어·일본어 렌더링 폰트
- 파일 형식 명세와 JSON Schema

## 다음 작업: 데모 애플리케이션 재검토

문서 정리가 끝나면 동봉 데모가 현재 공개 API와 권장 통합 방식을 올바르게 보여 주는지 검토합니다.

대상은 다음과 같습니다.

- 기본 Web Component 데모
- React 데모
- Vue 데모
- `examples/shared`의 공통 구현

### 검토 항목

- `createSlipKit`을 사용하는 공통 설정 방식
- 디자이너, 작성폼과 뷰어의 역할 분리
- 양식 저장과 전표 저장의 구분
- IndexedDB와 로컬 파일 저장 흐름
- 파일 암호화 설정과 샘플 키 경고
- `locale` 설정과 기본 언어(영어) 동작
- 파라미터와 목록 데이터 입력 예시
- `buildVoucher` 사용 예시
- 폰트, 용지와 바코드 후보 공급
- 오류와 비동기 작업 처리
- 프레임워크별 데모의 기능 차이 여부
- 데모 전용 기능과 SlipKit 컴포넌트 기능의 구분
- 불필요하게 복잡하거나 실제 사용을 오해하게 만드는 코드

### 완료 조건

- 세 데모가 같은 핵심 사용 흐름을 제공합니다.
- 데모 코드가 현재 가이드의 예제와 일치합니다.
- 데모 전용 로직이 SlipKit의 기본 기능처럼 보이지 않습니다.
- 사용자가 복사해 실제 애플리케이션에 적용할 수 있는 구조로 정리됩니다.
- 각 데모가 빌드되고 주요 기능을 직접 확인할 수 있습니다.

데모 검토 이후 패키지별 소스 코드를 다시 확인합니다.

새 기능을 늘리기보다 이해하기 어려운 구조, 예외 입력과 실제 사용 중 발생할 수 있는 문제를 찾는 데 집중합니다.

- 수식 파서와 평가기의 경계 조건
- 그리드 확장과 페이지 분할
- 암호화 봉투 검증과 오류 구분

- 불필요한 변환과 깊은 복사

### `elements`

- 디자이너의 상태와 선택 대상 관리

- 빠른 연속 조작과 비동기 작업의 경합
- 모달과 편집 패널의 상태 동기화
- 저장과 불러오기 실패 처리
- 좁은 화면, 확대와 키보드 조작
- 로케일별 문구 길이와 레이아웃
- 이미지와 대용량 데이터 처리

### React와 Vue 래퍼

- Web Component 속성 전달
- 이벤트 등록과 해제
- 객체와 함수 속성의 갱신

- 이미지와 바코드 렌더링 실패
- 미리보기와 최종 PDF의 동작 차이

## 이후 작업: 기본설계 문서 작성

소스 코드 검토가 끝나면 현재 구현과 기존 요구사항·명세·설계 결정을 근거로 기본설계 문서를 작성합니다.

문서의 목적은 소스 코드 작성 방법을 설명하는 것이 아니라, 각 화면과 기능의 입력·처리·분기·출력 및 서로의 관계를 문서만으로 파악할 수 있게 하는 것입니다.

### 문서 구성

하나의 파일에 모든 내용을 모으지 않고 역할과 설계 대상별로 분리합니다.

- 공통 설계: 시스템 개요, 패키지 책임, 용어와 공통 처리
- 화면 설계: 디자이너, 작성폼, 뷰어 및 독립적인 모달·화면 상태
- 기능 설계: 파싱, 검증, 마이그레이션, 수식 평가, 전표 발행, PDF 렌더링, 저장과 암호화
- 데이터 설계: `.slip` 봉투, 양식, 전표, 파라미터와 요소 구조
- 인터페이스 설계: core 공개 API, 저장소 어댑터, Web Component 이벤트와 프레임워크 래퍼
- 오류 설계: 오류 분류, 발생 조건, 표시 방식과 복구 흐름
- 문서 관리: 설계 문서 색인과 요구사항·화면·기능·데이터 간 추적표

화면과 기능은 `SCR-001`, `FNC-001`과 같은 식별자를 부여하고 각각 별도 파일로 작성합니다. 버튼이나 소스 함수마다 나누지 않고 독립적인 목적과 처리 흐름을 가진 단위를 기준으로 분리합니다.

### 개별 설계서 내용

화면 설계서에는 화면 목적, 진입·종료 조건, 구성, 입력·출력 항목, 이벤트, 상태별 표시, 검증, 오류 처리, 화면 전이와 호출 기능을 기록합니다.

기능 설계서에는 기능 목적, 호출 조건, 입력·출력, 사전 조건, 정상·분기·오류 처리 흐름, 데이터 변경, 하위 기능과 관련 화면·데이터·인터페이스를 기록합니다. 처리 흐름은 설명문보다 흐름도, 시퀀스 다이어그램, 상태 전이도와 표를 우선합니다.

### 예상 범위

- 공통 설계 5~8개
- 화면 설계 15~25개
- 기능 설계 20~35개
- 데이터·인터페이스·오류 설계 10~15개
- 문서 색인과 추적표 3~5개

전체 예상 범위는 약 50~80개 파일입니다. 실제 파일 수는 설계 대상 목록을 먼저 작성한 뒤 조정합니다.

### 완료 조건

- 주요 사용자 흐름과 내부 처리 흐름을 소스 코드를 읽지 않고 파악할 수 있습니다.
- 각 화면에서 호출하는 기능과 사용하는 데이터·인터페이스를 추적할 수 있습니다.
- 정상 처리뿐 아니라 주요 분기와 오류 처리도 확인할 수 있습니다.
- 기존 `REQUIREMENTS.md`, `SPEC.md`, `DECISIONS.md` 및 실제 구현과 모순되지 않습니다.
- 문서 색인에서 전체 설계 범위와 작성 상태를 확인할 수 있습니다.

## 보류 항목

현재 공개 범위에는 포함하지 않지만, 필요성이 확인되면 다시 검토합니다.

### 문서 기준 언어를 영어로 전환

가이드와 리포 `README` 같은 다국어 문서의 기준(메인)을 영어판으로 두고, 한국어판과 일본어판을 보조로 두는 계획입니다.

현재는 한국어판을 기준으로 확정한 뒤 영어판과 일본어판을 동기화합니다. 전환하려면 다음을 함께 정해야 하므로, 착수 시 ADR로 확정합니다(ADR-042 개정).

- 파일 이름 구성 — 무접미사 파일을 어느 언어에 줄지(`*.md`를 영어로 바꿀지, `*.ko.md`를 새로 둘지)
- 문서 사이 링크, 언어 전환 링크와 가이드 목차의 갱신 범위
- 문안 확정·동기화 절차의 기준 언어 변경

### 페이지별 소계와 이월

반복 그리드가 여러 페이지로 나뉠 때 페이지별 소계와 다음 페이지 이월 금액을 표시하는 기능입니다.

페이지 분할과 수식 평가 순서에 영향을 주며 현재 양식은 반복 없는 그리드 등으로 우회할 수 있어 보류합니다.

### 동봉 프리셋 확충

기본 제공 양식 종류를 늘리는 작업입니다.

호스트가 자체 프리셋을 공급할 수 있으므로 라이브러리에 많은 업무별 양식을 포함하는 작업은 우선하지 않습니다.

### 캔버스와 PDF의 글꼴 통일

현재 캔버스와 PDF가 서로 다른 글꼴 측정 환경을 사용할 수 있어 같은 너비에서도 줄바꿈 위치가 달라질 수 있습니다.

캔버스에서도 PDF와 같은 폰트를 사용할 수 있게 하면 차이를 줄일 수 있지만, 웹폰트 로딩과 번들 크기에 영향을 주므로 별도 결정이 필요합니다.

### 배경 그라디언트

화면과 PDF에서 같은 결과를 만들 수 있는지 먼저 검증해야 합니다. PDF 변환 계층이 지원하지 않는다면 화면에만 추가하지 않습니다.

## 유지보수 백로그

다음 항목은 공개를 반드시 막는 작업은 아니지만 지속적으로 검토합니다.

- 뷰어와 디자이너의 PDF 미리보기 로직 공통화
- 실행 취소 스냅샷의 전체 바이트 상한
- 패키지 사이 테스트 헬퍼 공통화
- 로컬 파일 선택 취소 감지 개선
- 중복된 편집 모달 진입점 확인
- 대용량 양식과 이미지의 성능 측정
- 키보드 조작과 접근성 개선
- 오류 메시지와 복구 방법 정리

백로그 항목이 실제 사용자 문제나 공개 차단 문제로 확인되면 현재 작업으로 올리고 구체적인 완료 조건을 추가합니다.

## 향후 검토: MCP와 AI 연동

MCP와 AI를 이용해 전표 양식을 생성하거나 수정하는 기능을 장기 방향으로 검토합니다.

현재 확정된 구현 범위나 일정은 없습니다. 기존 편집 기능과 공개 API가 안정된 뒤 다음 사항부터 다시 정의합니다.

- AI가 생성하거나 수정할 수 있는 대상
- MCP 도구의 입력과 출력
- 양식 검증과 오류 복구 방식
- 사용자 확인 없이 허용할 작업의 범위
- 기존 양식 변경 이력과 되돌리기
- 민감한 전표 데이터의 전달 범위
- 호스트 애플리케이션과 AI 서비스의 책임 경계

> [!CAUTION]
> AI 연동은 파일 스키마를 생성할 수 있다는 이유만으로 바로 추가하지 않습니다. 실제 사용 흐름, 사용자의 확인 절차와 데이터 보호 방식을 먼저 결정해야 합니다.

## 로드맵 관리 원칙

- 현재 진행 중인 작업과 다음 작업이 위쪽에서 바로 보이게 유지합니다.
- 완료 작업의 상세 구현 이력은 Git 기록과 ADR에 남깁니다.
- 새로운 설계 쟁점은 결정하기 전에 `OPEN-QUESTIONS.md`에 기록합니다.
- 결정이 확정되면 `DECISIONS.md`와 관련 요구사항을 함께 갱신합니다.
- 기능을 추가할 때는 실제 사용 사례와 완료 조건을 먼저 정의합니다.
- 작업 순서나 범위가 바뀌면 상태와 다음 작업을 갱신합니다.
