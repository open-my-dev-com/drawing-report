# 로드맵 / 세션 인수인계

최종 갱신: 2026-08-23 — **사용자 인수 검토 진행 중**(`fix/user-acceptance-review`). 공개 전 문서 정리와
스키마 버전 0.1.0 재정리(ADR-046)를 했고, 이어서 사용자가 소스 코드 리뷰를 진행한다.

## 현재 상태

v1·v2 기능 작업은 **전부 완료**됐다. 남은 것은 공개 전 인수 검토(아래 「남은 작업」)와 v3다.

- **패키지**: pnpm 모노레포 4종 — `@omdc-slipkit/core`(순수 TS) · `elements`(Lit) · `react` · `vue`.
  `main`이 기준 브랜치, 작업은 [`.claude/rules/branching.md`](../.claude/rules/branching.md) 규칙대로 분기.
- **파일 포맷**: `.slip`(양식·전표 공용). 현재 스키마 **0.1.0**(첫 버전, ADR-046). 요소 9종(텍스트·
  이미지·선·사각형·타원·정다각형·필드·그리드·바코드). 규범 명세는 [SPEC.md](SPEC.md), 상세 Zod 스키마 +
  JSON Schema 동봉, 마이그레이션 계층은 비어 있음(공개된 옛 버전 없음).
- **수식 엔진**: 자체 파서(`eval` 금지)·평가기, 함수 32종, 엄격 타입 + 타입 변환(ADR-044).
- **렌더러**: `.slip` → pdfme 변환 계층(pdfme 외부 비공개, ADR-016), 그리드는 선·사각형·글자로 분해해
  페이지 분할까지 직접 계산(ADR-037). 화면 미리보기가 같은 변환 결과를 써 화면·PDF 불일치가 구조적으로
  불가능(ADR-012).
- **무결성**: JCS 정규화 + SHA-256 해시 + JWS(ES256) 서명·검증. 뷰어는 발행 전표를 로드 시 검증(fail-closed, ADR-043).
- **UI**: `<slip-designer>`(양식 편집기) · `<slip-form>`(전표 작성폼) · `<slip-viewer>`(뷰어). 저장소
  어댑터(IndexedDB·로컬 파일), 폰트·용지 호스트 공급 인터페이스(ADR-040). UI 언어 한·영·일(ADR-028/042).
- **문서**: 가이드 5종 + 리포 README를 한·영·일 3벌로 유지(ADR-042). 데모 앱 동봉(`pnpm demo`·`demo:react`·`demo:vue`).
- **검증 게이트**: `pnpm lint && pnpm -r typecheck && pnpm -r build && pnpm -r test`(커밋 훅이 강제).

기능·화면의 자세한 요구는 [REQUIREMENTS.md](REQUIREMENTS.md), 설계 근거는 [DECISIONS.md](DECISIONS.md)에 있다.

## 남은 작업

### 1. 사용자 인수 검토 (진행 중 — `fix/user-acceptance-review`)

공개 전, 사용자가 직접 검토하며 나온 항목을 이 브랜치에서 처리한다.

- **완료**: 스키마 버전 0.1.0 재정리(ADR-046), 문서 정리(DECISIONS 다이어트·낡은 ADR 제거, ROADMAP·
  REQUIREMENTS·OPEN-QUESTIONS 정리).
- **예정**: 소스 코드 리뷰 — 사용자가 코드를 하나씩 짚으며 질문·수정. 복잡도(가독성)를 우선으로 본다.

앞서 G-48 총괄 리뷰(`chore/repo-final-review-v2`, main 병합 완료)에서 11개 병렬 에이전트로 다관점 코드
리뷰·유저 친화성·버그 찾기를 훑고, 확실한 버그·보안·가독성 항목을 고쳤다(정확성 core 다수, ADR-012 정합,
뷰어 무결성 검증 ADR-043, 가독성 리팩터, 수식 엄격 타입 ADR-044, IndexedDB Blob 최적화 ADR-045, npm 준비,
라이선스 BUSL-1.1 확정). 이번 인수 검토는 그 위에서 사용자가 직접 보는 단계다.

리뷰에서 특히 보는 갈래(예시이며 목록이 아니다): 경계·극단값과 예상 못한 입력(빈 값·음수·소수점·아주 긴
글·이모지·개행) · 조작 순서와 타이밍(빠른 연속 조작, 비동기 엇갈림) · 상태 조합(선택 × 모드 × 페이지 ×
미리보기 × 되돌리기) · 밖에서 들어온 파일(손상·다른 시스템 산출·스키마는 통과하나 내용이 이상한 것) ·
저장소·파일 입출력 실패(용량·취소·권한) · 화면 환경(좁은 창·확대·키보드 조작·로케일) · **화면과 PDF
불일치**(핵심 불변식, ADR-012) · 발행·무결성 우회 경로.

### 3. 유지보수 백로그 (버전 무관)

- **캔버스 줄바꿈 위치**: 안쪽 여백을 맞춰도 줄이 바뀌는 자리가 PDF와 한 낱말쯤 어긋난다 — 캔버스는
  시스템 글꼴, PDF는 Pretendard라 글자 폭이 달라서다. 캔버스에도 같은 글꼴을 웹폰트로 물리면 맞출 수 있으나
  동봉 폰트를 화면용으로도 싣는 결정이 필요하다.
- **배경 그라디언트**(아이디어): PDF 변환 계층이 그릴 수 있는지 확인된 뒤에만 진행 — 화면만 되는 불일치 금지.
- **사소 개선**: 뷰어·디자이너 PDF 미리보기 로직 공용화 · undo 스냅샷 총 바이트 상한 · 테스트 헬퍼 공용화 ·
  `LocalFileStorage` 취소 감지 폴백 · 열 편집 모달 진입점이 두 곳인지 확인·정리.
- **npm 공개 전 체크리스트**: 완료 — 패키지 4종에 `repository`·`publishConfig`·`license`, core `schemas` 서브패스
  export, 루트·패키지별 LICENSE(BUSL-1.1, Licensor JangHyeonho, Change Date 2031-01-01 → Apache-2.0). 동봉 폰트는 OFL 1.1.

## 진행 방식 메모

- 모든 결정은 사용자 Q&A로 확정하며 [DECISIONS.md](DECISIONS.md)에 ADR로 기록하고 REQUIREMENTS.md와 일치하도록 유지한다.
- 새 쟁점은 [OPEN-QUESTIONS.md](OPEN-QUESTIONS.md)에 다음 Q 번호로 추가하고 사용자 확인 전에는 결정처럼 쓰지 않는다.
- **넣기 전에 "왜 필요한가"부터**: 화면에 항목을 더할 때는 쓰는 사람이 그 자리에서 왜 필요로 하는지부터
  답한다. 자리가 비어 보인다고 채우지 않고, 다른 곳에 이미 있는 조작을 겹쳐 두지 않으며, 목록을 보면 아는
  값은 따로 표시하지 않는다. 애매하면 사용자에게 묻는다 (CLAUDE.md 「작업 원칙」).
- **편집 UI 배치**: 항목이 많아지는 편집 기능은 모달 분리를 우선 고려하고, 패널에는 자주 쓰는 빠른 수정만 남긴다.
