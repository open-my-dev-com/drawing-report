      호스트가 자기 시스템에 맞게 조인다. **기본 2MB**(파일에는 ~2.7MB로 들어감). HTML 속성
      `max-image-bytes`로도 준다. react·vue 래퍼에도 노출. 넘치면 얼마까지 되는지·고른 파일이 얼마인지 알려 준다
    - 담는 곳은 **요소 `src`에 직접** — 용량의 실제 지렛대는 중복 제거보다 업로드 상한이고, `assets` 경유는
      디자이너에 없던 계층을 새로 들이는 값에 견줘 이득이 작다. 같은 이미지를 여러 곳에 쓰는 일이 잦아지면
      그때 `assets` 중복 제거를 얹는다
37. `feat/core-file-encryption` — **파일 잠그기** (ADR-009 미이행분): `.slip`은 지금 JSON 그대로라
    편집기로 열면 내용이 다 보인다. 해시·서명은 "고쳐지지 않았음"을 보장할 뿐 내용을 가리지 않는다.
    내용을 암호로 잠가 두는 선택지를 넣는다(끄면 지금과 동일). 열쇠 관리는 호스트 몫이고,
    잠근 파일은 다른 시스템과 그대로 주고받을 수 없다는 점을 SPEC에 적는다.
    착수 시 알고리즘·열쇠 전달 방식·봉투 구조를 ADR로 확정한다
38. `feat/core-table-subtotal` — **쪽마다 소계** (ADR-011 미이행분): 표가 여러 쪽으로 나뉠 때 쪽마다
    그때까지의 합을 아래에 넣는 선택지. 머리행 반복은 이미 되지만 소계는 자리도 계산도 없다.
    **23번 표 렌더러 교체 뒤에 해야 한다** — 지금 엔진으로는 행 사이에 소계 줄을 끼울 수 없다
39. `feat/elements-designer-fonts` — **글꼴 등록 화면** (ADR-012·ADR-021 미이행분): 지금은 호스트가
    코드로 넘겨줘야만 글꼴이 늘어난다. 디자이너에서 글꼴 파일을 직접 올려 등록하고, 올린 글꼴은
    저장소 어댑터를 거쳐 보관해 다음에 열어도 남아 있게 한다(ADR-021이 정한 대로 같은 어댑터 계층).
    어댑터가 지금은 `.slip`만 받으므로 인터페이스 확장 여부를 착수 시 함께 정한다

### G 묶음 마지막 — 일본어 대응 (2026-08-21 확정, 위 항목이 전부 끝난 뒤)

40. `feat/repo-locale-ja` — **일본어 대응** (ADR-028 확장): UI 언어와 문서에 일본어를 더한다.
    **다른 항목이 끝난 뒤 마지막에 한다** — 화면과 문구가 계속 바뀌는 동안 사전을 만들면 계속 뒤따라야 한다.
    - **UI 사전**: `SlipLocale`을 `'ko' | 'en' | 'ja'`로 넓히고 `ja` 사전을 채운다(문구 약 190개).
      뷰어·디자이너·작성폼·저장소 어댑터 오류 문구와 react·vue 래퍼의 `locale` 타입까지 함께 넓힌다
    - **문서**: 가이드 6종(`README`·`core`·`formula`·`types`·`fonts-and-presets`)과 리포 `README`에
      일본어판을 더한다. 지금 한국어·영어 2벌에서 3벌이 되므로 **문서가 어긋나기 쉬워진다** —
      한 벌을 고칠 때 나머지도 함께 고치는 절차를 규칙에 적어 둔다
    - **글꼴이 핵심 걸림돌**: 동봉한 Pretendard는 한글+라틴만 있어 **가나·한자 글리프가 없다** —
      그대로 두면 일본어 전표가 PDF에서 두부(□)로 나온다. 한국어에서 A-2로 해결했던 것과 같은 문제다.
      착수 시 정한다: ⓐ 일본어 글꼴을 동봉하고 `locale="ja"`면 자동으로 불러온다(한국어와 대칭이지만
      **용량이 크다** — 지금 Pretendard 2종이 4.2MB인데 한자까지 담으면 더 커진다. 서브패스로 내보내
      쓰지 않는 호스트 번들에는 안 들어가게 하는 방식은 그대로 쓸 수 있다) ⓑ 동봉하지 않고 호스트가
      `fonts`로 넣게 하고 문서에 명시한다(가벼우나 그냥 쓰면 깨진다). **39번(글꼴 등록 화면)이 있으면
      ⓑ의 불편이 줄어드므로 순서상 그 뒤가 유리하다**
    - **`NUMBER_TO_KOREAN`은 한글 전용**이다. 일본에도 금액을 대자(壱・弐・参…)로 적는 관습이 있으므로
      대응 함수를 넣을지 착수 시 정한다(넣는다면 ADR-017 개정 — 함수 29종이 늘어난다)
    - 수식 포맷의 로케일은 이미 BCP-47 문자열(`RenderOptions.locale`)이라 `ja-JP`가 **코드 변경 없이 된다**
    - 동봉 프리셋(거래명세서·청구서)의 **내용은 한국어 고정**이다. 일본어 양식은 호스트가 `presets`로
      넣는 지금 방침을 그대로 두고 문서에 적는다 — 프리셋을 언어별로 늘리는 건 별도 판단
