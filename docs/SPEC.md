# `.slip` 파일 형식 명세

이 문서는 SlipKit의 `.slip` 파일 형식을 정의하는 공개 규범 명세입니다.

- 문서 상태: **Draft**
- 현재 `schemaVersion`: **`0.1.0`**
- 최종 갱신: 2026-09-02
- 레퍼런스 구현: `@omdc-slipkit/core`
- JSON Schema: `@omdc-slipkit/core/schemas/slip.schema.json`

> [!IMPORTANT]
> `.slip` 파일을 생성하는 외부 시스템은 이 문서와 현재 버전의 JSON Schema를 모두 따라야 합니다.
>
> JSON Schema는 구조를 검증하고, 이 문서는 JSON Schema로 표현하기 어려운 교차 필드 규칙과 렌더링 의미를 정의합니다. 둘이 어긋난다면 문서나 스키마의 결함으로 보고 함께 수정해야 합니다.

## 1. 규범 용어

이 문서에서는 다음 용어를 사용합니다.

| 표현 | 의미 |
| --- | --- |
| 해야 한다 | 규범을 준수하기 위한 필수 조건 |
| 하면 안 된다 | 규범을 준수하기 위해 금지되는 조건 |
| 권장한다 | 상호 운용성과 안정성을 위한 권고 |
| 할 수 있다 | 선택적으로 지원할 수 있는 동작 |

## 2. 파일 적합성

`.slip` 파일의 적합성은 다음 단계로 구분합니다.

| 단계 | 의미 |
| --- | --- |
| JSON 적합성 | UTF-8 JSON 문서로 파싱할 수 있음 |
| 구조 적합성 | 현재 버전의 JSON Schema를 통과함 |
| 의미 적합성 | ID 유일성, 그리드 범위, 발행 규칙 등의 교차 필드 규칙을 통과함 |
| 렌더링 가능성 | 수식, 데이터, 이미지, 바코드와 폰트가 실제로 PDF로 변환될 수 있음 |

구조와 의미 검증에 성공한 파일도 다음과 같은 이유로 렌더링에 실패할 수 있습니다.

- 지원하지 않는 외부 이미지 URL을 사용한 경우
- 수식 문법이나 타입이 올바르지 않은 경우
- 반복 그리드의 값이 객체 배열이 아닌 경우
- 바코드 값이 해당 바코드의 형식에 맞지 않는 경우
- 필요한 글자를 포함한 폰트가 제공되지 않은 경우

`@omdc-slipkit/core`의 `parseSlipFile()`은 JSON 파싱, 버전 처리, 구조 검증과 의미 검증을 수행합니다. PDF 생성 과정에서는 렌더링에 필요한 추가 조건을 검사합니다.

## 3. 파일 개요

일반 `.slip` 파일은 UTF-8로 인코딩된 단일 JSON 문서입니다.

하나의 파일은 다음 중 한 종류를 나타냅니다.

| `kind` | 의미 | 주요 내용 |
| --- | --- | --- |
| `template` | 양식 | 용지, 페이지, 요소, 파라미터와 리소스 |
| `voucher` | 전표 | 작성 당시의 양식 스냅샷, 입력값과 발행 상태 |

권장 MIME 타입은 다음과 같습니다.

```text
application/vnd.slipkit.slip+json
```

MIME 타입은 권장 사항이며 파일 적합성에는 영향을 주지 않습니다.

JSON 객체의 프로퍼티 순서는 의미가 없습니다. 들여쓰기와 줄바꿈도 자유롭게 사용할 수 있습니다.

현재 JSON Schema에 정의되지 않은 프로퍼티를 추가하면 안 됩니다. 새로운 필드가 필요하다면 스키마 버전을 변경해야 합니다.

> [!NOTE]
> 암호화된 봉투는 일반 `.slip` 문서가 아닙니다. 복호화한 내부 데이터가 이 명세를 따라야 합니다.

## 4. 최상위 구조와 버전

모든 일반 `.slip` 파일은 다음 프로퍼티를 가져야 합니다.

| 프로퍼티 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `schemaVersion` | 문자열 | ● | 파일 형식 버전 |
| `kind` | 문자열 | ● | `template` 또는 `voucher` |
| `template` | 객체 | 조건부 | `kind: "template"`일 때 필수 |
| `templateSnapshot` | 객체 | 조건부 | `kind: "voucher"`일 때 필수 |
| `values` | 객체 | 조건부 | `kind: "voucher"`일 때 필수 |
| `issued` | 논리값 | 조건부 | `kind: "voucher"`일 때 필수 |

`schemaVersion`은 `MAJOR.MINOR.PATCH` 형태의 SemVer 문자열이어야 합니다.

현재 버전은 `0.1.0`이며 공개 전 첫 스키마를 나타냅니다.

### 4.1 버전 처리

파일을 읽는 구현은 다음 순서로 버전을 처리해야 합니다.

1. `schemaVersion`의 형식을 확인합니다.
2. 현재 지원 버전과 같으면 그대로 검증합니다.
3. 현재 지원 버전보다 낮으면 등록된 마이그레이션을 순서대로 적용합니다.
4. 마이그레이션 경로가 없으면 파일을 거부합니다.
5. 현재 지원 버전보다 높으면 내용을 임의로 해석하지 않고 파일을 거부합니다.
6. 마이그레이션이 끝난 결과를 현재 스키마로 다시 검증합니다.

파일을 쓰는 구현은 자신이 지원하는 최신 `schemaVersion`으로 저장해야 합니다.

현재 `0.1.0`보다 앞선 공개 버전은 없으므로 기본 마이그레이션 목록은 비어 있습니다.

## 5. 공통 자료형

### 5.1 길이와 좌표

모든 용지 크기, 위치, 요소 크기, 그리드 크기와 테두리 두께는 밀리미터 단위입니다.

좌표계는 용지 왼쪽 위를 원점으로 합니다.

- `x`는 오른쪽으로 증가합니다.
- `y`는 아래쪽으로 증가합니다.
- 요소의 `position.x`와 `position.y`는 `0` 이상이어야 합니다.
- 요소의 `width`와 `height`는 `0` 이상이어야 합니다.
- 용지의 `width`와 `height`는 `0`보다 커야 합니다.
- 그리드 행 높이와 열 너비는 `0`보다 커야 합니다.

요소가 용지 경계를 벗어나는지는 파일 검증에서 제한하지 않습니다. 파일 작성자는 출력할 요소가 의도한 용지 범위 안에 들어가도록 배치하는 것을 권장합니다.

### 5.2 색상

색상은 다음 중 하나의 16진수 문자열이어야 합니다.

| 형식 | 의미 |
| --- | --- |
| `#RRGGBB` | 불투명 RGB 색상 |
| `#RRGGBBAA` | 알파값을 포함한 RGBA 색상 |

16진수 문자의 대소문자는 구분하지 않습니다.

### 5.3 식별자

일반적인 ID와 키는 비어 있지 않은 문자열이어야 합니다.

식별자별 유일성 범위는 다음과 같습니다.

| 식별자 | 유일성 범위 |
| --- | --- |
| 요소 `id` | 양식 본문 전체 |
| 에셋 `id` | `assets` 배열 |
| 페이지 `key` | `pages` 배열 |
| 파라미터 `key` | `parameters` 배열 |
| 하위 필드 `key` | 해당 파라미터의 `fields` 배열 |

수식에서 참조할 파라미터 키와 하위 필드 키는 다음 규칙을 따르는 것을 권장합니다.

- 문자 또는 밑줄로 시작
- 이후에는 문자, 숫자 또는 밑줄 사용
- 한글을 포함한 유니코드 문자 사용 가능
- 공백, 하이픈과 기타 특수문자 사용 불가

파일 스키마는 비어 있지 않은 문자열만 요구하지만, 위 규칙을 따르지 않는 키는 수식에서 직접 참조할 수 없습니다.

### 5.4 날짜와 일시

`meta.createdAt`과 `meta.updatedAt`은 시간대 오프셋이 포함된 ISO 8601 `date-time` 문자열이어야 합니다.

```text
2026-08-25T15:30:00+09:00
2026-08-25T06:30:00Z
```

날짜 파라미터의 값 형식은 파일 구조 검증에서 강제하지 않습니다. 상호 운용을 위해 `YYYY-MM-DD` 형식을 권장합니다.

### 5.5 JSON 값

전표의 `values`와 양식의 `sampleValues`에는 다음 JSON 값만 사용할 수 있습니다.

- 문자열
- 유한한 숫자
- 논리값
- `null`
- JSON 값의 배열
- JSON 값으로 구성된 객체

`undefined`, `NaN`, `Infinity`, 함수, 바이너리 객체와 순환 참조는 JSON 값이 아니므로 사용할 수 없습니다.

## 6. 구조 크기 제한

과도하게 큰 파일이 검증기와 렌더러의 메모리나 스택을 고갈시키지 않도록 다음 제한을 적용합니다.

| 대상 | 최대값 | 검사 시점 |
| --- | ---: | --- |
| 문서의 페이지 수 | 500 | 구조 검증 |
| 페이지당 요소 수 | 2,000 | 구조 검증 |
| 에셋 수 | 1,000 | 구조 검증 |
| 파라미터 수 | 500 | 구조 검증 |
| 그리드 행 수 | 1,000 | 구조 검증 |
| 그리드 열 수 | 100 | 구조 검증 |
| 그리드 셀 수 | 100,000 | 구조 검증 |
| 그리드당 행 구간 수 | 20 | 구조 검증 |
| 고정 페이지의 `itemsPerPage` | 1,000 | 구조 검증 |
| 자동 확장의 `minItems`와 `maxItems` | 100,000 | 구조 검증 |
| 양식 페이지당 출력 페이지 수 | 2,000 | 페이지 계획 |
| 줄간격 `lineHeight` | 10 | 구조 검증 |
| 자간 `characterSpacing` 절대값 | 100pt | 구조 검증 |
| 요소·셀당 조건부 서식 규칙 수 | 20 | 구조 검증 |
| 수식 문자열 길이 | 10,000자 | 수식 파싱 |
| 수식 중첩 깊이 | 100단계 | 수식 파싱 |
| 수식 값의 중첩 깊이 | 256단계 | 수식 평가 |

구조 검증 제한은 `@omdc-slipkit/core`의 `SLIP_LIMITS`에서도 확인할 수 있습니다.

## 7. 리소스 참조

이미지와 에셋의 리소스 참조는 `src` 프로퍼티를 사용합니다.

### 7.1 지원 형식

| 형식 | 예 | 의미 |
| --- | --- | --- |
| HTTP URL | `https://example.com/logo.png` | 외부 리소스 |
| data URI | `data:image/png;base64,iVBOR...` | 파일에 내장된 리소스 |
| 에셋 참조 | `asset://logo` | 같은 양식 본문의 에셋 참조 |

data URI는 다음 구조여야 합니다.

```text
data:<mime-type>;base64,<base64-data>
```

base64 데이터에는 공백이나 줄바꿈을 포함하면 안 됩니다.

### 7.2 외부 URL

외부 HTTP 또는 HTTPS URL은 파일 구조상 허용됩니다. 그러나 SlipKit Core는 네트워크 요청을 수행하지 않으므로 외부 URL을 PDF로 렌더링할 수 없습니다.

외부 URL을 사용하는 시스템은 PDF를 생성하기 전에 호스트에서 이미지를 내려받아 data URI로 변환해야 합니다.

### 7.3 `asset://` 참조

`asset://<id>`는 같은 양식 본문의 `assets` 배열에 존재하는 에셋을 가리켜야 합니다.

```json
{
  "assets": [
    {
      "id": "company-logo",
      "mimeType": "image/png",
      "src": "data:image/png;base64,iVBOR..."
    }
  ]
}
```

이미지 요소에서는 다음과 같이 참조합니다.

```json
{
  "type": "image",
  "id": "logo-image",
  "name": "회사 로고",
  "position": { "x": 10, "y": 10 },
  "width": 40,
  "height": 15,
  "src": "asset://company-logo"
}
```

에셋은 자기 자신을 참조하면 안 됩니다.

현재 PDF 렌더러는 이미지 요소가 참조한 에셋의 `src`가 data URI일 때만 렌더링합니다. 상호 운용 가능한 파일을 생성하려면 에셋 본문에는 다른 `asset://` 참조나 외부 URL이 아니라 data URI를 사용하는 것을 권장합니다.

### 7.4 에셋 항목

에셋 항목은 다음 프로퍼티를 가집니다.

| 프로퍼티 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `id` | 문자열 | ● | 에셋 식별자 |
| `mimeType` | 문자열 | ● | `type/subtype` 형식의 MIME 타입 |
| `src` | 문자열 | ● | 리소스 참조 |

`mimeType`과 data URI의 MIME 타입이 같은지는 구조 검증에서 비교하지 않습니다. 파일 작성자는 두 값을 일치시키는 것을 권장합니다.

## 8. 양식 본문

양식 본문은 양식 파일의 `template`과 전표 파일의 `templateSnapshot`에서 공통으로 사용합니다.

```json
{
  "meta": {
    "title": "거래명세서",
    "createdAt": "2026-08-25T10:00:00+09:00"
  },
  "paper": {
    "width": 210,
    "height": 297,
    "padding": [15, 15, 15, 15]
  },
  "pages": [
    {
      "key": "main",
      "label": "본문",
      "elements": []
    }
  ],
  "assets": [],
  "parameters": [],
  "sampleValues": {}
}
```

### 8.1 양식 본문 프로퍼티

| 프로퍼티 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `meta` | 객체 | ● | 양식 메타데이터 |
| `paper` | 객체 | ● | 용지 크기와 여백 |
| `pages` | 배열 | ● | 한 개 이상의 페이지 |
| `assets` | 배열 | ● | 에셋 목록, 빈 배열 허용 |
| `parameters` | 배열 | — | 파라미터 정의 |
| `sampleValues` | 객체 | — | 디자이너 미리보기용 값 |

### 8.2 메타데이터

| 프로퍼티 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `title` | 문자열 | ● | 비어 있지 않은 양식 제목 |
| `createdAt` | 문자열 | — | 생성 일시 |
| `updatedAt` | 문자열 | — | 최종 수정 일시 |

파일 형식은 `updatedAt`이 `createdAt` 이후인지 검사하지 않습니다.

### 8.3 용지

| 프로퍼티 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `width` | 양수 | ● | 용지 너비(mm) |
| `height` | 양수 | ● | 용지 높이(mm) |
| `padding` | 숫자 4개 배열 | ● | `[top, right, bottom, left]` 여백(mm) |

왼쪽과 오른쪽 여백의 합은 용지 너비보다 작아야 합니다. 위쪽과 아래쪽 여백의 합은 용지 높이보다 작아야 합니다.

### 8.4 페이지

페이지는 다음 프로퍼티를 가집니다.

| 프로퍼티 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `elements` | 배열 | ● | 페이지에 배치된 요소 |
| `key` | 문자열 | — | 페이지의 물리 식별자 |
| `label` | 문자열 | — | 사용자에게 표시할 페이지 이름 |
| `pageNumber` | 객체 | — | 페이지 번호 표시 설정 |
| `flowArea` | 객체 | — | `{ top, bottom }` 흐름 영역의 세로 범위(mm) |

`key`를 지정한다면 양식 본문 안에서 유일해야 합니다.

#### 흐름 영역

흐름 영역은 반복 그리드가 항목을 채우고 페이지를 나누는 세로 범위입니다.

`flowArea`를 생략하면 용지 여백의 위·아래 경계를 사용합니다. `top`은 `bottom`보다 작아야 하고 `bottom`은 용지 높이를 넘을 수 없습니다.

첫 출력 페이지의 반복 그리드는 요소의 `position.y`에서 시작하고, 이어지는 출력 페이지에서는 `flowArea.top`에서 시작합니다.

#### 페이지 번호

| 프로퍼티 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `position` | 열거형 | ● | 페이지 번호 위치 |
| `format` | 문자열 | — | 번호 표시 형식 |
| `fontSize` | 양수 | — | 글자 크기(pt) |

지원 위치는 다음과 같습니다.

- `top-left`
- `top-center`
- `top-right`
- `bottom-left`
- `bottom-center`
- `bottom-right`

`format`에서는 다음 치환자를 사용할 수 있습니다.

| 치환자 | 의미 |
| --- | --- |
| `{n}` | 현재 출력 페이지 번호 |
| `{total}` | 전체 출력 페이지 수 |

`format`을 생략하면 `{n} / {total}`을 사용합니다. `fontSize`를 생략하면 9pt를 사용합니다.

페이지 번호는 반복 그리드의 페이지 분할이 모두 끝난 뒤 전체 출력 페이지를 기준으로 계산합니다. `n`은 양식 페이지마다 다시 시작하지 않습니다.

### 8.5 파라미터

파라미터는 양식에 입력할 데이터의 이름과 종류를 정의합니다.

| 프로퍼티 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `key` | 문자열 | ● | 파일, 수식과 외부 연계에서 사용하는 물리 이름 |
| `label` | 문자열 | — | 화면에 표시할 이름 |
| `valueType` | 문자열 | — | 값 종류 |
| `fields` | 배열 | 조건부 | 목록 항목의 하위 필드 |

지원하는 `valueType`은 다음과 같습니다.

| 값 | 권장되는 전표 값 |
| --- | --- |
| `text` | 문자열 |
| `number` | 숫자 |
| `date` | `YYYY-MM-DD` 문자열 |
| `boolean` | 논리값 |
| `image` | data URI 문자열 또는 빈 값 |
| `list` | 평평한 객체의 배열 |

`valueType`을 생략하면 작성 폼은 해당 파라미터를 텍스트로 취급합니다.

`fields`는 `valueType: "list"`일 때만 사용할 수 있습니다. 하위 필드는 다음 프로퍼티를 가집니다.

| 프로퍼티 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `key` | 문자열 | ● | 목록 항목 안의 키 |
| `label` | 문자열 | — | 화면 표시 이름 |
| `valueType` | 문자열 | — | 하위 필드 값 종류 |

하위 필드에는 다시 `fields`를 정의할 수 없습니다. 목록 항목은 평평한 객체여야 합니다.

```json
{
  "key": "items",
  "label": "품목",
  "valueType": "list",
  "fields": [
    { "key": "name", "label": "품명", "valueType": "text" },
    { "key": "quantity", "label": "수량", "valueType": "number" },
    { "key": "unitPrice", "label": "단가", "valueType": "number" }
  ]
}
```

파라미터 정의는 작성 폼과 디자이너를 위한 데이터 정의입니다. 요소가 `parameters`에 등록되지 않은 키를 참조하는 것도 파일 구조상 허용됩니다.

`parseSlipFile()`은 전표 `values`의 타입이 `valueType`과 일치하는지 전부 교차 검증하지 않습니다. 파일 작성자는 상호 운용을 위해 위 표의 값 형태를 따라야 합니다.

### 8.6 샘플 값

`sampleValues`는 디자이너에서 데이터가 채워진 모습을 확인하기 위한 값입니다.

```json
{
  "sampleValues": {
    "customerName": "한빛상사",
    "items": [
      {
        "name": "복사용지",
        "quantity": 2,
        "unitPrice": 5000
      }
    ]
  }
}
```

`sampleValues`는 양식 본문의 일부이므로 전표의 `templateSnapshot`에도 포함될 수 있습니다. 다만 전표 렌더링에서는 `sampleValues`가 아니라 전표 최상위의 `values`를 사용합니다.

## 9. 요소 공통 구조

SlipKit은 다음 9개 요소 타입을 지원합니다.

| `type` | 의미 |
| --- | --- |
| `text` | 직접 입력한 고정 텍스트 |
| `field` | 전표 값 또는 수식 결과 |
| `image` | 고정 이미지 또는 이미지 파라미터 |
| `barcode` | 바코드 |
| `line` | 선 |
| `rect` | 사각형 |
| `ellipse` | 타원 |
| `polygon` | 정다각형 |
| `grid` | 고정 및 반복 그리드 |

### 9.1 모든 요소의 공통 프로퍼티

| 프로퍼티 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `type` | 문자열 | ● | 요소 종류 |
| `id` | 문자열 | ● | 양식 본문 전체에서 유일한 요소 ID |
| `name` | 문자열 | ● | 요소를 식별하기 위한 이름 |
| `position` | 객체 | ● | `{ x, y }` 위치(mm) |
| `width` | 0 이상의 수 | ●* | 요소 너비(mm) — 그리드 제외 |
| `height` | 0 이상의 수 | ●* | 요소 높이(mm) — 그리드 제외 |
| `group` | 문자열 | — | 요소 그룹 식별자 |
| `pagePlacement` | 객체 | — | 출력 페이지 배치 설정 |

그리드는 `width`와 `height`를 저장하지 않습니다. 그리드의 크기는 열 너비의 합과 행 높이의 합으로 계산합니다.

`group`은 편집기에서 여러 요소를 함께 다루기 위한 메타데이터입니다. 같은 그룹이라는 이유만으로 PDF 렌더링 결과가 달라지지는 않습니다.

#### 출력 페이지 배치

반복 그리드가 출력 페이지를 늘릴 때 다른 요소를 어느 페이지에 어떻게 배치할지 정합니다.

절대 배치는 표시할 출력 페이지를 고릅니다.

```json
{ "mode": "absolute", "pages": "first" }
```

| `pages` | 표시 페이지 |
| --- | --- |
| `all` | 모든 출력 페이지 (기본값) |
| `first` | 첫 출력 페이지 |
| `continuation` | 첫 페이지를 제외한 이어지는 페이지 |
| `non-final` | 마지막 페이지를 제외한 페이지 |
| `last` | 마지막 출력 페이지 |

이어서 배치는 대상 요소의 마지막 출력 조각 아래에 요소를 놓습니다.

```json
{ "mode": "after", "target": "items-grid", "gap": 5 }
```

- `target`은 같은 양식 페이지의 요소 ID여야 하며 `after` 참조가 순환하면 안 됩니다.
- `gap`은 대상의 출력 끝에서 띄울 간격(mm)이며 생략하면 0입니다.
- 남은 흐름 영역에 들어가지 않으면 다음 출력 페이지의 `flowArea.top`으로 넘어갑니다.
- 대상이 절대 배치 요소이면 대상이 마지막으로 표시되는 출력 페이지를 기준으로 배치합니다. 대상이 표시되는 페이지가 없으면(한 페이지 문서의 `continuation` 대상 등) 이 요소도 출력되지 않습니다. 뒤따르는 배치가 출력 페이지 수를 계속 늘려 페이지 수가 확정되지 않으면 계획 오류입니다.
- `pagePlacement`를 생략하면 `{ "mode": "absolute", "pages": "all" }`과 같습니다.

### 9.2 색상과 테두리

텍스트, 필드, 그리드와 그리드 셀은 다음 스타일을 사용할 수 있습니다.

| 프로퍼티 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `backgroundColor` | 색상 | — | 배경색 |
| `fontColor` | 색상 | — | 글자색 |
| `borderColor` | 색상 | — | 테두리색 |
| `borderWidth` | 0 이상의 수 | — | 테두리 두께(mm) |
| `borderStyle` | 문자열 | — | `solid`, `dashed`, `dotted` |

도형에는 각 타입에서 정의한 스타일만 사용할 수 있습니다.

파선과 점선의 렌더링 패턴은 다음과 같습니다.

| 형태 | 선 길이 | 간격 |
| --- | ---: | ---: |
| `dashed` | 2.4mm | 1.2mm |
| `dotted` | 0.4mm | 0.8mm |

파선과 점선은 직선에만 적용합니다. 곡선 테두리를 사용하는 요소는 실선만 지원합니다.

### 9.3 글자 스타일

텍스트, 필드, 그리드와 그리드 셀은 다음 글자 스타일을 사용할 수 있습니다.

| 프로퍼티 | 타입 | 기본값 | 설명 |
| --- | --- | --- | --- |
| `fontName` | 문자열 | 렌더러 대체 폰트 | 글꼴 이름 |
| `fontSize` | 양수 | 10 | 글자 크기(pt) |
| `alignment` | 문자열 | `left` | 가로 정렬 |
| `verticalAlignment` | 문자열 | 요소별 기본값 | `top`, `middle`, `bottom` |
| `bold` | 논리값 | `false` | 굵게 |
| `italic` | 논리값 | `false` | 기울임 |
| `underline` | 논리값 | `false` | 밑줄 |
| `strikethrough` | 논리값 | `false` | 취소선 |
| `lineHeight` | 양수 | 1 | 줄간격 배수 |
| `characterSpacing` | 수 | 0 | 자간(pt) |
| `vertical` | 논리값 | `false` | 세로쓰기 |

텍스트와 필드의 기본 세로 정렬은 `top`입니다. 그리드 셀의 기본 세로 정렬은 `middle`입니다.

`bold`와 `italic`은 제공된 폰트 이름을 기준으로 다음 변형 폰트를 찾습니다.

- `<fontName>-Bold`
- `<fontName>-Italic`
- `<fontName>-BoldItalic`

두 스타일을 함께 지정하면 `BoldItalic`, `Bold`, `Italic`, 기본 폰트 순으로 사용할 수 있는 폰트를 선택합니다. 해당 변형 폰트가 없으면 인위적인 기울기나 굵기를 만들지 않습니다. 지정한 `fontName`이 렌더러에 제공되지 않은 이름이면 대체 폰트를 기준으로 같은 순서를 적용합니다.

`vertical: true`이면 문자를 한 글자씩 세로로 배치합니다. 원문의 줄바꿈 문자는 제거합니다. 여러 세로 열이 필요하면 요소를 나누어야 합니다.

### 9.4 조건부 서식

텍스트 요소, 필드 요소와 그리드 셀은 값에 따라 색과 글자 강조를 바꾸는 조건부 서식 규칙을 가질 수 있습니다.

| 프로퍼티 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `conditionalFormats` | 규칙 배열 | — | 값에 따라 색과 글자 강조를 바꾸는 규칙 목록 |

규칙은 다음 프로퍼티를 가집니다.

| 프로퍼티 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `condition` | 문자열 | ● | 논리값을 반환하는 수식 (§16) |
| `fontColor` | 색상 | — | 조건이 참일 때 적용할 글자색 |
| `backgroundColor` | 색상 | — | 조건이 참일 때 적용할 배경색 |
| `borderColor` | 색상 | — | 조건이 참일 때 적용할 테두리색 |
| `bold` | 논리값 | — | 조건이 참일 때의 굵게. `false`는 기본 서식의 굵게를 끕니다 |
| `italic` | 논리값 | — | 조건이 참일 때의 기울임. `false`는 기본 서식의 기울임을 끕니다 |
| `underline` | 논리값 | — | 조건이 참일 때의 밑줄. `false`는 기본 서식의 밑줄을 끕니다 |
| `strikethrough` | 논리값 | — | 조건이 참일 때의 취소선. `false`는 기본 서식의 취소선을 끕니다 |

- 규칙은 색상 또는 강조 프로퍼티를 하나 이상 지정해야 합니다.
- 기본 서식을 먼저 적용한 뒤, 조건이 참인 규칙을 선언된 순서대로 합성합니다. 여러 규칙이 같은 속성을 바꾸면 뒤에 선언된 규칙의 값을 사용합니다.
- 강조 프로퍼티를 생략하면 기본 서식의 강조를 유지합니다. `bold`와 `italic`은 §9.3의 변형 폰트 규칙을 그대로 따르며, 해당 변형 폰트가 없으면 적용하지 않습니다.
- 조건식에 문법 오류가 있거나 계산 결과가 논리값이 아니면 렌더링 오류입니다. `IF`의 조건과 달리 숫자와 빈 값을 논리값으로 바꾸지 않습니다.
- 조건식 계산이 오류가 되면(값 없음, 타입 불일치 등) 그 조건은 참으로 보지 않고 규칙을 적용하지 않습니다. 값이 비어 있는 양식과 입력 중인 전표는 기본 서식으로 렌더링됩니다.
- 항목 구간 안의 셀에서는 조건식을 반복 항목마다 평가합니다. 셀 수식과 같은 방식으로 항목의 필드를 참조하며, 같은 키가 전표 최상위에도 있다면 반복 항목의 값이 우선합니다. 행 구간 셀의 조건식은 예약 참조(§16.4)도 사용할 수 있습니다. 빈 항목 인스턴스에서는 평가하지 않습니다.
- 자동 병합(§15.7)으로 합쳐진 셀은 병합 묶음의 첫 항목으로 평가한 조건부 서식을 사용합니다.
- 조건부 서식은 색과 글자 강조만 바꿉니다. 위치, 크기, 글꼴, 글자 크기, 표시 여부와 내용은 바꾸지 않습니다.

```json
{
  "type": "field",
  "id": "amount",
  "name": "금액",
  "position": { "x": 140, "y": 60 },
  "width": 50,
  "height": 8,
  "parameter": "amount",
  "conditionalFormats": [
    { "condition": "amount < 0", "fontColor": "#FF0000" }
  ]
}
```

## 10. 텍스트 요소

`text` 요소는 모든 전표에서 동일하게 표시할 고정 문구를 나타냅니다.

| 프로퍼티 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `content` | 문자열 | ● | 표시할 텍스트 |

`content`는 가공하지 않고 그대로 렌더링합니다. `{...}`와 같은 문자를 수식이나 치환 표현식으로 해석하지 않습니다.

```json
{
  "type": "text",
  "id": "document-title",
  "name": "문서 제목",
  "position": { "x": 15, "y": 10 },
  "width": 180,
  "height": 10,
  "content": "거래명세서",
  "fontSize": 18,
  "alignment": "center",
  "bold": true
}
```

## 11. 필드 요소

`field` 요소는 전표 값 또는 수식 결과를 표시합니다.

| 프로퍼티 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `parameter` | 문자열 | 조건부 | 전표 `values`에서 읽을 키 |
| `formula` | 문자열 | 조건부 | 표시 값을 계산할 수식 |

`parameter`와 `formula` 중 정확히 하나만 지정해야 합니다.

```json
{
  "type": "field",
  "id": "customer-name",
  "name": "거래처명",
  "position": { "x": 30, "y": 30 },
  "width": 80,
  "height": 8,
  "parameter": "customerName"
}
```

수식 필드는 다음과 같이 작성합니다.

```json
{
  "type": "field",
  "id": "total-amount",
  "name": "합계금액",
  "position": { "x": 140, "y": 250 },
  "width": 50,
  "height": 8,
  "formula": "FORMAT_NUMBER(SUM(items.amount))",
  "alignment": "right"
}
```

필드의 `formula`가 빈 문자열이거나 공백뿐이면 빈 텍스트로 렌더링합니다. 이는 디자이너에서 수식 입력을 시작한 상태를 허용하기 위한 예외입니다.

## 12. 이미지 요소

`image` 요소는 고정 이미지 또는 전표마다 달라지는 이미지를 표시합니다.

| 프로퍼티 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `src` | 문자열 | 조건부 | 고정 이미지 참조 |
| `parameter` | 문자열 | 조건부 | 전표 `values`에서 이미지 값을 읽을 키 |

`src`와 `parameter` 중 정확히 하나만 지정해야 합니다.

### 12.1 고정 이미지

```json
{
  "type": "image",
  "id": "company-logo",
  "name": "회사 로고",
  "position": { "x": 15, "y": 10 },
  "width": 40,
  "height": 15,
  "src": "asset://logo"
}
```

### 12.2 변동 이미지

```json
{
  "type": "image",
  "id": "approval-signature",
  "name": "승인 서명",
  "position": { "x": 155, "y": 250 },
  "width": 30,
  "height": 15,
  "parameter": "signatureImage"
}
```

변동 이미지 값은 다음 중 하나여야 합니다.

- data URI 문자열
- 빈 문자열
- `null`
- 값 없음

빈 값이면 이미지를 렌더링하지 않고 해당 영역을 비워 둡니다.

문자열이 아닌 값이나 data URI가 아닌 문자열은 렌더링 오류가 됩니다.

## 13. 바코드 요소

`barcode` 요소는 직접 입력한 값, 전표 값 또는 수식 결과를 바코드로 표시합니다.

| 프로퍼티 | 타입 | 필수 | 설명 |

## 15. 그리드 요소

`grid`는 고정 표와 반복 목록을 하나의 구조로 표현하는 유일한 표 요소입니다.

반복 설정이 없으면 고정 그리드로 사용합니다. 반복 설정이 있으면 그리드의 행을 역할별 행 구간으로 나누고, 항목 구간을 목록 항목마다 복제해 출력 페이지에 배치합니다.

### 15.1 그리드 프로퍼티

| 프로퍼티 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `columns` | 배열 | ● | 한 개 이상의 열 정의 |
| `rows` | 배열 | ● | 한 개 이상의 행 정의 |
| `cells` | 배열 | ● | 셀 정의, 빈 배열 허용 |
| `repeat` | 객체 | — | 반복 설정 (§15.5) |
| `overflow` | 문자열 | — | `clip` 또는 `shrink` |

그리드는 `width`와 `height`를 저장하지 않습니다. 그리드의 너비는 열 너비의 합, 높이는 원본 행 높이의 합입니다. 반복 그리드의 출력 높이는 페이지 계획 결과(§15.6)에 따라 출력 페이지마다 달라집니다.

열은 다음 구조를 사용합니다.

```json
{
  "width": 40,
  "autoMerge": false
}
```

| 프로퍼티 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `width` | 양수 | ● | 열 너비(mm) |
| `autoMerge` | 논리값 | — | 반복 항목의 연속된 같은 값을 자동 병합할지 여부 |

행은 다음 구조를 사용합니다.

```json
{
  "height": 8
}
```

### 15.2 셀

셀은 다음 프로퍼티를 가집니다.

| 프로퍼티 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `row` | 0 이상의 정수 | ● | 시작 행 |
| `column` | 0 이상의 정수 | ● | 시작 열 |
| `name` | 문자열 | — | 편집기에서 셀을 식별하는 표시 이름 |
| `rowSpan` | 1 이상의 정수 | — | 병합할 행 수, 기본값 1 |
| `colSpan` | 1 이상의 정수 | — | 병합할 열 수, 기본값 1 |
| `content` | 문자열 | — | 직접 입력한 값 |
| `parameter` | 문자열 | — | 전표 또는 반복 항목에서 읽을 키 |
| `formula` | 문자열 | — | 표시 값을 계산할 수식 |
| `overflow` | 문자열 | — | 그리드의 overflow 설정 재정의 |
| `conditionalFormats` | 규칙 배열 | — | 값에 따라 색과 글자 강조를 바꾸는 규칙 목록 (§9.4) |
| 글자 및 색상 스타일 | 각 스타일 타입 | — | 그리드 스타일 재정의 |

`content`, `parameter`, `formula`는 최대 하나만 지정할 수 있습니다. 모두 생략하면 빈 셀입니다.

`name`은 편집기 표시 전용이며 렌더링 결과에 영향을 주지 않습니다. 중복을 허용하고, 파라미터나 헤더에서 자동으로 만들어 저장하지 않습니다.

셀은 다음 조건을 충족해야 합니다.

- 셀과 병합 범위가 그리드 행과 열의 범위를 벗어나면 안 됩니다.
- 두 셀의 점유 범위가 서로 겹치면 안 됩니다.
- 병합 범위가 행 구간(§15.5)의 경계를 가로지르면 안 됩니다.
- 명시되지 않은 좌표는 빈 셀로 취급합니다.

항목 구간 밖의 `parameter`는 전표 최상위 `values`에서 값을 읽습니다.

항목 구간 안의 `parameter`는 현재 반복 항목에서 먼저 값을 읽습니다. 같은 키가 전표 최상위에도 있다면 반복 항목의 값이 우선합니다.

### 15.3 셀 스타일 상속

셀의 글자 스타일을 생략하면 그리드 요소의 해당 스타일을 상속합니다.

다음 스타일이 상속됩니다.

- `fontName`
- `fontSize`
- `alignment`
- `verticalAlignment`
- `bold`
- `italic`
- `underline`
- `strikethrough`
- `lineHeight`
- `characterSpacing`
- `vertical`
- `fontColor`

셀의 배경색은 그리드의 배경 위에 별도로 그립니다.

셀의 테두리 설정을 생략하면 그리드의 테두리 설정을 사용합니다. 그리드에도 설정이 없다면 다음 기본값을 사용합니다.

- 테두리색: `#000000`
- 테두리 두께: `0.2`
- 테두리 형태: `solid`

### 15.4 공유 테두리

두 셀이 공유하는 변은 다음 규칙으로 렌더링합니다.

1. 두 셀 중 테두리가 더 두꺼운 쪽의 설정을 사용합니다.
2. 두께가 같으면 아래쪽 또는 오른쪽 셀의 설정을 사용합니다.
3. `borderWidth: 0`이면 해당 변을 그리지 않습니다.
4. 병합된 셀 내부의 경계선은 그리지 않습니다.

### 15.5 반복 설정과 행 구간

반복 설정은 다음 프로퍼티를 가집니다.

| 프로퍼티 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `parameter` | 문자열 | ● | 전표 `values`에서 객체 배열을 읽을 키 |
| `bands` | 배열 | ● | 행 구간 정의 목록 |
| `pagination` | 객체 | ● | 페이지 방식 (자동 확장 또는 고정 페이지) |
| `groupBy` | 문자열 배열 | — | 그룹 기준이 되는 항목 필드 키 목록 |
| `maxItems` | 1 이상의 정수 | — | 계획에 사용할 최대 항목 수 |

#### 행 구간

행 구간은 그리드의 원본 행 범위에 출력 역할을 부여합니다.

| 프로퍼티 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `id` | 문자열 | ● | 그리드 안에서 유일한 구간 ID |
| `fromRow` | 0 이상의 정수 | ● | 구간 시작 행 |
| `toRow` | 0 이상의 정수 | ● | 구간 종료 행 |
| `placement` | 열거형 | ● | 구간 역할 |
| `name` | 문자열 | — | 편집기에서 표시할 구간 이름 |
| `pages` | 열거형 | — | 표시할 출력 페이지 (`page-start`·`page-end` 전용, §9.1의 `pages` 값) |
| `repeatOnPageBreak` | 논리값 | — | 페이지를 넘긴 그룹의 시작 구간을 다시 표시할지 (`group-start` 전용) |

`placement`는 다음 값을 사용하며, 구간은 이 세로 순서를 따라야 합니다.

| `placement` | 배치 |
| --- | --- |
| `before-data` | 첫 출력 페이지 머리에서 한 번 |
| `page-start` | 출력 페이지마다 위쪽 (`pages`로 제한 가능) |
| `group-start` | 그룹의 첫 항목 앞 |
| `item` | 데이터 항목마다 복제 |
| `group-end` | 그룹의 마지막 항목 뒤 |
| `after-data` | 마지막 항목 뒤에서 한 번 |
| `page-end` | 출력 페이지마다 아래쪽 (`pages`로 제한 가능) |

행 구간은 다음 조건을 충족해야 합니다.

- 모든 원본 행이 정확히 하나의 구간에 속해야 합니다 (겹침·빈틈 금지).
- `item` 구간은 정확히 하나여야 하며 한 행 이상으로 구성할 수 있습니다.
- `pages`는 `page-start`와 `page-end` 구간에만 지정할 수 있습니다. 걸러진 구간은 자리도 차지하지 않습니다.
- `repeatOnPageBreak`는 `group-start` 구간에만 지정할 수 있습니다.
- `group-start`·`group-end` 구간은 `groupBy`가 있어야 합니다.

#### 페이지 방식

`pagination`은 두 형태 중 하나이며 서로의 프로퍼티를 섞으면 검증에 실패합니다.

```json
{ "mode": "auto", "minItems": 0 }
{ "mode": "fixed", "itemsPerPage": 10 }
```

- 자동 확장(`auto`)은 흐름 영역이 찰 때까지 항목을 채우고 다음 출력 페이지로 이어집니다. 데이터가 `minItems`보다 적으면 빈 항목으로 채웁니다. `minItems: 0`이고 데이터가 없으면 항목 없이 고정 구간만 표시합니다.
- 고정 페이지(`fixed`)는 모든 출력 페이지에 정확히 `itemsPerPage`개의 항목 자리를 배치합니다. 데이터가 적으면 빈 항목으로 채우고, 한 페이지 묶음이 흐름 영역에 들어가지 않으면 계획 오류입니다.

#### 그룹

`groupBy`를 지정하면 연속된 항목 중 지정한 필드 값이 모두 같은 항목이 한 그룹이 됩니다. 데이터 정렬은 수행하지 않으며, 그룹이 이어지도록 정렬하는 책임은 호스트에 있습니다. 빈 항목은 그룹에 속하지 않습니다.

#### 최대 항목 수

`maxItems`를 지정하면 해당 수를 넘는 항목은 계획에서 제외합니다. `maxItems`는 `itemsPerPage`보다 작아도 됩니다.

반복 값은 객체 배열이어야 합니다.

```json
{
  "items": [
    {
      "name": "복사용지",
      "quantity": 2,
      "unitPrice": 5000
    },
    {
      "name": "볼펜",
      "quantity": 3,
      "unitPrice": 1000
    }
  ]
}
```

배열이 아니거나 배열 항목이 객체가 아니면 렌더링에 실패합니다.

### 15.6 페이지 계획과 반복 렌더링

반복 그리드는 렌더링 전에 페이지 계획을 만들고, 화면과 PDF는 같은 계획 결과를 사용합니다.

1. `values[repeat.parameter]`에서 항목 배열을 읽고 `maxItems`를 적용합니다.
2. `groupBy`가 있으면 그룹을 만듭니다.
3. 페이지 방식에 따라 항목 인스턴스(실제 항목 + 빈 항목)를 출력 페이지에 배치합니다.
4. 각 출력 페이지에 `page-start`(첫 페이지는 `before-data` 포함) → 항목·그룹 구간 → `page-end`(마지막 페이지는 `after-data` 포함) 순서로 구간을 쌓습니다.

계획은 다음 규칙을 따릅니다.

- `item` 구간은 원자 단위입니다. 한 항목이 페이지 사이에서 나뉘지 않습니다.
- `group-start`는 그룹의 첫 항목과, `group-end`는 마지막 항목과 같은 페이지에 붙습니다.
- 페이지를 넘긴 그룹은 `repeatOnPageBreak: true`인 `group-start` 구간을 다음 페이지 머리에 다시 표시합니다.
- 자동 확장에서 `after-data`와 마지막 페이지 전용 구간이 남은 공간에 들어가지 않으면 새 출력 페이지를 만들어 배치합니다.
- 페이지 머리 구간이나 새 마지막 페이지의 최종 구간처럼 고정 구간이 흐름 영역에 들어가지 않으면 계획 오류입니다. 빈 이어지는 페이지에서도 항목(이월된 그룹 시작 구간 포함)을 배치하지 못하면 계획 오류입니다.
- `after` 배치로 시작 위치가 줄어든 반복 그리드는 첫 페이지에 아무 항목도 들어가지 않으면 빈 조각을 만들지 않고 다음 출력 페이지에서 시작합니다.
- 빈 항목 인스턴스는 괘선만 그리고 값·수식·조건부 서식을 평가하지 않습니다.
- 항목이 없더라도 출력 페이지는 한 장 생성됩니다.

같은 양식 페이지에 반복 그리드가 여러 개 있다면 각 그리드는 독립된 흐름으로 배치되고, 전체 출력 페이지 수는 가장 긴 흐름을 따릅니다. 서로 다른 흐름의 출력 영역(반복 그리드의 조각과 `after`로 배치된 요소)이 같은 출력 페이지에서 겹치면 계획 오류입니다.

한 양식 페이지의 출력 페이지 수가 상한(§6)을 넘으면 계획 오류입니다.

### 15.7 자동 병합

열의 `autoMerge: true`는 항목 구간에서 연속된 같은 표시값을 세로로 병합합니다.

자동 병합은 다음 규칙을 따릅니다.

1. 같은 열에서 바로 앞 항목과 표시 문자열이 같을 때만 병합합니다.
2. 빈 값과 빈 항목은 병합하지 않습니다.
3. 출력 페이지가 바뀌면 병합을 끝내고 값을 다시 표시합니다.
4. 그룹 경계에서도 병합을 끝냅니다.
5. 항목 구간 밖의 행에는 적용하지 않습니다.
6. 데이터 정렬은 수행하지 않습니다.
7. 병합할 값이 이어지도록 정렬하는 책임은 호스트에 있습니다.
8. 병합으로 합쳐진 셀은 병합 묶음의 첫 항목으로 평가한 조건부 서식(§9.4)을 사용합니다.

자동 병합을 사용하는 열은 항목 구간 전체 높이를 하나의 셀이 차지해야 합니다. 여러 행으로 구성된 항목 구간에서 해당 열이 행마다 별도 셀로 나뉘어 있다면 파일 검증에 실패합니다.

### 15.8 셀 overflow

`overflow`는 셀 영역보다 긴 텍스트를 처리하는 방법입니다.

| 값 | 동작 |
| --- | --- |
| `clip` | 셀 높이를 넘는 줄을 표시하지 않음 |
| `shrink` | 셀에 들어갈 때까지 글자 크기를 줄임 |

기본값은 `clip`입니다.

`shrink`는 글자 크기를 최소 4pt까지 줄입니다.

텍스트는 낱말 단위로 줄바꿈합니다. 낱말 하나가 셀 너비보다 길면 해당 낱말을 글자 단위로 나눕니다.

## 16. 수식

수식은 `field.formula`, `grid.cells[].formula`와 `barcode.formula`에서 사용합니다.

수식은 JavaScript가 아니며 SlipKit 전용 파서로 해석합니다.

### 16.1 기본 문법

```text
expr       := comparison
comparison := addition (("=" | "<>" | "<=" | ">=" | "<" | ">") addition)*
addition   := multiply (("+" | "-") multiply)*
multiply   := unary (("*" | "/") unary)*
unary      := ("+" | "-") unary | primary
primary    := number | string | TRUE | FALSE | function | reference | "(" expr ")"
reference  := ("@")? identifier ("." identifier)*
```

문자열은 큰따옴표로 감쌉니다. 문자열 안의 큰따옴표는 두 번 작성합니다.

```text
"한빛 ""문구"""
```

함수 이름은 대소문자를 구분하지 않습니다.

### 16.2 지원 함수

| 분류 | 함수 |
| --- | --- |
| 집계 | `SUM`, `AVG`, `COUNT`, `MIN`, `MAX` |
| 조건부 집계 | `SUMIF`, `COUNTIF` |
| 산술 | `ROUND`, `FLOOR`, `CEIL`, `ABS` |
| 문자열 | `CONCAT`, `LEFT`, `RIGHT`, `MID`, `REPLACE`, `TRIM`, `UPPER`, `LOWER` |
| 조건 | `IF`, `AND`, `OR` |
| 표시 형식 | `FORMAT_NUMBER`, `FORMAT_DATE`, `NUMBER_TO_KOREAN` |
| 날짜 | `TODAY`, `DATE_ADD`, `DATE_DIFF` |
| 세무 | `VAT` |
| 타입 변환 | `TO_NUMBER`, `TO_STRING`, `TO_DATE` |

지원되지 않는 함수는 수식 파싱에서 거부합니다.

### 16.3 값과 타입

숫자가 필요한 연산과 함수는 문자열을 자동으로 숫자로 변환하지 않습니다.

```text
TO_NUMBER(amount) * 2
```

숫자 파라미터의 값이 없거나 `null` 또는 빈 문자열이면 `buildVoucher()`와 PDF 렌더링 과정에서 `0`으로 정규화합니다.

문자열 표시에서는 값을 다음과 같이 변환합니다.

| 값 | 표시 결과 |
| --- | --- |
| 문자열 | 그대로 표시 |
| 숫자 | 10진 문자열 |
| `true` | `TRUE` |
| `false` | `FALSE` |
| `null` 또는 값 없음 | 빈 문자열 |
| 배열 또는 객체 | 렌더링 오류 |

### 16.4 예약 참조

`@`로 시작하는 참조는 반복 그리드의 행 구간 셀에서 페이지 계획 결과를 읽습니다.

| 참조 | 값 |
| --- | --- |
| `@item` | 현재 항목 객체 |
| `@group` | 현재 그룹의 실제 항목 배열 |
| `@page` | 현재 출력 페이지에 배치된 실제 항목 배열 |
| `@all` | `maxItems` 적용 후의 전체 실제 항목 배열 |
| `@carried` | 이전 출력 페이지까지 배치된 실제 항목 배열 |

- 예약 참조 뒤에 점 표기로 필드를 이어 쓸 수 있습니다. 예: `SUM(@page.amount)` (페이지 소계), `SUM(@carried.amount)` (누계).
- 빈 항목 인스턴스는 어떤 예약 참조에도 포함되지 않습니다.
- 위 다섯 가지 외의 `@` 참조는 수식 파싱에서 거부합니다.
- 행 구간 밖(필드 요소 등)에서 예약 참조를 평가하면 오류입니다.

수식 문법과 함수별 동작은 [수식 작성 및 함수 참조](guide/formula.ko.md)를 참고합니다.

> [!NOTE]
> `.slip` 파일의 구조 검증은 수식 문자열의 문법을 검사하지 않습니다. 수식 문법과 값 타입 오류는 수식 파싱 또는 PDF 렌더링 과정에서 발견될 수 있습니다.

## 17. 양식 파일

양식 파일은 `kind: "template"`을 사용하고 `template`에 양식 본문을 저장합니다.

다음은 유효한 최소 양식 예제입니다.

```json
{
  "schemaVersion": "0.1.0",
  "kind": "template",
  "template": {
    "meta": {
      "title": "빈 양식"
    },
    "paper": {
      "width": 210,
      "height": 297,
      "padding": [15, 15, 15, 15]
    },
    "pages": [
      {
        "elements": []
      }
    ],
    "assets": []
  }
}
```

## 18. 전표 파일

전표 파일은 `kind: "voucher"`를 사용합니다.

| 프로퍼티 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `schemaVersion` | 문자열 | ● | 파일 형식 버전 |
| `kind` | 문자열 | ● | 항상 `voucher` |
| `templateSnapshot` | 객체 | ● | 작성 당시 양식 본문의 전체 복사본 |
| `values` | 객체 | ● | 파라미터 키와 실제 값 |
| `issued` | 논리값 | ● | 발행 여부 |

```json
{
  "schemaVersion": "0.1.0",
  "kind": "voucher",
  "templateSnapshot": {
    "meta": {
      "title": "거래명세서"
    },
    "paper": {
      "width": 210,
      "height": 297,
      "padding": [15, 15, 15, 15]
    },
    "pages": [
      {
        "elements": []
      }
    ],
    "assets": []
  },
  "values": {
    "customerName": "한빛상사",
    "totalAmount": 13000
  },
  "issued": false
}
```

### 18.1 양식 스냅샷

`templateSnapshot`은 전표를 생성한 시점의 양식 본문 전체를 포함해야 합니다.

전표 렌더러는 별도의 원본 양식을 조회하지 않고 `templateSnapshot`을 사용해야 합니다. 따라서 원본 양식이 수정되거나 삭제되어도 전표의 렌더링 기준은 바뀌지 않습니다.

`buildVoucher()`는 양식과 값의 깊은 복사본을 사용하여 전표를 만들고 `issued: false`로 반환합니다.

### 18.2 전표 값

`values`는 파라미터 키를 JSON 값에 연결하는 객체입니다.

```json
{
  "customerName": "한빛상사",
  "tradeDate": "2026-08-25",
  "taxIncluded": true,
  "signatureImage": "data:image/png;base64,...",
  "items": [
    {
      "name": "복사용지",
      "quantity": 2,
      "unitPrice": 5000,
      "amount": 10000
    }
  ]
}
```

수식으로 계산하는 값은 반드시 `values`에 저장할 필요가 없습니다. 렌더링 시 수식이 입력값을 이용해 계산합니다.

## 19. 발행 상태

`issued`는 전표의 값이 업무상 확정되었는지를 나타냅니다.

| 값 | 의미 |
| --- | --- |
| `false` | 작성 중인 전표 |
| `true` | 값이 확정되어 작성 폼에서 잠긴 전표 |

> [!WARNING]
> `issued: true`는 전자서명, 파일 무결성, 작성자 신원이나 법적인 발행 증명을 의미하지 않습니다.
>
> JSON을 직접 수정하면 `issued` 값도 변경할 수 있습니다. 권한 관리와 감사 기록이 필요하다면 호스트 시스템에서 별도로 구현해야 합니다.

### 19.1 발행 전표의 이미지 규칙

`issued: true`인 전표는 외부 URL에 의존하지 않아야 합니다.

다음 위치에 HTTP 또는 HTTPS URL이 있으면 의미 검증에 실패합니다.

- `templateSnapshot.assets[].src`
- `templateSnapshot.pages[].elements[]`의 고정 이미지 `src`

변동 이미지 요소가 참조하는 `values`의 값은 비어 있거나 올바른 data URI여야 합니다. 외부 URL 또는 잘못된 이미지 문자열이면 검증에 실패합니다.

`issued: false`인 전표는 구조상 외부 URL을 포함할 수 있지만 SlipKit Core가 해당 URL을 PDF로 렌더링하지는 않습니다.

## 20. PDF 렌더링 의미

PDF 렌더러는 파일 종류에 따라 다음 데이터를 사용합니다.

| 파일 종류 | 양식 | 값 |
| --- | --- | --- |
| `template` | `template` | 빈 값 |
| `voucher` | `templateSnapshot` | `values` |

양식 파일을 Core에서 직접 렌더링하면 `sampleValues`는 자동 적용되지 않습니다. SlipKit 디자이너는 미리보기를 만들 때 `sampleValues`를 전표 값으로 전달합니다.

### 20.1 기본 렌더링 값

| 항목 | 기본값 |
| --- | --- |
| 일반 글자 크기 | 10pt |
| 페이지 번호 글자 크기 | 9pt |
| 글자색 | `#000000` |
| 일반 가로 정렬 | `left` |
| 텍스트·필드 세로 정렬 | `top` |
| 그리드 셀 세로 정렬 | `middle` |
| 줄간격 | 1 |
| 자간 | 0pt |
| 텍스트·필드 테두리 | 없음 |
| 그리드·도형 테두리색 | `#000000` |
| 그리드·도형 테두리 두께 | 0.2mm |
| 그리드·도형 테두리 형태 | `solid` |
| 그리드 셀 안쪽 여백 | 1mm |
| 그리드 overflow | `clip` |
| shrink 최소 글자 크기 | 4pt |

PDF 출력에 필요한 글꼴은 렌더러 설정으로 제공해야 합니다. `fontName`이 없거나 제공된 폰트에 그 이름이 없으면 대체 폰트를 사용합니다. 파일에 저장된 `fontName` 값은 렌더링 때문에 바뀌지 않습니다.

## 21. 암호화 봉투

SlipKit은 일반 `.slip` 파일 내용을 AES-256-GCM으로 암호화할 수 있습니다.

암호화 봉투는 일반 `.slip` JSON Schema의 검증 대상이 아닙니다. 복호화한 내부 JSON이 현재 `.slip` 명세를 따라야 합니다.

### 21.1 알고리즘

| 항목 | 값 |
| --- | --- |
| 암호 | AES-256-GCM |
| 인증 태그 | 128비트 |
| 초기화 벡터 | 무작위 12바이트 |
| 문자열 비밀번호 KDF | PBKDF2-SHA256 |
| PBKDF2 반복 횟수 | 600,000 |
| PBKDF2 솔트 | 무작위 16바이트 |
| 원시 키 | 32바이트 |
| 문자열 인코딩 | UTF-8 |
| 바이너리 인코딩 | 패딩 없는 base64url |

AES-GCM 추가 인증 데이터는 사용하지 않습니다.

### 21.2 봉투 구조

```json
{
  "slipkit": "encrypted",
  "v": 1,
  "cipher": "A256GCM",
  "kdf": {
    "algo": "PBKDF2-SHA256",
    "salt": "<base64url>",
    "iterations": 600000
  },
  "iv": "<base64url>",
  "data": "<base64url>"
}
```

| 프로퍼티 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `slipkit` | 문자열 | ● | 항상 `encrypted` |
| `v` | 숫자 | ● | 암호화 봉투 버전, 현재 `1` |
| `cipher` | 문자열 | ● | 항상 `A256GCM` |
| `kdf` | 객체 | 조건부 | 문자열 비밀번호를 사용한 경우 필수 |
| `iv` | 문자열 | ● | 12바이트 초기화 벡터의 base64url |
| `data` | 문자열 | ● | 암호문과 인증 태그의 base64url |

`kdf`는 다음 프로퍼티를 가집니다.

| 프로퍼티 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `algo` | 문자열 | ● | 항상 `PBKDF2-SHA256` |
| `salt` | 문자열 | ● | 16바이트 솔트의 base64url |
| `iterations` | 숫자 | ● | 새로 만드는 봉투는 `600000`. 복호화는 봉투에 기록된 값을 사용한다 |

32바이트 원시 키를 사용한 경우 `kdf`를 포함하면 안 됩니다.

`data`는 일반 `.slip` 파일을 직렬화한 UTF-8 바이트를 AES-GCM으로 암호화한 결과입니다. 인증 태그는 암호문 뒤에 포함됩니다.

### 21.3 복호화

복호화 구현은 다음 순서로 처리해야 합니다.

1. JSON 봉투 형식을 확인합니다.
2. `slipkit`, `v`와 `cipher`를 확인합니다.
3. `kdf` 존재 여부와 입력된 키 종류가 일치하는지 확인합니다.
4. base64url 값을 디코딩합니다.
5. 문자열 비밀번호라면 PBKDF2로 키를 파생합니다.
6. AES-GCM으로 복호화하고 인증 태그를 확인합니다.
7. 복호화된 UTF-8 JSON을 일반 `.slip` 파일로 파싱합니다.
8. 버전, 구조와 의미 규칙을 검증합니다.

키가 잘못되었거나 암호문이 변경되었다면 복호화에 실패해야 합니다.

> [!IMPORTANT]
> 암호화는 파일의 기밀성과 복호화 시 변조 감지를 제공합니다. 사용자 권한, 전자서명, 작성자 신원, 감사 기록과 키 관리 체계를 제공하지 않습니다.
>
> 키의 생성, 보관, 배포, 회전과 폐기는 호스트 시스템의 책임입니다.

## 22. 검증 절차

권장 검증 절차는 다음과 같습니다.

```text
UTF-8 JSON
  → 최상위 kind·schemaVersion 확인
  → 버전 마이그레이션
  → JSON Schema 구조 검증
  → 교차 필드 의미 검증
  → 수식·데이터·리소스 확인
  → PDF 렌더링
```

### 22.1 JSON Schema가 검사하는 항목

JSON Schema는 다음과 같은 구조 규칙을 검사합니다.

- 필수 프로퍼티
- 프로퍼티 타입
- 열거형 값
- 숫자 범위
- 문자열 형식
- 배열 최소 및 최대 길이
- 요소 타입별 프로퍼티
- 정의되지 않은 프로퍼티

### 22.2 레퍼런스 구현이 추가로 검사하는 항목

`@omdc-slipkit/core`는 다음 교차 필드 규칙을 추가로 검사합니다.

- 용지 크기와 여백의 관계
- 파라미터 및 하위 필드 키 중복
- 에셋 ID 중복
- 요소 ID 중복
- 페이지 키 중복
- `asset://` 참조 대상
- 이미지 값 소스의 배타성
- 필드와 바코드 값 소스의 배타성
- 행 구간의 범위·겹침·빈틈과 세로 순서
- 항목 구간이 정확히 하나인지
- 행 구간별 `pages`·`repeatOnPageBreak`·`groupBy` 조건
- 셀 범위와 겹침
- 행 구간 경계를 넘는 셀 병합
- 자동 병합 열의 구조
- 흐름 영역의 범위와 용지 높이의 관계
- `after` 배치 대상의 존재와 순환
- 발행 전표의 외부 URL 이미지
- 발행 전표의 변동 이미지 값

### 22.3 렌더링 단계가 검사하는 항목

다음 항목은 구조 검증이 아니라 실제 사용 시점에 검사할 수 있습니다.

- 수식 문법과 함수 이름
- 수식 값의 타입
- 반복 그리드 값이 객체 배열인지
- 페이지 계획 (항목·그룹·고정 페이지 묶음과 고정 구간이 흐름 영역에 들어가는지, 흐름 겹침, 출력 페이지 상한, 출력 페이지 수 확정)
- 이미지가 실제로 렌더링 가능한 data URI인지
- `asset://` 대상이 내장 이미지인지
- 바코드 값이 바코드 종류에 적합한지
- 폰트가 필요한 문자를 포함하는지

## 23. JSON Schema 제공

`@omdc-slipkit/core` 패키지는 JSON Schema Draft 2020-12 파일을 제공합니다.

| 경로 | 설명 |
| --- | --- |
| `@omdc-slipkit/core/schemas/slip-0.1.0.schema.json` | 버전 `0.1.0` 고정 스키마 |
| `@omdc-slipkit/core/schemas/slip.schema.json` | 현재 최신 버전 별칭 |

스키마의 `$id`는 다음 형식을 사용합니다.

```text
urn:slipkit:schema:slip:<schemaVersion>
```

현재 버전의 `$id`는 다음과 같습니다.

```text
urn:slipkit:schema:slip:0.1.0
```

TypeScript에서는 `slipFileJsonSchema()`로 같은 JSON Schema 객체를 얻을 수 있습니다.

> [!NOTE]
> JSON Schema는 버전 마이그레이션을 수행하지 않습니다. 외부 시스템은 파일의 `schemaVersion`에 맞는 스키마를 선택해야 합니다.

## 24. 향후 확장

현재 규범 형식은 단일 JSON 문서입니다.

`asset://`는 향후 대용량 리소스를 별도 항목으로 담는 컨테이너 형식을 고려할 수 있도록 예약되어 있습니다. 그러나 ZIP 또는 다른 바이너리 컨테이너는 현재 `.slip` 형식에 포함되지 않습니다.

향후 확장은 별도의 설계 결정과 스키마 버전 변경을 거쳐 정의해야 합니다. 현재 구현이 예약되지 않은 필드를 임의로 추가해서는 안 됩니다.
