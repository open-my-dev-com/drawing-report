# `.slip` 파일 포맷 명세 (SPEC)

> `.slip` 파일의 **공개 규범 명세**다 (ADR-022). 타 시스템은 이 문서와 동봉된
> JSON Schema만으로 `.slip` 파일을 읽고 쓸 수 있어야 한다.
> 레퍼런스 구현은 `@omdc-slipkit/core`이며, 이 문서와 구현이 어긋나면 이 문서가 우선한다.

- 상태: **Draft** (schemaVersion `0.1.0`)
- 최종 갱신: 2026-08-23
- 근거 ADR: 001, 007, 008, 011, 018, 019, 020, 022, 032, 036, 037, 046, 047, 048, 049, 050

이 문서에서 **필수/금지/해야 한다**는 규범 요구사항을, *권장*은 비규범 권고를 뜻한다.

---

## 1. 개요

`.slip` 파일은 **UTF-8로 인코딩된 단일 JSON 문서**다 (ADR-007). 파일 하나가
다음 둘 중 하나를 담는다 (`kind` 필드로 구분, ADR-018):

| kind | 내용 |
|---|---|
| `template` | 양식(템플릿) — 용지·페이지·요소 정의 |
| `voucher` | 전표 — 생성 시점의 양식 **전체 스냅샷** + 기입값 |

전표 파일은 양식 저장소 없이 **파일 단독으로 열람 가능**해야 한다(자기완결, ADR-008).

MIME 타입(비규범 권장): `application/vnd.slipkit.slip+json`

## 2. 봉투(envelope)와 버전

모든 `.slip` 문서의 최상위에는 다음 두 필드가 **필수**다:

```json
{ "schemaVersion": "0.1.0", "kind": "template" }
```

- `schemaVersion`: 이 문서가 따르는 스키마 버전. `MAJOR.MINOR.PATCH` semver 형식 필수.
- 현재 버전은 **`0.1.0`**이며 이것이 첫 버전이다. 개발 단계에서 스키마를 여러 차례 고쳤으나 공개된 적이
  없어 하나로 합쳐 0.1.0으로 둔다 (ADR-046). 제품 안정 릴리스(공개) 시점에 `1.0.0`으로 확정한다.

### 2.1 버전 처리 규칙 (ADR-007)

구현(리더)은 파일을 열 때:

1. `schemaVersion`이 자신이 아는 최신 버전과 같으면 그대로 검증·해석한다.
2. 더 **낮으면** 단계별 마이그레이션으로 최신 버전까지 끌어올린 뒤 해석해야 한다.
3. 더 **높으면** 해석을 시도하지 말고 명확한 오류를 내야 한다(미래 포맷).

라이터는 항상 자신이 아는 최신 `schemaVersion`으로 기록해야 한다.

## 3. 공통 자료형

| 자료형 | 규칙 |
|---|---|
| 길이 | 항상 **mm** 단위의 수. 좌표계는 용지 좌상단 원점, x→오른쪽, y→아래 (ADR-011) |
| 색상 | `#RRGGBB` 또는 `#RRGGBBAA` (대소문자 무관 hex) |
| id | 비어 있지 않은 문자열. 유일성 범위는 각 절에 명시 |
| 일시 | ISO 8601 (`date-time`, 오프셋 허용) |
| 정렬 | `left` \| `center` \| `right` |
| 비율 배열 | 양수 배열, 합이 100 (허용 오차 ±0.01) |

### 3.1 리소스 참조 `src` (ADR-007)

이미지 등 리소스 참조는 `src` 문자열 하나로 통일하며 3형식을 지원한다:

| 형식 | 예 | 용도 |
|---|---|---|
| 외부 URL | `https://cdn.example.com/logo.png` | 스키마상 허용하나 **PDF로 렌더할 수 없다** — 파일에는 base64(`data:`)로 담는다 (ADR-036) |
| data URI | `data:image/png;base64,iVBOR...` | 파일 내장 |
| 내부 에셋 | `asset://logo` | 같은 문서 `assets` 항목의 `id` 참조 |

`asset://<id>` 참조는 같은 문서 본문의 `assets` 배열에 해당 `id`가 **존재해야 한다**.
(`asset://`는 추후 ZIP 컨테이너 확장의 장치이기도 하다 — ADR-007. 컨테이너가 추가되어도
스키마는 변하지 않는다.)

### 3.2 구조 크기 상한

적대적으로 큰 파일이 구현의 메모리·스택을 고갈시키지 못하도록, 아래 상한을 넘는
문서는 **거부해야 한다**:

| 대상 | 상한 |
|---|---|
| `pages` 수 | 500 |
| 페이지당 `elements` 수 | 2,000 |
| `assets` 수 | 1,000 |
| `grid.rows` 길이 | 1,000 |
| `grid.columns` 길이 | 100 |
| `grid.cells` 수 | 100,000 |
| `grid.repeat.perPage` | 1,000 |
| `grid.repeat.maxItems` | 100,000 |
| `parameters` 길이 | 500 |
| 줄간격 배수 | 10 |
| 자간 절대값 | 100pt |
| `field.formula` 길이 | 10,000자 |
| 수식 중첩 깊이 (괄호·함수 인자·부호) | 100단계 |
| 값(`values` 등)의 중첩 깊이 | 256단계 |

위쪽 8개는 구조 검증(§9-1) 대상이라 동봉 JSON Schema에도 반영된다. 수식 길이·중첩과
값 깊이는 수식 파싱·평가 시점에 강제된다. 코드에서는 `SLIP_LIMITS`
상수로 같은 값을 얻을 수 있다.

## 4. 양식 본문 (`template` / `templateSnapshot`)

```json
{
  "meta": { "title": "거래명세서", "createdAt": "2026-08-18T09:00:00+09:00" },
  "paper": { "width": 210, "height": 297, "padding": [20, 15, 20, 15] },
  "pages": [ { "elements": [ ... ] } ],
  "assets": [ { "id": "logo", "mimeType": "image/png", "src": "data:image/png;base64,..." } ]
}
```

| 필드 | 필수 | 내용 |
|---|---|---|
| `meta.title` | ✅ | 양식 이름 (비어 있지 않은 문자열) |
| `meta.createdAt` / `meta.updatedAt` | — | ISO 8601 일시 |
| `paper` | ✅ | 용지 크기(mm)와 여백. `padding`은 `[top, right, bottom, left]`. 여백 합은 용지보다 작아야 한다 |
| `pages` | ✅ | 1개 이상의 페이지. 각 페이지는 `elements` 배열 (ADR-011: 페이지는 1급 개념). 페이지는 `key`(물리명, 문서 내 유일)·`label`(논리명)·`pageNumber`를 가질 수 있다 — 전부 선택 |
| `assets` | ✅ | 내장 리소스 목록 (빈 배열 가능). `id`는 문서 내 유일 필수 |
| `parameters` | — | 파라미터 정의부 (ADR-032/047): `{ key, label?, valueType?, fields? }` 배열. **물리명 `key`**는 파일·수식·백엔드 연동에, **논리명 `label`**은 화면 표시에 쓴다. `key`는 목록 안에서 유일. 정의부는 보조 정보이며 요소가 미등록 키를 쓰는 것도 허용된다. **값 종류 `valueType`**(`text`\|`number`\|`date`\|`boolean`\|`image`\|`list`, 선택)은 작성폼 입력 방식과 쓸 수 있는 함수를 가리는 데 쓰며 생략하면 글자로 다룬다. **하위 필드 `fields`**(선택)는 `valueType: 'list'`일 때만 둘 수 있고 항목 하나가 가진 값을 `{ key, label?, valueType? }`로 선언한다 — 항목은 평평한 객체라 하위 필드는 다시 하위를 갖지 않는다(ADR-038). `fields`의 `key`도 그 목록 안에서 유일해야 한다 |
| `sampleValues` | — | 미리보기용 샘플 값 (ADR-032): 파라미터 물리명 → JSON 값. 발행과 무관하며 전표 생성 시 복사하지 않는다 |

요소 `id`는 **문서 전체에서 유일**해야 한다(페이지가 달라도 중복 금지).

**페이지 번호 `pageNumber`**: `{ position, format?, fontSize? }`.
`position`은 `bottom-left`·`bottom-center`·`bottom-right`·`top-left`·`top-center`·`top-right`.
`format`의 `{n}`은 현재 쪽, `{total}`은 전체 쪽 수로 바뀐다(생략하면 `{n} / {total}`).
번호는 **출력 페이지가 다 만들어진 뒤에** 찍는다 — 반복 그리드가 넘치면 한 양식 페이지가 여러 출력
페이지가 되므로, 전체 쪽 수는 그때에야 정해진다. 자리는 용지 여백 안쪽 가장자리에 맞춘다.

## 5. 요소 9종 (ADR-020/032/037)

모든 요소의 공통 필드:

| 필드 | 필수 | 내용 |
|---|---|---|
| `type` | ✅ | 요소 종류 판별자 (아래 9종) |
| `id` | ✅ | 문서 내 유일 id |
| `name` | ✅ | 디자이너에 표시되는 이름 |
| `position` | ✅ | `{ x, y }` mm, 용지 좌상단 기준. **음수 금지** (x, y ≥ 0) |
| `width` / `height` | ✅ | mm (0 허용 — 예: 수평선의 height) |
| `group` | — | 그룹 식별자 (ADR-032). 같은 값을 가진 요소들을 한 묶음으로 다룬다 |

색 스타일(ADR-020/032): 텍스트류·그리드(`text`·`grid`·`field`)는
`backgroundColor`, `fontColor`, `borderColor`, `borderWidth`(mm),
`borderStyle`(`solid`|`dashed`|`dotted`)을 갖는다 — 전부 선택.
도형 4종(`line`·`rect`·`ellipse`·`polygon`)은 **종류마다 의미 있는 스타일만** 갖는다
(§5.3) — 도형을 독립 타입으로 분리한 이유다 (ADR-032).

`borderStyle`의 렌더 규칙(ADR-032): 파선·점선은 **직선에만** 적용된다 —
선 요소, 사각형(`radius` 미지정), 그리드선. 그 밖(텍스트·필드 테두리)은
`solid`로 그린다. 파선 = 2.4mm 선 + 1.2mm 간격, 점선 = 0.4mm 점 + 0.8mm 간격.

글꼴(텍스트류 — `text`·`field`·그리드 셀): `fontName`, `fontSize`(pt), `alignment`,
`bold`, `underline`, `strikethrough` — 전부 선택 (ADR-032).
**글자 조판** 필드도 있다(전부 선택):

| 필드 | 값 | 뜻 |
|---|---|---|
| `verticalAlignment` | `top`(기본) \| `middle` \| `bottom` | 상자 안에서 글이 놓이는 세로 자리 |
| `italic` | 불리언 | 기울임 |
| `lineHeight` | 양수(기본 1) | 줄간격 배수 |
| `characterSpacing` | 수(기본 0, pt) | 자간. 음수는 글자를 좁힌다 |
| `vertical` | 불리언 | 세로쓰기 |

`bold`·`italic`은 **변형 폰트로 전환하는 방식**이다. 유효 폰트(요소 `fontName`, 없으면 대체 폰트)의
`<이름>-Bold`·`<이름>-Italic`(둘 다면 `<이름>-BoldItalic`)이 렌더 옵션에 있을 때 그 폰트로 그리며,
없으면 **PDF에서 무시된다** — 기울이기 흉내는 내지 않는다 (ADR-032).

`vertical`은 글자를 **한 자씩 세로로 쌓아** 그린다. 상자 하나가 세로 한 줄이므로 원문의 줄바꿈은
자리를 차지하지 않도록 없앤다 — 여러 줄을 세로로 쓰려면 상자를 나눈다.

### 5.1 `text` — 텍스트

직접 입력한 글. `content`(필수)에 담는다. 전표 값 치환·수식은 `field`를 사용한다.

### 5.2 `image` — 이미지

`src`(§3.1의 3형식) 또는 `parameter` 중 **하나**를 갖는다. 색 스타일 필드는 없다.

- `src` — 양식에 박히는 **고정 이미지**.
- `parameter` — 전표 값에서 읽는 **변동 이미지**(서명·도장·상품 사진). 값은 **`data:` base64만**
  받는다 (ADR-036) — 전표 `values`는 JSON이라 바이너리를 담지 못하고, 이 라이브러리는 네트워크를
  쓰지 않아 주소를 받아올 수 없다 (ADR-002). 값이 비면 그 자리는 빈 채로 둔다.

둘 다 없거나 둘 다 있으면 거부한다.
PDF 렌더 시 외부 URL 참조는 거부된다 — 렌더하려면 `data:` 또는 `asset://`로
내장되어 있어야 한다. 이 라이브러리는 이미지를 받아오지 않으므로, 주소로 받아야 하는
이미지는 **호스트가 base64로 바꿔 넣어야 한다** (ADR-036). 외부 URL을 형식으로 계속
받아들이는 것은 다른 시스템이 만든 파일을 읽기 위해서다.

### 5.3 도형 4종 — `line` / `rect` / `ellipse` / `polygon`

도형은 종류마다 의미 있는 스타일이 달라 **독립 요소 타입**으로 둔다 (ADR-032) —
하나의 뭉뚱그린 도형 타입이 아니라 종류별 타입이다.

| 타입 | 스타일 필드 (전부 선택) | 전용 필드 |
|---|---|---|
| `line` 선 | `borderColor`(선 색) · `borderWidth`(굵기 mm) · `borderStyle`(형태) | `lineDirection` (기본 `horizontal`): `horizontal`(상자 세로 중앙의 수평선) \| `vertical`(가로 중앙의 수직선) \| `down`(좌상→우하 대각선) \| `up`(좌하→우상 대각선). 임의 선분은 상자(position·width·height)와 방향으로 표현한다. 편집 화면은 이 인코딩을 **길이·각도**로 바꿔 보여준다(ADR-050) — 파일 형식은 그대로다 |
| `rect` 사각형 | `backgroundColor` · `borderColor` · `borderWidth` · `borderStyle` | `radius` 모서리 반경(mm). 파선·점선 테두리와 동시 지정 금지(곡선 구간은 분해 렌더 불가) |
| `ellipse` 타원 | `backgroundColor` · `borderColor` · `borderWidth` (테두리는 실선 고정) | — |
| `polygon` 정다각형 | `backgroundColor` · `borderColor` · `borderWidth` (테두리는 실선 고정) | `sides`(필수, 3~12): 변 수 — 3=삼각형, 5=오각형, 6=육각형 … |

타원·정다각형은 상자에 내접해 그린다. 정다각형은 첫 꼭짓점이 위쪽이며, 꼭짓점들을
상자에 꽉 차게 정규화한다 (삼각형이면 위 꼭짓점·아래 밑변).

### 5.4 `field` — 입력 필드

전표 작성 시 값이 채워지는 자리.

값 소스는 **`parameter`와 `formula` 중 정확히 하나**다 (ADR-049) — 그리드 셀·바코드와 같은 규칙이다.
둘을 함께 두면 거부한다.

| 필드 | 필수 | 내용 |
|---|---|---|
| `parameter` | 둘 중 하나 | 전표 `values`의 키 — 사람이 채우는 값 |
| `formula` | 둘 중 하나 | 표시 값을 계산하는 수식 (ADR-010/017). 예: `FORMAT_NUMBER(SUM(items.금액))`. 빈 문자열이면 빈 글로 그린다 |

수식 문법·함수 목록(32종)은 ADR-017·044를 따르며 별도 문서로 상세화한다.
수식 길이·중첩 깊이는 §3.2 상한을 따른다 (초과 시 파싱 단계에서 거부).

**타입 규칙 (ADR-044)**: 숫자를 요구하는 자리(산술 연산·`SUM`·`ROUND`·`VAT` 등)는 숫자만 받는다 —
글자를 자동으로 수로 바꾸지 않으며, 바꾸려면 `TO_NUMBER`로 감싼다. 빈 값(미입력)은 0으로 본다.
글자를 요구하는 자리는 숫자·논리를 자동으로 글자화한다(`TO_STRING`은 명시용). 비교(`= <> < > <= >=`)는
같은 타입끼리만 비교한다. `number` 종류 파라미터(§4.1 `valueType`)의 빈 값은 렌더·작성 시 0으로 정규화된다.

### 5.5 `grid` — 그리드 (ADR-037)

고정 틀과 반복 목록을 **하나로 다루는 그리드**이자 **유일한 표 요소**다. 행 범위 하나를
반복 구간으로 지정하면 그 구간이 데이터 배열 길이만큼 복제된다. 반복 구간을 두지 않으면
고정 틀로 쓴다.

| 필드 | 필수 | 내용 |
|---|---|---|
| `columns` | ✅ | 열 정의 배열(1개 이상): `{ width, autoMerge? }` — 너비 **mm** |
| `rows` | ✅ | 행 정의 배열(1개 이상): `{ height }` — 높이 **mm** |
| `cells` | ✅ | 셀 배열(빈 배열 가능). 명시하지 않은 좌표는 빈 셀 |
| `repeat` | — | 반복 구간. 생략하면 고정 틀 |
| `overflow` | — | 셀을 넘치는 글의 처리: `clip`(기본) \| `shrink` |

요소의 `width`는 **열 너비의 합**과 같아야 한다. `height`는 **실제로 그려지는 높이**와 같아야
한다 — 반복 구간이 없으면 행 높이의 합이고, 있으면 반복 구간이 `perPage`번 복제된 높이다:

```
height = 위쪽 행 높이 + perPage x 반복 구간 높이 + 아래쪽 행 높이
```

비율(%)이 아니라 mm 절대값이므로, 행을 더해도 다른 행 높이가 변하지 않는다.

**셀**

| 필드 | 필수 | 내용 |
|---|---|---|
| `row` / `column` | ✅ | 0-기반 좌표 |
| `rowSpan` / `colSpan` | — | 병합 범위 (기본 1) |
| `content` | — | 직접 입력한 글 |
| `parameter` | — | 값 키. 반복 구간 안이면 **그 항목의 필드**, 밖이면 전표 `values`의 키 |
| `formula` | — | 표시 전 가공 수식 (ADR-010/017) |
| `overflow` | — | 요소 값을 덮어쓴다 |
| 색·글꼴 | — | §5의 색 스타일·글꼴 필드. 셀에 없으면 요소 값을 물려받는다 |

`content`·`parameter`·`formula`는 **함께 쓸 수 없다** — 하나만 지정한다. 셋 다 없으면 빈 셀이다.
셀(병합 범위 포함)은 그리드를 벗어나거나 서로 겹치면 안 된다.

**셀별 테두리 렌더 규칙** (ADR-033): 셀의 `borderColor`·`borderWidth`·`borderStyle`은
그 셀(병합 범위)의 **둘레 변**에 적용된다. 셀에 없는 값은 요소 값(그것도 없으면 기본
0.2mm 검정 실선)을 쓴다. 이웃한 두 셀이 공유하는 변은 **유효 굵기가 더 큰 쪽** 설정을
따르고, 굵기가 같으면 아래·오른쪽 셀 설정을 따른다. `borderWidth: 0`은 그 변을 그리지
않는다는 뜻이다 (예: 마지막 행 왼쪽 셀들의 테두리를 지우고 오른쪽 한 셀만 합계 박스로 남기기).
병합 범위 내부의 경계선은 그리지 않는다.

**데이터 자동 병합 `columns[i].autoMerge`** (ADR-038)

켜면 그 열의 **반복 구간 셀이 앞 벌과 값이 같을 때 세로로 합쳐진다.** 상품별 주문자 목록처럼 한 열의
값이 이어지는 목록을 묶어 보이게 하는 데 쓴다. 기본값은 꺼짐이며 **열마다 지정한다** — 그리드를 통째로
켜면 수량 열의 `2`와 `2`가 우연히 같다고 합쳐져 전표가 틀린다.

1. 앞 벌의 같은 열 셀과 값이 같으면 새로 그리지 않고 앞 셀의 세로 병합을 늘린다.
2. **페이지가 바뀌면 끊고 값을 다시 쓴다** — 이어지는 페이지 첫 줄이 어느 묶음인지 알 수 있어야 한다.
3. **빈 값은 합치지 않는다.**

반복 구간 **밖**(헤더·꼬리 행)은 영향받지 않는다. 켜려면 그 열의 반복 구간 셀이 **구간 전체 높이를
차지**해야 한다 — 구간이 한 줄이면 저절로 성립하고, 여러 줄인데 열이 줄마다 따로 셀을 가지면 거부한다.
같은 값이 **이어져 있어야** 합쳐지므로 **정렬은 호스트 몫**이다.

**반복 구간 `repeat`**

| 필드 | 필수 | 내용 |
|---|---|---|
| `parameter` | ✅ | 전표 `values`에서 항목 배열(객체 배열)을 담는 키 |
| `fromRow` / `toRow` | ✅ | 반복할 행 범위(0-기반, 양끝 포함). `fromRow` ≤ `toRow` |
| `perPage` | ✅ | 한 페이지에 담는 **항목 수**(1 이상). 행 수가 아니다 |
| `repeatHeader` | ✅ | 이어지는 페이지에 반복 구간 **위쪽 행**을 다시 그릴지 |
| `maxItems` | — | 그릴 항목 수 상한 (ADR-048). 넘는 항목은 그리지 않으며 페이지도 늘리지 않는다. 정하지 않으면 항목 수만큼 페이지가 늘어난다. `perPage` 이상이어야 하고 상한은 100,000이다 |

반복 구간 안 셀의 병합 범위는 구간을 벗어날 수 없다. 반복 구간은 그리드당 **하나**다 —
둘 이상 필요하면 그리드를 나눈다.

**렌더 규칙**

1. 항목 수를 `perPage`로 나눠 페이지 수를 정한다. 항목이 없으면 한 쪽이다.
2. 각 쪽에서 반복 구간은 그 페이지 몫의 항목만큼 복제되고, **남는 자리는 빈 줄로 그린다**
   (괘선 포함) — 항목이 적어도 그리드 크기와 아래 요소의 자리가 변하지 않는다.
3. 반복 구간 **아래쪽 행**(합계 등)은 반복 결과 바로 아래에 놓인다. 그리드 전체 높이는 페이지마다
   같으므로 항목 수가 달라도 아래 요소의 자리가 흔들리지 않는다.
4. 이어지는 페이지에는 **같은 양식 페이지를 그대로 다시 그린다.** 반복 구간만 다음 몫으로 바뀌며,
   `repeatHeader`가 거짓이면 위쪽 행을 그리지 않고 그 자리를 비운다.
5. 한 페이지에 반복 그리드가 여럿이면 페이지 수는 **그중 가장 많은 페이지 수**를 따른다.

**셀을 넘치는 글**

셀 안에서 낱말 단위로 줄이 바뀐다. 낱말 하나가 셀 폭보다 길면 그 낱말만 글자 단위로 쪼갠다.
줄이 셀 높이를 넘을 때:

- `clip` — 넘치는 줄을 그리지 않는다. 그리드 모양이 무너지지 않는다.
- `shrink` — 셀에 들어갈 때까지 글자 크기를 줄인다(최소 4pt).

### 5.6 `barcode` — 바코드

전표번호를 기계로 읽거나 QR로 조회 링크를 걸 때 쓴다.

| 필드 | 필수 | 내용 |
|---|---|---|
| `kind` | ✅ | 바코드 종류(아래 12종) |
| `content` / `parameter` / `formula` | ✅ | 값 — **셋 중 하나만** 갖는다. 직접 입력한 글 / 전표 `values`의 키 / 표시 전 가공 수식 |
| `fontColor` | — | 막대·점 색 (생략하면 검정) |
| `backgroundColor` | — | 바탕색 (생략하면 없음) |

종류: `qrcode` · `code128` · `ean13` · `code39` · `ean8` · `upca` · `upce` · `itf14` · `nw7` ·
`japanpost` · `gs1datamatrix` · `pdf417`. 전표에 흔한 앞의 셋을 먼저 적었다.

종류마다 값 규칙이 다르다(EAN-13은 숫자 13자리, CODE39는 대문자·숫자 등). **어긋난 값은 렌더가
실패한다** — 파일 검증 단계에서는 막지 않는다.

{ "schemaVersion": "0.1.0", "kind": "template", "template": { ...양식 본문(§4)... } }

## 7. 전표 파일 (`kind: "voucher"`)

```json
{
  "schemaVersion": "0.1.0",
  "kind": "voucher",
  "templateSnapshot": { ...양식 본문(§4)... },
  "values": { "total": 3000, "items": [ { "품명": "노트", "금액": 3000 } ] },
  "issued": true
}
```

| 필드 | 필수 | 내용 |
|---|---|---|
| `templateSnapshot` | ✅ | **생성 시점 양식 전체의 복사본** (ADR-008). 이후 원본 양식이 바뀌어도 전표는 불변 |
| `values` | ✅ | 파라미터 키 → 값(JSON 값). `grid.repeat.parameter` 키에는 객체 배열을 담는다 |
| `issued` | ✅ | 발행(확정·잠금) 여부 |

### 7.1 발행(issued) 규칙

발행은 값을 확정해 **잠그는** 것이다(작성폼은 발행 후 입력을 막는다). `issued: true`인 파일은:

1. `templateSnapshot` 안의 어떤 `src`도 **외부 URL이면 안 된다** — 발행 시점에
   base64(`data:`) 또는 `asset://` 내장 리소스로 변환해야 한다 (ADR-036, 파일 단독 완결).

`issued: false`(작성 중)인 파일은 외부 URL 참조가 허용된다.

## 8. 암호화 (선택, ADR-054)

`.slip` 파일 내용을 대칭키로 잠가, 편집기로 열어도 내용이 보이지 않게 하는 **선택** 기능이다.
`@omdc-slipkit/core`의 `encryptSlipFile`·`decryptSlipFile`이 구현이며, Web Crypto API로 동작한다.

- **암호 알고리즘**: AES-256-GCM (인증 암호 — 잘못된 키·변조는 복호화 실패로 걸러진다).
- **키**: 호스트가 공급한다. 32바이트 원시 키, 또는 암호(passphrase)를 **PBKDF2-SHA256**(반복
  210,000회)으로 파생. 키 관리·전달은 호스트 책임이다.
- **표준 교환성 제한**: 잠근 파일은 표준 `.slip`이 **아니다**. 다른 시스템은 같은 키로 복호화해야
  읽을 수 있다.

### 8.1 봉투 형식

암호화 파일은 아래 JSON이다. 최상위 `slipkit: "encrypted"`로 표준 `.slip`과 구분한다.

```json
{
  "slipkit": "encrypted",
  "v": 1,
  "cipher": "A256GCM",
  "kdf": { "algo": "PBKDF2-SHA256", "salt": "<base64url>", "iterations": 210000 },
  "iv": "<base64url>",
  "data": "<base64url: AES-GCM 암호문 + 인증 태그>"
}
```

| 필드 | 필수 | 내용 |
|---|---|---|
| `slipkit` | ✅ | 표식 — 항상 `"encrypted"` |
| `v` | ✅ | 봉투 형식 버전 (현재 1) |
| `cipher` | ✅ | `"A256GCM"` |
| `kdf` | 암호 사용 시 | 암호(passphrase) 파생 정보. 원시 키로 잠갔으면 **없다** |
| `iv` | ✅ | AES-GCM 초기화 벡터 (12바이트, base64url) |
| `data` | ✅ | 직렬화된 `.slip`(§2~§7)을 암호화한 바이트 (base64url) |

복호화하면 안쪽 `.slip`을 §9 검증 수준대로 검증한다 — 키가 맞아도 내용이 규칙에 어긋나면 거부한다.

## 9. 검증 수준

1. **구조 검증**: 동봉 JSON Schema(§10)로 언어 무관 기계 검증.
2. **교차 규칙 검증**: JSON Schema로 표현되지 않는 교차 필드 규칙 — 비율 합 100,
   그리드 셀 범위·겹침, `asset://` 참조 해소, 요소/에셋 id 유일성, §7.1 발행 규칙.
   레퍼런스 구현(`parseSlipFile`)이 기준이다.

## 10. JSON Schema 동봉 (ADR-022)

`@omdc-slipkit/core` 패키지의 `schemas/` 디렉터리에 Zod 스키마에서 산출한
JSON Schema(draft 2020-12)를 동봉한다:

- `schemas/slip-<schemaVersion>.schema.json` — 버전별
- `schemas/slip.schema.json` — 최신 별칭
- `$id`: `urn:slipkit:schema:slip:<schemaVersion>`

코드에서는 `slipFileJsonSchema()`로 같은 것을 얻을 수 있다.
재생성: `pnpm --filter @omdc-slipkit/core build && pnpm --filter @omdc-slipkit/core generate:schemas`.

## 11. 확장 예약 (비규범)

- **ZIP 컨테이너** (ADR-007): 대용량 리소스가 필요해지면 현재 JSON을 manifest로 하는
  ZIP 컨테이너를 추가한다. `asset://` 참조가 그대로 컨테이너 내 파일을 가리키게 되며
  스키마 변경은 없어야 한다.
- **동적 행 표 셀 병합, 요소 그룹화** 등은 v2 (ADR-020).
