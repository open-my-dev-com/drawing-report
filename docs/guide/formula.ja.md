# 数式の記述と関数リファレンス

[한국어](formula.md) · [English](formula.en.md)

SlipKit の数式は、テンプレートに入力された値の計算、表示形式への変換、条件付き書式を適用するかどうかの判定に使います。

フィールド、グリッドセル、バーコードの表示値と、テキスト・フィールド・グリッドセルの条件付き書式に数式を使用できます。数式では次のような処理を行えます。

- 品目ごとの金額の合計
- 数量と単価を使った金額計算
- 条件に応じた文言の表示
- 数値と日付の表示形式の変更
- 消費税の計算
- 日付の加算と期間の計算

このドキュメントでは、数式の記述ルールと、SlipKit が提供する内蔵関数 32 種を説明します。

> [!NOTE]
> SlipKit の数式は JavaScript コードを実行しません。
> 登録された演算子と関数のみを、独自の数式エンジンで解釈します。

## 数式を書ける場所

| 場所 | 数式で参照できる値 | 使用例 |
|---|---|---|
| フィールド | 伝票の全体の値 | 合計、税額、表示用の文言 |
| バーコード | 伝票の全体の値 | 注文番号の組み立て、バーコード値の生成 |
| データ繰り返し領域の外のグリッドセル | 伝票の全体の値 | 表の下部の合計 |
| データ繰り返し領域の中のグリッドセル | 伝票の全体の値と現在の繰り返し項目 | 行ごとの金額計算 |
| テキスト・フィールド・データ繰り返し領域外のセルの条件付き書式 | 伝票の全体の値 | 負の金額や特定の状態の強調 |
| データ繰り返し領域内のセルの条件付き書式 | 伝票の全体の値と現在の繰り返し項目 | 条件に一致する行の強調 |

フィールド、バーコード、またはグリッドのセルを選択してから、値の種類を <kbd>数式</kbd> に変更すると、数式を入力できます。

条件付き書式の条件式も同じ構文と関数を使用しますが、結果は真偽値でなければなりません。テキスト、フィールド、またはグリッドセルを選択し、<kbd>条件付き書式</kbd>で条件式を入力します。

![数式の編集ウィンドウ](images/ja/formula.png)

数式の編集ウィンドウでは、次の機能を提供します。

- パラメータとリストフィールドの挿入
- サポート関数の確認
- 文法エラーの確認
- サンプル値を使った計算結果の確認

表示値の数式については、フォームデザイナー利用ガイドの[数式を書く](designer.ja.md#7-数式を書く)を確認してください。条件式については、[条件付き書式を設定する](designer.ja.md#8-条件付き書式を設定する)を確認してください。

## クイックスタート

次のような伝票の値があると仮定します。

```json
{
  "customerName": "ハンビット商事",
  "shippingFee": 3000,
  "items": [
    {
      "name": "コピー用紙",
      "quantity": 2,
      "unitPrice": 5000,
      "amount": 10000
    },
    {
      "name": "ボールペン",
      "quantity": 3,
      "unitPrice": 1000,
      "amount": 3000
    }
  ]
}
```

すべての品目金額を合計します。

```text
SUM(items.amount)
→ 13000
```

送料を含めた総額を計算します。

```text
SUM(items.amount) + shippingFee
→ 16000
```

表示する文言を作ります。

```text
CONCAT(customerName, " 御中")
→ "ハンビット商事 御中"
```

総額に桁区切り記号を適用します。

```text
CONCAT(FORMAT_NUMBER(SUM(items.amount) + shippingFee), "ウォン")
→ "16,000ウォン"
```

繰り返しグリッドの中では、現在の項目のフィールドを名前で直接参照できます。

```text
quantity * unitPrice
```

> [!IMPORTANT]
> データ繰り返し領域の中では、現在の項目のフィールドが、同じ名前の伝票最上位の値より優先されます。
> 全体のリストは、これまでどおり `items.amount` の形で参照できます。

### 繰り返しグリッドの計算範囲

行範囲の数式では、`@` で始まる予約参照を使って計算範囲を指定できます。

| 参照 | 範囲 | 例 |
|---|---|---|
| `@item` | 現在の項目 | `@item.amount` |
| `@group` | 現在のグループに含まれる項目 | `SUM(@group.amount)` |
| `@page` | 現在の出力ページに含まれる項目 | `SUM(@page.amount)` |
| `@carried` | 現在の出力ページより前に配置された項目 | `SUM(@carried.amount)` |
| `@all` | 出力対象の全項目 | `SUM(@all.amount)` |

空の項目はこれらの計算範囲に含まれません。<kbd>最大項目数</kbd>を設定した場合、制限適用後の項目だけが `@all` に含まれます。

デザイナーの <kbd>グループ小計</kbd>、<kbd>ページ小計</kbd>、<kbd>最終合計</kbd> のかんたん設定は、それぞれ `@group`、`@page`、`@all` の数式を作成します。予約参照は、出力計画から該当する範囲が渡される繰り返しグリッドの行で使用します。

## 数式の記述ルール

### 値と参照

| 種類 | 書き方 | 例 |
|---|---|---|
| 数値 | 数値をそのまま書く | `1500`, `-3.5`, `1e3` |
| 文字列 | 二重引用符で囲んで書く | `"完了"` |
| 論理値 | `TRUE` または `FALSE` | `TRUE` |
| パラメータ | パラメータキーを書く | `totalAmount` |
| 下位フィールド | ピリオドでパスをつなぐ | `customer.name` |
| リスト範囲 | リストと下位フィールドをつなぐ | `items.amount` |

文字列の中に二重引用符を入れるには、二重引用符を 2 回書きます。

```text
"ハン ""ビット"""
→ ハン "ビット"
```

パラメータとフィールドの名前は、次のルールに従うと数式で参照できます。

- 文字またはアンダースコア(`_`)で始める
- その後は、文字、数字、アンダースコアを使える
- 韓国語を含む Unicode 文字を使える
- 空白、ハイフン(`-`)、特殊文字は使えない

```text
totalAmount     正しい
총금액           正しい
_item1          正しい
item-price      数式の参照名として使えない
1stItem         数字で始まるので使えない
```

> [!TIP]
> テンプレートのパラメータを作るときから、英字・韓国語の文字、数字、アンダースコアだけを使えば、数式参照の問題を防げます。

### 演算子

| 分類 | 演算子 | 説明 |
|---|---|---|
| 算術 | `+` | 加算 |
| 算術 | `-` | 減算または負の符号 |
| 算術 | `*` | 乗算 |
| 算術 | `/` | 除算 |
| 比較 | `=` | 等しい |
| 比較 | `<>` | 等しくない |
| 比較 | `<` | より小さい |
| 比較 | `>` | より大きい |
| 比較 | `<=` | 以下 |
| 比較 | `>=` | 以上 |

演算の優先順位は次のとおりです。

1. 括弧
2. 単項符号 `+`、`-`
3. 乗算と除算
4. 加算と減算
5. 比較

```text
1 + 2 * 3
→ 7

(1 + 2) * 3
→ 9
```

> [!IMPORTANT]
> `+` は数値の加算にのみ使います。
> 文字列を連結するには `CONCAT` を使ってください。

### 値の型

SlipKit の数式の値は、次の 5 つの型に分けられます。

- 数値
- 文字列
- 論理値
- 空の値
- 範囲

数値を要求する演算や関数は、文字列を自動的には数値に変換しません。

```text
amount * 2
```

`amount` が文字列 `"1500"` なら、上の数式はエラーになります。明示的に変換する必要があります。

```text
TO_NUMBER(amount) * 2
→ 3000
```

通常の比較演算は、同じ型どうしを比較します。

```text
3 = 3
→ TRUE

3 = "3"
→ FALSE

TO_STRING(3) = "3"
→ TRUE
```

`<`、`>`、`<=`、`>=` の比較は、数値どうし、または文字列どうしでのみ使えます。

> [!NOTE]
> `SUMIF` と `COUNTIF` の条件文字列は、通常の比較演算とは別の条件比較ルールを使います。
> 数値として解釈できる条件文字列は、数値の値と比較できます。

### 空の値

存在しないパラメータや、値が指定されていない参照は、空の値として扱われます。

空の値は、使う場所によって異なる扱いになります。

| 使う場所 | 扱い |
|---|---|
| 算術演算 | `0` |
| `SUM`, `AVG`, `MIN`, `MAX` | 集計の対象から除外 |
| `COUNT` | 個数から除外 |
| `CONCAT`, `TO_STRING` | 空文字列 |
| 条件 | 偽 |
| 通常の比較 | 別の型の値と等しくない |

空文字列 `""` は集計関数から除外されますが、直接算術演算に使うとエラーになります。

> [!CAUTION]
> 存在しないパラメータも空の値になるため、名前を間違えて入力しても、必ずしも文法エラーになるとは限りません。
> デザイナーのサンプルデータで結果を確認してください。

### 範囲

リストパラメータの下位フィールドを参照すると、範囲が作られます。

```text
items.amount
```

範囲は、`SUM`、`AVG`、`COUNT`、`MIN`、`MAX`、`SUMIF`、`COUNTIF` のような集計関数に渡せます。

```text
SUM(items.amount)
```

範囲を算術演算に直接使うことはできません。

```text
items.amount + 1000
→ エラー
```

集計関数を使う必要があります。

```text
SUM(items.amount) + 1000
```

リスト項目にそのフィールドがなければ、その項目の値は空の値として扱われます。

## 関数を一覧で見る

| 分類 | 関数 |
|---|---|
| 集計 | `SUM`, `AVG`, `COUNT`, `MIN`, `MAX` |
| 条件付き集計 | `SUMIF`, `COUNTIF` |
| 算術 | `ROUND`, `FLOOR`, `CEIL`, `ABS` |
| 文字列 | `CONCAT`, `LEFT`, `RIGHT`, `MID`, `REPLACE`, `TRIM`, `UPPER`, `LOWER` |
| 条件 | `IF`, `AND`, `OR` |
| 表示形式 | `FORMAT_NUMBER`, `FORMAT_DATE`, `NUMBER_TO_KOREAN` |
| 日付 | `TODAY`, `DATE_ADD`, `DATE_DIFF` |
| 税務 | `VAT` |
| 型変換 | `TO_NUMBER`, `TO_STRING`, `TO_DATE` |

関数名は大文字と小文字を区別しません。

```text
SUM(items.amount)
sum(items.amount)
```

2 つの数式は同じ関数として扱われます。

登録されていない関数は、文法解析の段階で拒否されます。

## 集計関数

### `SUM`

`SUM(値, ...)`

数値と範囲の合計を計算します。複数の値と範囲を一緒に渡せます。

空の値と空文字列は除外します。集計対象に数値でない値があるとエラーになります。

```text
SUM(items.amount)
→ 品目金額の合計

SUM(items.amount, shippingFee)
→ 品目金額の合計 + 送料

SUM()
→ 0
```

### `AVG`

`AVG(値, ...)`

数値と範囲の平均を計算します。

空の値と空文字列は除外し、平均を計算する数値が一つもなければエラーになります。

```text
AVG(items.unitPrice)
```

### `COUNT`

`COUNT(値, ...)`

空の値と空文字列を除いた項目数を返します。

数値だけでなく、文字列と論理値も、値があれば個数に含まれます。

```text
COUNT(items.name)
→ 品名が入力された項目数
```

### `MIN`

`MIN(値, ...)`

最も小さい数値を返します。計算する数値がなければ `0` を返します。

```text
MIN(items.unitPrice)
```

### `MAX`

`MAX(値, ...)`

最も大きい数値を返します。計算する数値がなければ `0` を返します。

```text
MAX(items.amount)
```

## 条件付き集計関数

### `SUMIF`

`SUMIF(条件範囲, 条件, 合計範囲?)`

条件に合う項目だけを合計します。

合計範囲を省略すると、条件範囲の値を合計します。

```text
SUMIF(items.category, "食品", items.amount)
→ category が "食品" の項目の amount の合計

SUMIF(items.amount, ">=10000")
→ 10000 以上の amount の合計
```

条件範囲と合計範囲を一緒に使うとき、2 つの範囲の長さが異なるとエラーになります。

合計対象の空の値と空文字列は除外します。条件に合う合計対象が数値でないとエラーになります。

### `COUNTIF`

`COUNTIF(範囲, 条件)`

条件に合う項目数を返します。

```text
COUNTIF(items.status, "完了")
→ status が "完了" の項目数

COUNTIF(items.quantity, ">4")
→ quantity が 4 より大きい項目数
```

### 条件文字列

`SUMIF` と `COUNTIF` は、次の条件文字列をサポートします。

| 条件 | 意味 |
|---|---|
| `"食品"` | `"食品"` と等しい |
| `"=食品"` | `"食品"` と等しい |
| `"<>完了"` | `"完了"` と等しくない |
| `">=10"` | 10 以上 |
| `">10"` | 10 より大きい |
| `"<=10"` | 10 以下 |
| `"<10"` | 10 未満 |

比較演算子のない条件は、等しいかどうかの比較として扱います。

数値比較の条件は、条件文字列の比較対象が数値として解釈できるときのみ動作します。

```text
COUNTIF(items.quantity, "3")
COUNTIF(items.quantity, "=3")
```

どちらの数式も、数値 `3` の項目を数えられます。

> [!CAUTION]
> `"<>"` の条件は、空の値も指定した値と異なると判断します。
> たとえば `COUNTIF(items.status, "<>完了")` には、状態が空の項目も含まれます。

## 算術関数

### `ROUND`

`ROUND(数, 桁数?)`

指定した桁数で四捨五入します。桁数を省略すると、整数に四捨五入します。

桁数は整数である必要があり、負の数を指定すると、十・百・千の単位で四捨五入できます。

```text
ROUND(1234.567, 2)
→ 1234.57

ROUND(1234.567)
→ 1235

ROUND(1234.567, -2)
→ 1200
```

### `FLOOR`

`FLOOR(数, 桁数?)`

指定した桁数で、小さい方向へ切り捨てます。

```text
FLOOR(1234.567, 1)
→ 1234.5

FLOOR(-15, -1)
→ -20
```

### `CEIL`

`CEIL(数, 桁数?)`

指定した桁数で、大きい方向へ切り上げます。

```text
CEIL(1234.001, 2)
→ 1234.01
```

### `ABS`

`ABS(数)`

数値の絶対値を返します。

```text
ABS(-500)
→ 500
```

## 文字列関数

### `CONCAT`

`CONCAT(値, ...)`

複数の値を文字列に変換してつなぎます。

数値と論理値は文字列に変換され、空の値は空文字列として扱われます。範囲は直接連結できません。

```text
CONCAT("合計: ", 1000, "ウォン")
→ "合計: 1000ウォン"

CONCAT(customerName, " 御中")
→ "ハンビット商事 御中"
```

### `LEFT`

`LEFT(文字列, 文字数?)`

文字列の左から、指定した数だけ返します。文字数を省略すると、1 文字を返します。

文字数が `0` 以下なら、空文字列を返します。

```text
LEFT("取引明細書", 2)
→ "取引"
```

### `RIGHT`

`RIGHT(文字列, 文字数?)`

文字列の右から、指定した数だけ返します。文字数を省略すると、1 文字を返します。

文字数が `0` 以下なら、空文字列を返します。

```text
RIGHT("取引明細書", 3)
→ "明細書"
```

### `MID`

`MID(文字列, 開始位置, 長さ)`

指定した開始位置から、文字列の一部を返します。開始位置は `1` から数えます。

開始位置は 1 以上の整数である必要があります。長さが `0` 以下なら、空文字列を返します。

```text
MID("取引明細書", 3, 2)
→ "明細"
```

### `REPLACE`

`REPLACE(文字列, 検索文字列, 置換文字列)`

一致するすべての文字列を置き換えます。

```text
REPLACE("2026-08-25", "-", "/")
→ "2026/08/25"
```

検索文字列が空なら、元の文字列をそのまま返します。

### `TRIM`

`TRIM(文字列)`

文字列の前後の空白を取り除きます。文字列の途中の空白は残します。

```text
TRIM("  ハンビット商事  ")
→ "ハンビット商事"
```

### `UPPER`

`UPPER(文字列)`

英字を大文字に変換します。

```text
UPPER("slip-001")
→ "SLIP-001"
```

### `LOWER`

`LOWER(文字列)`

英字を小文字に変換します。

```text
LOWER("SLIP-001")
→ "slip-001"
```

## 条件関数

### `IF`

`IF(条件, 真のとき, 偽のとき?)`

条件が真なら 2 番目の引数を、偽なら 3 番目の引数を返します。

偽のときの値を省略すると、条件が偽のとき空の値を返します。

```text
IF(totalAmount >= 100000, "大量", "通常")

IF(isPaid, "決済完了")
```

`IF` は選ばれた結果だけを計算します。使われない側の数式は評価しません。

```text
IF(quantity = 0, 0, amount / quantity)
```

数量が `0` なら除算を実行しないため、0 での除算エラーは発生しません。

### `AND`

`AND(条件, ...)`

すべての条件が真なら `TRUE` を返します。一つでも偽なら、残りの条件を評価せずに `FALSE` を返します。

一つ以上の条件が必要です。

```text
AND(quantity > 0, unitPrice > 0)
```

### `OR`

`OR(条件, ...)`

一つ以上の条件が真なら `TRUE` を返します。真の条件に出会うと、残りの条件は評価しません。

一つ以上の条件が必要です。

```text
OR(status = "完了", status = "発行")
```

条件には論理値または数値を使えます。

- `TRUE` は真
- `FALSE` は偽
- `0` は偽
- `0` でない数値は真
- 空の値は偽

文字列と範囲は、条件として直接使えません。

## 表示形式関数

### `FORMAT_NUMBER`

`FORMAT_NUMBER(数, 小数桁数?)`

数値にロケール別の桁区切り形式を適用し、文字列で返します。

```text
FORMAT_NUMBER(1234567)
→ "1,234,567"

FORMAT_NUMBER(1234.5, 2)
→ "1,234.50"
```

小数桁数を指定すると、その桁数まで固定して表示します。指定できる範囲は `0` から `20` までです。

表示結果は、数式評価コンテキストの `locale` 設定に従います。`locale` を指定しないと `en-US` を使います。

たとえば `de-DE` では、次のように表示されます。

```text
FORMAT_NUMBER(1234.5)
→ "1.234,5"
```

ロケールの設定方法は[環境設定ガイド](configuration.ja.md#ui-言語の設定)を確認してください。

### `FORMAT_DATE`

`FORMAT_DATE(日付, パターン?)`

日付を指定したパターンに変換し、文字列で返します。パターンを省略すると `YYYY-MM-DD` 形式を使います。

```text
FORMAT_DATE("2026-08-25")
→ "2026-08-25"

FORMAT_DATE("2026-08-25", "YYYY年M月D日")
→ "2026年8月25日"
```

サポートするパターントークンは次のとおりです。

| トークン | 意味 | 例 |
|---|---|---|
| `YYYY` | 4 桁の年 | `2026` |
| `YY` | 2 桁の年 | `26` |
| `MM` | 2 桁の月 | `08` |
| `M` | 月 | `8` |
| `DD` | 2 桁の日 | `05` |
| `D` | 日 | `5` |
| `HH` | 2 桁の時 | `09` |
| `mm` | 2 桁の分 | `30` |
| `ss` | 2 桁の秒 | `00` |

日付と時刻は UTC 基準で処理されます。

実際に存在しない日付は自動補正せず、エラーとして扱います。

```text
FORMAT_DATE("2026-02-30")
→ エラー
```

### `NUMBER_TO_KOREAN`

`NUMBER_TO_KOREAN(整数)`

整数を、韓国語の金額表記に使える文字列に変換します。

十・百・千の前の `일` を省略しません。

```text
NUMBER_TO_KOREAN(0)
→ "영"

NUMBER_TO_KOREAN(110)
→ "일백일십"

NUMBER_TO_KOREAN(123456)
→ "일십이만삼천사백오십육"

NUMBER_TO_KOREAN(-3000)
→ "마이너스삼천"
```

整数のみをサポートし、JavaScript の安全な整数の範囲を超える値はエラーとして扱います。

金額の文言を作るときは、次のように組み合わせられます。

```text
CONCAT("금 ", NUMBER_TO_KOREAN(totalAmount), " 원")
```

## 日付関数

日付関数には ISO 形式の日付文字列を使います。

```text
"2026-08-25"
"2026-08-25T09:30:00Z"
```

日付の計算は UTC 基準で行われます。業務上、特定の地域の日付が重要なら、アプリケーションで `YYYY-MM-DD` の値を作り、パラメータとして渡す方法を推奨します。

### `TODAY`

`TODAY()`

現在時刻の UTC 基準の日付を `YYYY-MM-DD` 形式で返します。

```text
TODAY()
→ "YYYY-MM-DD"
```

数式を直接評価するときは、評価コンテキストに `now` を渡して結果を再現できます。

詳しい使い方は[Core 利用ガイド](core.ja.md#数式を評価する)を確認してください。

### `DATE_ADD`

`DATE_ADD(日付, 増減量, 単位?)`

日付に、指定した期間を加算または減算します。

| 単位 | 意味 |
|---|---|
| `"days"` | 日 |
| `"months"` | 月 |
| `"years"` | 年 |

単位を省略すると `"days"` を使います。増減量は整数である必要があり、負の数を使うと日付を減算できます。

```text
DATE_ADD("2026-08-18", 14)
→ "2026-09-01"

DATE_ADD("2026-08-18", -1, "months")
→ "2026-07-18"

DATE_ADD("2026-08-18", 2, "years")
→ "2028-08-18"
```

月や年を加算した結果に同じ日付が存在しなければ、対象の月の最終日を使います。

```text
DATE_ADD("2026-01-31", 1, "months")
→ "2026-02-28"

DATE_ADD("2024-01-31", 1, "months")
→ "2024-02-29"
```

### `DATE_DIFF`

`DATE_DIFF(開始日, 終了日, 単位?)`

終了日から開始日を引いた差を返します。

| 単位 | 計算結果 |
|---|---|
| `"days"` | 2 つの日付の間の日数 |
| `"months"` | 完了した月数 |
| `"years"` | 完了した年数 |

単位を省略すると `"days"` を使います。

```text
DATE_DIFF("2026-08-01", "2026-08-18")
→ 17

DATE_DIFF("2026-01-31", "2026-03-01", "months")
→ 1

DATE_DIFF("2024-08-18", "2026-08-17", "years")
→ 1
```

終了日が開始日より早ければ、負の数を返します。

## 税務関数

### `VAT`

`VAT(供給価額, 税率?)`

供給価額に対する消費税額を計算します。税率を省略すると `10` を使います。

税率はパーセントの数値で指定します。

```text
VAT(10000)
→ 1000

VAT(10000, 8)
→ 800
```

`VAT` は計算結果を自動的には四捨五入も切り捨てもしません。必要な処理方法を明示的に組み合わせてください。

```text
FLOOR(VAT(12345))
→ 1234

ROUND(VAT(12345))
→ 1235
```

税率には `0` 以上の数値のみを使えます。

> [!IMPORTANT]
> `VAT` は供給価額と税率を使った単純計算の関数です。
> 実際の税務処理に必要な課税区分、免税、複数税率、計算単位と丸めのポリシーは、使うアプリケーションで決める必要があります。

## 型変換関数

### `TO_NUMBER`

`TO_NUMBER(値)`

値を数値に変換します。

| 入力 | 結果 |
|---|---|
| 数値 | 同じ数値 |
| 数値形式の文字列 | 変換された数値 |
| `TRUE` | `1` |
| `FALSE` | `0` |
| 空の値 | `0` |
| 空文字列 | `0` |

```text
TO_NUMBER("1500")
→ 1500

TO_NUMBER("-3.5")
→ -3.5

TO_NUMBER(TRUE)
→ 1
```

前後の空白は取り除いてから変換します。10 進数と指数表記はサポートしますが、次の文字列は数値に変換しません。

- 桁区切り記号を含む値: `"1,500"`
- 16 進数: `"0x1F"`
- 無限大: `"Infinity"`
- 数値でない文字列: `"金額"`

桁区切り記号を含む値を変換する必要があれば、先に区切り記号を取り除きます。

```text
TO_NUMBER(REPLACE("1,500", ",", ""))
→ 1500
```

範囲は数値に変換できません。

### `TO_STRING`

`TO_STRING(値)`

数値、論理値、空の値を文字列に変換します。

| 入力 | 結果 |
|---|---|
| `1500` | `"1500"` |
| `TRUE` | `"TRUE"` |
| `FALSE` | `"FALSE"` |
| 空の値 | `""` |
| 文字列 | 元の文字列 |

範囲は文字列に変換できません。

```text
TO_STRING(3) = "3"
→ TRUE
```

### `TO_DATE`

`TO_DATE(値)`

日付文字列を検証し、UTC 基準の `YYYY-MM-DD` 形式に変換します。

```text
TO_DATE("2026-01-05")
→ "2026-01-05"

TO_DATE("2026-01-05T09:30:00Z")
→ "2026-01-05"
```

実際に存在しない日付や、日付として解釈できない値は、エラーとして扱います。

## エラーの確認

数式のエラーは、大きく 2 種類に分けられます。

| 種類 | 発生例 |
|---|---|
| 文法エラー | 閉じていない括弧、不正な文字、サポートしない関数 |
| 計算エラー | 型の不一致、0 での除算、不正な日付 |

デザイナーでは、数式の編集ウィンドウに、文法エラーとサンプル値を使った計算結果が表示されます。条件式をサンプル値で計算できる場合は、結果が真偽値かどうかも確認します。

PDF を生成するときに表示値の数式の計算が失敗すると、対象のフィールド、グリッドセル、またはバーコードを示すレンダリングエラーが発生します。

条件式の構文が正しくない場合や、結果が真偽値でない場合もレンダリングエラーになります。必要な値がない、型が一致しないなどの理由で条件式を計算できない場合は、そのルールを適用せずに残りのレンダリングを続行します。

### よくある問題

| 問題 | 確認する内容 |
|---|---|
| 数値計算で型エラーが発生する | パラメータの型が数値かを確認し、文字列なら `TO_NUMBER` を使う |
| 範囲を直接使えないというエラーが発生する | `SUM`、`AVG` などの集計関数を使う |
| 数式の結果が空になる | パラメータ名とサンプルデータを確認 |
| 存在しない関数というエラーが発生する | このドキュメントのサポート関数一覧を確認 |
| 日付計算が予想と異なる | 入力値が ISO 形式か、UTC 基準かを確認 |
| バーコードのレンダリングが失敗する | 数式の結果が、選んだバーコード種類の形式と一致するかを確認 |
| `COUNTIF` の結果が予想より大きい | `<>` の条件に空の値が含まれていないかを確認 |
| `3 = "3"` が偽になる | 同じ型に変換してから比較 |

> [!TIP]
> 数式を書いた後は、できるだけ実際に近いサンプルデータを入力し、通常の値、空の値、リストがない場合を一緒に確認してください。

## 数式の制限

安全な実行のために、次の制限が適用されます。

| 項目 | 制限 |
|---|---:|
| 数式文字列の長さ | 最大 10,000 文字 |
| 数式のネストの深さ | 最大 100 段階 |
| 値データのネストの深さ | 最大 256 段階 |

制限を超えた数式や値は、エラーとして扱われます。

数式では、次の機能を使えません。

- 任意の JavaScript の実行
- ユーザー定義関数の呼び出し
- オブジェクト値の直接の返却
- 範囲に対する直接の算術演算
- `==`、`!=`、`&&`、`||` 演算子
- 外部 API またはネットワーク呼び出し

## 完了確認

数式を適用する前に、次の項目を確認してください。

- [ ] パラメータとリストフィールドの名前を正確に参照した。
- [ ] 数値計算に数値型の値を使った。
- [ ] 文字列の数値があれば `TO_NUMBER` で変換した。
- [ ] リスト範囲を集計関数と一緒に使った。
- [ ] 値とリストが空のときの結果を確認した。
- [ ] 税額の四捨五入または切り捨ての方法を明示した。
- [ ] 日付が ISO 形式で、UTC 基準であることを確認した。
- [ ] デザイナーでサンプルデータで結果を確認した。
- [ ] バーコードの数式結果が、バーコード形式のルールと一致する。
- [ ] PDF プレビューで最終的な表示結果を確認した。
