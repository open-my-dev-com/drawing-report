## 1. 제품 정의

| 항목 | 내용 | 근거 |
|---|---|---|
| 제품 성격 | **범용 양식 엔진**. 문서형 전표(거래명세서·청구서·견적서 등)와 회계형 전표를 모두 "양식(템플릿)"으로 표현할 수 있어야 한다 | ADR-001 |
| 사용 형태 | 외부 프로젝트가 npm 등으로 **설치(install)해서 자신의 앱에 임베드**하는 패키지. 독립 실행 앱이 아니다 | ADR-002 |
| 주 사용자 | **양식 제작: 일반 사용자(비개발자)** — GUI 디자이너 필수. 전표 작성/조회: 일반 사용자 | ADR-005 |

## 2. 아키텍처

| 항목 | 내용 | 근거 |
|---|---|---|
| 패키지 구조 | 계층형 모노레포: `core`(순수 TS 로직) / `elements`(Web Component UI) / `react`·`vue`(얇은 래퍼) | ADR-002, ADR-003 |
| UI 배포 형태 | **Web Component**(`<voucher-designer>`, `<voucher-viewer>` 등)로 배포하여 호스트 앱의 프레임워크와 무관하게 동작. React/Vue 사용자를 위한 얇은 래퍼 패키지를 별도 제공 | ADR-003 |
| core의 위치 | 파일 포맷 스키마·검증·마이그레이션·수식 평가·레이아웃 엔진·PDF 렌더러는 전부 core(순수 TS, DOM 비의존)에 둔다. UI는 core의 소비자일 뿐이다 | ADR-003, ADR-011 |

## 3. 권한 모델

| 항목 | 내용 | 근거 |
|---|---|---|
| 권한 주체 | **호스트 앱에 위임**. 패키지는 자체 유저/인증 시스템을 갖지 않는다 | ADR-004 |
| 인터페이스 | 컴포넌트가 `mode`(edit/view 등)·권한 플래그를 속성으로 받는다. 누가 어떤 권한을 갖는지는 설치한 앱이 결정 | ADR-004 |

## 4. 외부 연계

확정된 연계 방식 3가지 (ADR-006):

1. **호스트 데이터 주입**: 호스트 앱이 자기 데이터(거래처, 품목 등)를 넘기면 양식에 바인딩되어 렌더
2. **저장소 어댑터**: 저장/불러오기를 인터페이스로 추상화. 로컬 파일, S3, DB, 자체 서버 등 어디든 붙일 수 있게
3. **표준 교환 파일 포맷**: 전표 파일 자체가 명세화된 포맷이라 다른 시스템이 파일을 읽고 쓸 수 있게

> REST API 서버 제공은 범위에서 **제외** (호스트가 필요 시 직접 구성).

## 5. 파일 포맷

| 항목 | 내용 | 근거 |
|---|---|---|
| 포맷 | **JSON 기반 자체 스키마** (전용 확장자 사용, 예: `.vchr` — 명칭 미확정) | ADR-007 |
| 스키마 버전 | 모든 파일에 `schemaVersion` 내장. 구버전 파일을 열 때 자동 마이그레이션하는 계층을 core에 처음부터 둔다 | ADR-007 |
| 이미지 참조 | `src` 필드로 통일하며 3종 지원: 외부 URL / `data:`(base64 내장) / `asset://`(내부 리소스 참조) | ADR-007 |
| 컨테이너 확장 | v1은 순수 JSON 단일 파일. 대용량 리소스 필요 시 동일 JSON을 manifest로 하는 ZIP 컨테이너를 **추후** 추가할 수 있는 구조로 스키마를 설계(`asset://` 참조가 이를 위한 장치) | ADR-007 |
| 템플릿-데이터 분리 | 양식(템플릿)과 전표 데이터(기입값)는 별도 구조. 양식 하나로 전표 N장을 생성 | ADR-001 |
| 양식 버저닝 | 전표 파일은 **생성 시점의 양식 전체를 스냅샷으로 내장**한다. 발행된 전표는 이후 양식이 수정되어도 절대 모양이 바뀌지 않으며, 파일 단독으로 열람 가능(자기완결) | ADR-008 |

## 6. 보안

| 항목 | 내용 | 근거 |
|---|---|---|
| 위변조 방지 서명 | 전표 내용의 해시/서명을 파일에 내장하여 "발행 후 수정되지 않았음"을 검증 가능하게 한다. **기본 제공** | ADR-009 |
| 암호화 | 파일 내용 암호화를 **옵션**으로 제공(필수 아님). 키 관리는 호스트 책임. 암호화된 파일은 표준 교환성이 제한됨을 명시 | ADR-009 |
| 수식 안전성 | 수식은 자체 파서로 해석. 임의 코드 실행(`eval`, `Function` 등) 절대 금지 | ADR-010 |

## 7. 수식(계산 필드)

| 항목 | 내용 | 근거 |
|---|---|---|
| 방식 | **내장 수식 엔진**. 양식 필드에 엑셀 스타일 수식 문자열을 기입 | ADR-010 |
| 함수 범위 | 모든 함수를 넣지 않고 **자주 쓰이는 함수를 엄선**한 세트로 시작. 스타터셋 초안은 OPEN-QUESTIONS.md의 Q-02에서 확정 예정 | ADR-010 |
| 함수 분류(초안) | 집계(SUM/AVG/COUNT/MIN/MAX), 산술(ROUND 등), 문자열(자르기/치환/연결 등), 조건(IF/AND/OR), 포맷(천단위 콤마, 날짜, 금액 한글 표기), 날짜(TODAY/DATE_ADD/DATE_DIFF) | ADR-010 |

## 8. 레이아웃 · 페이지 · 출력

| 항목 | 내용 | 근거 |
|---|---|---|
| 레이아웃 기준 | **용지(A4 등) 기준** 절대 좌표계. 화면·인쇄·PDF가 동일 레이아웃 | ADR-011 |
| 복수 페이지 | 페이지는 스키마의 1급 개념(`pages` 배열) | ADR-011 |
| 자동 페이지 분할 | **필수 기능.** 표(품목 리스트)가 페이지를 넘치면 자동으로 다음 페이지로 분할. 헤더 반복, 페이지별 소계 등의 옵션 포함 | ADR-011 |
| 렌더링 구조 | `양식+데이터 → 레이아웃 엔진(core) → 렌더 트리 → {화면 렌더러, PDF 렌더러}`. 좌표 계산은 core에서 단 한 번 — 화면과 PDF의 불일치가 구조적으로 불가능하게 | ADR-012 |
| PDF 생성 | **브라우저에서 클라이언트 직접 생성**(pdf-lib 계열). 서버 왕복 없음, 전표 데이터가 브라우저 밖으로 나가지 않음. DOM 캡처(스크린샷) 방식 금지 — 벡터 텍스트 유지 | ADR-012 |
| 서버 렌더러 | 추후 확장: 동일 core+PDF 렌더러를 Node 패키지로 재포장하여 **호스트 인프라에서** 일괄 발행 자동화에 사용. 제3자 외부 서버는 어떤 경우에도 개입하지 않음 | ADR-012 |
| 인쇄 | 생성된 PDF를 인쇄하는 방식 — 종이 출력까지 화면과 일치 | ADR-012 |
| 폰트 | PDF에 폰트 내장(한글 폰트는 사용 글자만 서브세팅). 기본 한글 폰트 1종 동봉 + **사용자가 자기 폰트를 업로드/등록해서 쓸 수 있어야 함** | ADR-012 |

## 10. GUI 디자이너 (v1의 주인공)

- 비개발자가 드래그앤드롭으로 양식을 설계하는 에디터 (ADR-005)
- 요소 배치(텍스트, 표, 이미지, 선/도형, 입력 필드), 용지 설정, 수식 입력, 실시간 미리보기
- 세부 기능 범위는 OPEN-QUESTIONS.md Q-05에서 구체화 예정

## 11. 범위 제외 (Non-goals)

- 자체 유저/인증/조직 관리 시스템 (호스트 위임 — ADR-004)
- REST API 서버 제공 (ADR-006)
- 제3자 호스팅 서비스(SaaS) — 데이터가 패키지 설치자의 인프라를 벗어나는 기능 일체 (ADR-012)
- 임의 코드 실행이 가능한 스크립팅 (ADR-010)
