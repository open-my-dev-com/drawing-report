## 4. 외부 연계

확정된 연계 방식 3가지 (ADR-006):

1. **호스트 데이터 주입**: 호스트 앱이 자기 데이터(거래처, 품목 등)를 넘기면 양식에 파라미터되어 렌더
2. **저장소 어댑터**: 저장/불러오기를 인터페이스로 추상화. 로컬 파일, S3, DB, 자체 서버 등 어디든 붙일 수 있게
3. **표준 교환 파일 포맷**: 전표 파일 자체가 명세화된 포맷이라 다른 시스템이 파일을 읽고 쓸 수 있게

> REST API 서버 제공은 범위에서 **제외** (호스트가 필요 시 직접 구성).

### 저장소 어댑터 상세 (ADR-021)

| 항목 | 내용 |
|---|---|
| 필수 인터페이스 | `save` / `load` / `delete` / `list`(페이징·필터 지원) |
| 버전 이력 | 별도의 **선택 인터페이스** — 구현한 어댑터에서만 이력 UI 노출 |
| 기본 동봉 | ① 로컬 파일 다운로드/업로드 ② IndexedDB |
| 구현 위치 | 인터페이스·타입·오류는 core, 브라우저 구현 2종은 elements (ADR-025). 로컬 파일 어댑터는 delete/list 미지원(`unsupported` 오류) |
| IndexedDB 구현 (ADR-045) | 본문을 Blob으로 저장(메타는 형제 필드) — `list()`는 메타만 읽어 본문을 메모리에 안 올린다. 목록 모달은 메타를 한 번 받아 스냅샷으로 쥐고 검색·번호 페이지를 화면에서 처리(중복·누락 없음). 열 때 손상 파일은 오류 표시. DB v1→v2 마이그레이션 |
| 저장 시 암호화 (ADR-055) | 동봉 어댑터 2종은 호스트가 주입하는 `encryption` 설정(`{ enabled, key?, previousKeys? }`)으로 저장 시 자동 암호화한다 — 켜고 키를 주면 그 키로, 켜고 키가 없으면 데모용 샘플 기본키로 잠근다(설정 없으면 평문). 불러오기는 봉투를 자동 감지해 푼다(옛 평문 저장분 호환). 키 변경은 `previousKeys`로 옛 키 파일을 읽고 재저장 때 새 키로 옮긴다. IndexedDB는 본문만 잠그고 목록용 메타(제목 등)는 평문. 실제 암호화는 core가 수행(ADR-054), 어댑터는 시점·키만 정한다 |
| 바코드 종류 공급 | 디자이너 바코드 고르개의 후보를 호스트가 `settings.getBarcodeKinds`로 좁힌다. 주지 않으면 12종을 모두 보인다 | ADR-048 |
| 폰트 공급 | 렌더 폰트는 호스트가 공급 인터페이스(`SlipFontProvider.getFonts`)로 준다 — 디자이너 업로드·저장소 어댑터 보관은 하지 않는다. 공급이 없으면 `locale`에 맞는 동봉 기본 폰트를 쓴다(한국어·영어 Pretendard, 일본어 Noto Sans JP) (ADR-040/042, 옛 ADR-012/021 계획 대체) |

### 교환 포맷 스펙 공개 (ADR-022)

`.slip` 포맷 명세서(SPEC.md)를 공개 문서로 유지하고, Zod 스키마에서 산출한 **JSON Schema를 패키지에 동봉**한다 — 타 시스템이 언어 무관하게 기계 검증 가능.

## 5. 파일 포맷

| 항목 | 내용 | 근거 |
|---|---|---|
| 포맷 | **JSON 기반 자체 스키마**, 확장자 **`.slip`** (양식·전표 파일 공용 — 내부 `kind` 필드로 구분) | ADR-007, ADR-018 |
| 스키마 버전 | 모든 파일에 `schemaVersion` 내장. 구버전 파일을 열 때 자동 마이그레이션하는 계층을 core에 처음부터 둔다 | ADR-007 |
| 파라미터 정의부 | 파라미터(`parameters`)는 물리명 `key` + 논리명 `label` + 값 종류 `valueType`을 갖는다. 목록 종류면 항목의 **하위 필드 `fields`**를 정의부에 선언한다 — 그리드와 무관하게 만들고 고칠 수 있으며, 항목은 평평한 객체라 하위 필드는 다시 하위를 갖지 않는다 | ADR-032, ADR-047 |
| 반복 항목 수 상한 | 그리드 반복 구간에 `maxItems`(선택)를 둘 수 있다. 넘는 항목은 그리지 않고 페이지도 늘리지 않는다 | ADR-048 |
| 스키마 버전 재정리 | 공개 전 개발 단계에서 거친 포맷 버전(0.1.1~0.5.0)은 공개된 적이 없어 첫 버전 **0.1.0** 하나로 합쳤다. 아래 v1·v2 이력·DECISIONS에 남은 0.2.0~0.5.0 표기는 개발 반복을 가리킬 뿐 릴리스 버전이 아니다. 공개(안정 릴리스) 시점에 1.0.0으로 확정한다 | ADR-046 |
| 이미지 참조 | `src` 필드로 통일하며 3종 지원: 외부 URL / `data:`(base64 내장) / `asset://`(내부 리소스 참조) | ADR-007 |
| 이미지 정책 | **base64로만 담는다**: 디자이너는 파일에서 골라 base64로 넣고 주소(URL) 입력은 없다. 전표 데이터로 받는 이미지도 base64만 받는다. 주소로 받아야 하면 **호스트 서버가 중계해 base64로 바꿔 넘긴다** — core는 네트워크를 쓰지 않아 URL을 렌더할 수 없다. 크기 상한은 `maxImageBytes`(기본 2MB). 발행 파일은 외부 URL 없이 완결이어야 한다 | ADR-036 |
| 컨테이너 확장 | v1은 순수 JSON 단일 파일. 대용량 리소스 필요 시 동일 JSON을 manifest로 하는 ZIP 컨테이너를 **추후** 추가할 수 있는 구조로 스키마를 설계(`asset://` 참조가 이를 위한 장치) | ADR-007 |
| 템플릿-데이터 분리 | 양식(템플릿)과 전표 데이터(기입값)는 별도 구조. 양식 하나로 전표 N장을 생성 | ADR-001 |
| 양식 버저닝 | 전표 파일은 **생성 시점의 양식 전체를 스냅샷으로 내장**한다. 발행된 전표는 이후 양식이 수정되어도 절대 모양이 바뀌지 않으며, 파일 단독으로 열람 가능(자기완결) | ADR-008 |

## 6. 보안

| 항목 | 내용 | 근거 |
|---|---|---|
| 발행(확정) | `issued: true`면 값이 확정되어 작성폼이 잠긴다(더 못 고침). 암호·서명과 무관한 상태 | ADR-009, ADR-053 |
| 파일 암호화 | 파일 내용을 대칭키(AES-256-GCM)로 잠그는 **옵션**. 편집기로 열어도 내용이 안 보인다. 키 관리·전달은 호스트 책임이고, 잠근 파일은 다른 시스템과 그대로 주고받을 수 없다 | ADR-054 |
| 수식 안전성 | 수식은 자체 파서로 해석. 임의 코드 실행(`eval`, `Function` 등) 절대 금지 | ADR-010 |

## 7. 수식(계산 필드)

| 항목 | 내용 | 근거 |
|---|---|---|
| 방식 | **내장 수식 엔진**. 양식 필드에 엑셀 스타일 수식 문자열을 기입 | ADR-010 |
| 함수 범위 | 모든 함수를 넣지 않고 **자주 쓰이는 함수를 엄선**한 세트로 시작 | ADR-010 |
| 함수 목록(확정, 32종) | 집계 `SUM AVG COUNT MIN MAX` · 조건부 집계 `SUMIF COUNTIF` · 산술 `+ - * / ROUND FLOOR CEIL ABS` · 문자열 `CONCAT LEFT RIGHT MID REPLACE TRIM UPPER LOWER` · 조건 `IF AND OR` + 비교연산자 · 포맷 `FORMAT_NUMBER FORMAT_DATE NUMBER_TO_KOREAN` · 날짜 `TODAY DATE_ADD DATE_DIFF` · 세무 `VAT` · 타입 변환 `TO_NUMBER TO_STRING TO_DATE` | ADR-017·044 |
| 수식 타입 규칙 | 숫자를 요구하는 자리는 숫자만 받는다(글자 자동 변환 없음, 빈 값=0). 글자 자리는 숫자·논리를 자동 글자화. 글자→숫자는 `TO_NUMBER`로 명시. `number` 파라미터의 빈 값은 받는 시점에 0으로 정규화 | ADR-044 |

## 8. 레이아웃 · 페이지 · 출력

| 항목 | 내용 | 근거 |
|---|---|---|
| 레이아웃 기준 | **용지(A4 등) 기준** 절대 좌표계. 화면·인쇄·PDF가 동일 레이아웃 | ADR-011 |
| 복수 페이지 | 페이지는 스키마의 1급 개념(`pages` 배열) | ADR-011 |
| 자동 페이지 분할 | **필수 기능.** 표(품목 리스트)가 페이지를 넘치면 자동으로 다음 페이지로 분할. 헤더 반복 옵션 포함. **분할 계산은 변환 계층이 직접 한다**(하부 엔진의 분할은 확장할 수 없어서 — ADR-037). 페이지별 소계는 보류(ADR-041) | ADR-011, ADR-037 |
| 렌더링 구조 | `양식+데이터 → 변환 계층(core: 우리 포맷 → pdfme 템플릿, 기본값 병합 필수) → pdfme 엔진 → PDF`. 화면 미리보기도 동일 변환 결과를 사용 — 화면과 PDF의 불일치가 구조적으로 불가능하게 | ADR-012, ADR-016 |
| PDF 생성 | **브라우저에서 클라이언트 직접 생성**(pdfme 엔진, 내부적으로 pdfme 유지보수 pdf-lib 포크). 서버 왕복 없음, 전표 데이터가 브라우저 밖으로 나가지 않음. DOM 캡처(스크린샷) 방식 금지 — 벡터 텍스트 유지 | ADR-012, ADR-016 |
| 서버 렌더러 | 추후 확장: 동일 core+PDF 렌더러를 Node 패키지로 재포장하여 **호스트 인프라에서** 일괄 발행 자동화에 사용. 제3자 외부 서버는 어떤 경우에도 개입하지 않음 | ADR-012 |
| 인쇄 | 생성된 PDF를 인쇄하는 방식 — 종이 출력까지 화면과 일치 | ADR-012 |
| 폰트 | PDF에 폰트 내장(사용 글자만 서브세팅). 언어별 기본 폰트 1종 동봉(한국어·영어 Pretendard, 일본어 Noto Sans JP Regular — `locale`에 맞춰 자동 선택) + **호스트가 공급 인터페이스(`getFonts`)로 폰트를 준다**(디자이너 업로드는 없음) | ADR-012, ADR-040, ADR-042 |

## 9. 국제화(i18n)

| 항목 | 내용 | 근거 |

## 10. GUI 디자이너 (v1의 주인공)

비개발자가 드래그앤드롭으로 양식을 설계하는 에디터 (ADR-005). v1 범위 확정 (ADR-020):

| 항목 | 내용 |
|---|---|

### 10-2. v2에서 더한 것 — 디자이너 사용 편의 (ADR-031)

테마: 새 능력 추가보다 **일반 사용자가 실제로 쓸 수 있는 도구로** 다듬기 — v1에서 포맷·렌더러는 지원하지만
GUI가 못 따라간 구간을 채웠다. UI는 Lit 유지(ADR-015) + 자체 CSS 디자인 토큰(MUI·Tailwind 미도입).

## 11. 개발 규칙

- 브랜치·커밋 규칙은 [`.claude/rules/branching.md`](../.claude/rules/branching.md)를 따른다 (ADR-023). `main` 직접 커밋 금지, 작업은 `<type>/<scope>-<topic>` 브랜치에서 PR로.
- `main`은 **스쿼시 머지** 전용. 미병합 브랜치 위 PR 스택 금지, 브랜치당 커밋 최소화 (ADR-024).
- 개발 규칙은 리포 루트 **`CLAUDE.md`**로 모든 Claude Code 세션에 자동 적용되며, `.claude/settings.json`이 main 직접 푸시를 기계적으로 차단한다 (ADR-024).
