# 요구사항

이 문서는 SlipKit이 충족해야 하는 확정 요구사항을 정의합니다.

- 요구사항의 설계 배경과 결정 과정은 [설계 결정 기록](DECISIONS.md)을 참고합니다.
- `.slip` 파일의 필드와 검증 규칙은 [.slip 파일 형식 명세](SPEC.md)를 참고합니다.
- 패키지 구조와 책임 경계는 [아키텍처](ARCHITECTURE.md)를 참고합니다.
- 예정된 작업과 보류 항목은 [로드맵](ROADMAP.md)을 참고합니다.
- 결정되지 않은 사항은 [미결 사항](OPEN-QUESTIONS.md)에서 관리합니다.

최종 갱신: 2026-09-02

> [!NOTE]
> 이 문서는 구현 진행 상황이나 개발 작업 이력을 기록하지 않습니다.
> 각 요구사항의 완료 여부와 향후 작업은 로드맵과 이슈에서 별도로 관리합니다.

## 1. 문서 규칙

각 요구사항에는 영역별 식별자를 부여합니다.

| 접두사 | 영역 |
| --- | --- |
| `PROD` | 제품 정의 |
| `DIST` | 배포와 실행 환경 |
| `DES` | 양식 디자이너 |
| `FORM` | 전표 작성 |
| `VIEW` | 전표 조회 |
| `FILE` | `.slip` 파일 |
| `CALC` | 수식 |
| `OUT` | PDF와 출력 |
| `STORE` | 저장소와 외부 연계 |
| `CONF` | 설정과 외부 자원 |
| `I18N` | 국제화 |
| `SEC` | 보안과 신뢰 경계 |
| `MCP` | AI 연동 MCP 서버 |
| `DOC` | 공개 문서 |

문서에서 “지원해야 한다” 또는 “제공해야 한다”라고 표현한 항목은 필수 요구사항입니다.

| `PROD-04` | UI 커스텀 엘리먼트는 `slip-*` 접두사를 사용한다. | 공개 Web Component 이름이 `<slip-designer>`, `<slip-form>`, `<slip-viewer>`로 제공된다. | ADR-018 |

| `PROD-07` | 비개발자가 양식을 제작할 수 있는 GUI 디자이너를 제공해야 한다. | 소스 코드나 JSON을 직접 작성하지 않고도 화면에서 양식을 만들고 수정할 수 있다. | ADR-005 |

## 3. 사용자와 주요 사용 흐름

SlipKit은 다음 사용자를 대상으로 합니다.

| 사용자 | 주요 작업 |
| --- | --- |
| 호스트 애플리케이션 개발자 | SlipKit 설치, 화면 구성, 상태 관리, 저장소와 서버 연동 |
| 양식 제작자 | 디자이너에서 양식 생성, 요소 배치, 파라미터와 수식 설정 |
| 전표 작성자 | 양식에 값을 입력하고 전표를 저장하거나 발행 |
| 전표 조회자 | 저장된 양식이나 전표 확인, PDF 조회와 출력 |

대표적인 사용 흐름은 다음과 같습니다.

1. 양식 제작자가 디자이너에서 양식을 만듭니다.
2. 호스트 애플리케이션이 양식을 저장합니다.
3. 전표 작성자가 저장된 양식을 선택합니다.
4. 작성 폼이 양식의 파라미터에 맞는 입력 항목을 표시합니다.
5. 작성 결과는 발행 전 전표로 저장할 수 있습니다.
6. 작성자가 값을 확정하면 전표를 발행합니다.
7. 발행된 전표는 읽기 전용으로 조회하거나 PDF로 출력합니다.

## 4. 배포와 실행 환경

| ID | 요구사항 | 검증 기준 | 근거 |
| --- | --- | --- | --- |
| `DIST-01` | 프로젝트는 역할별로 분리된 모노레포 패키지 구조를 사용해야 한다. | `core`, `elements`, `react`, `vue`, `mcp` 패키지가 각각 독립된 공개 진입점을 제공한다. | ADR-002, ADR-003 |
| `DIST-02` | 핵심 데이터 처리 기능은 `@omdc-slipkit/core`에서 제공해야 한다. | 파일 검증, 마이그레이션, 수식, 전표 조립, PDF 생성과 암호화 기능을 UI 없이 사용할 수 있다. | ADR-002, ADR-003 |
| `DIST-03` | `core`는 DOM에 의존하지 않아야 한다. | 브라우저 UI를 생성하지 않고도 Node.js 환경에서 `core`의 주요 기능을 실행할 수 있다. | ADR-002 |
| `DIST-04` | UI는 Web Component로 제공해야 한다. | 지원하는 프레임워크와 관계없이 커스텀 엘리먼트를 직접 사용할 수 있다. | ADR-003 |
| `DIST-05` | React와 Vue에는 프레임워크 관례에 맞는 래퍼를 제공해야 한다. | React와 Vue에서 속성과 이벤트를 각 프레임워크 방식으로 사용할 수 있다. | ADR-003 |
| `DIST-06` | React 래퍼는 React 19 이상을 지원해야 한다. | 패키지의 React 피어 의존성이 `react >=19`로 선언된다. | ADR-003 |
| `DIST-07` | Vue 래퍼는 Vue 3.4 이상을 지원해야 한다. | 패키지의 Vue 피어 의존성이 `vue >=3.4`로 선언된다. | ADR-003 |
| `DIST-08` | PDF 엔진은 `core` 내부 구현으로 감춰야 한다. | 공개 API와 `.slip` 파일이 pdfme의 템플릿 구조를 외부 계약으로 노출하지 않는다. | ADR-016 |
| `DIST-09` | `core`와 동봉 폰트 하위 경로는 CommonJS 프로젝트에서도 패키지 이름으로 불러올 수 있어야 한다. | `exports`의 `require` 조건이 ESM 산출물을 가리키고, 지원 Node에서 `require('@omdc-slipkit/core')`와 폰트 하위 경로 `require`가 동작한다. 이중 빌드는 하지 않는다. | ADR-057 |
| `DIST-10` | 패키지는 Node.js 지원 하한을 선언해야 한다. | `core`, `elements`와 `mcp`의 `engines.node`가 `>=22.13`으로 선언된다. | ADR-057 |
| `DIST-11` | 배포할 패키지는 실제 tarball을 사용하는 깨끗한 소비자 환경에서 설치하고 실행할 수 있어야 한다. | npm과 pnpm 소비자 프로젝트에서 공개 진입점, 타입, Node.js·브라우저 PDF, 프레임워크 래퍼와 MCP CLI를 검증하고 내부 `dist` 경로 접근은 거부된다. | ADR-074 |
| `DIST-12` | PR과 `main` 변경은 지원 Node.js 환경과 배포 소비자 경로에서 자동 검증해야 한다. | Node.js 22.13과 최신 LTS에서 `pnpm verify`·`pnpm verify:packages`가 실행되고, JSON Schema 재생성 차이와 Windows MCP 경로 시험이 별도 작업으로 검증된다. | ADR-075 |
| `DIST-13` | npm 배포는 장기 쓰기 토큰 없이 승인된 GitHub Actions 워크플로에서만 실행해야 한다. | GitHub-hosted runner의 OIDC, `npm-publish` Environment와 저장소 변수가 모두 준비된 `main` 수동 실행만 실제 배포할 수 있고, 그렇지 않으면 dry-run 검증으로 끝난다. | ADR-075 |
| `DIST-14` | 여러 패키지의 배포 순서와 부분 실패 후 재개 경계를 보장해야 한다. | 검증한 같은 tarball을 `core` → `elements` → `react` → `vue` → `mcp` 순서로 배포하며, 이미 존재하는 버전은 레지스트리 SRI가 같을 때만 건너뛰고 불일치나 조회 오류가 나면 즉시 중단한다. | ADR-075 |

## 5. 양식 디자이너

`<slip-designer>`는 일반 사용자가 `.slip` 양식을 시각적으로 만들고 수정하기 위한 구성 요소입니다.

### 5.1 기본 편집

| ID | 요구사항 | 검증 기준 | 근거 |
| --- | --- | --- | --- |
| `DES-01` | 디자이너는 양식 파일을 입력받아 편집할 수 있어야 한다. | `kind: "template"`인 `.slip` JSON을 `src`로 전달하면 해당 양식이 편집 화면에 표시된다. | ADR-003, ADR-020 |
| `DES-02` | 새 양식을 화면에서 생성할 수 있어야 한다. | 프리셋이나 기본 빈 양식으로 편집을 시작할 수 있다. | ADR-005, ADR-020 |
| `DES-03` | 요소를 추가, 선택, 이동, 크기 조절, 복사, 붙여넣기와 삭제할 수 있어야 한다. | 각 편집 작업이 캔버스에 반영되고 변경된 양식으로 출력된다. | ADR-020, ADR-031 |
| `DES-04` | 편집 작업을 되돌리거나 다시 실행할 수 있어야 한다. | 복수 단계의 undo와 redo가 동작한다. | ADR-020 |
| `DES-05` | 요소 배치를 돕는 격자, 눈금자, 스냅과 정렬 가이드를 제공해야 한다. | 요소 이동과 크기 조절 중 위치 및 정렬 보조 정보를 확인할 수 있다. | ADR-020, ADR-031 |
| `DES-06` | 양식 변경 결과를 호스트에 전달해야 한다. | 편집할 때마다 최신 양식이 `slip-change` 이벤트의 `detail.file`로 전달된다. | ADR-003, ADR-020 |
| `DES-52` | 요소와 그리드 셀에서 폰트를 고를 수 있어야 한다. | 텍스트 요소, 필드 요소, 그리드 공통 스타일과 그리드 셀에서 `SlipKit.getFonts`가 제공한 폰트를 고를 수 있고, 고른 값이 `.slip`에 저장된다. 셀에 지정이 없으면 그리드 공통 폰트를 상속하고, 기본값으로 되돌리면 셀의 `fontName`을 지운다. | ADR-069 |
| `DES-53` | 폰트 선택 항목은 고를 폰트 수와 무관하게 표시해야 한다. | 등록된 폰트가 하나뿐이어도 항목을 숨기거나 비활성으로 두지 않고, 지정을 해제했을 때 적용되는 폰트 이름을 함께 보여 준다. | ADR-069 |
| `DES-54` | 캔버스와 인라인 셀 편집은 고른 폰트로 그려야 한다. | 브라우저에 등록한 폰트로 캔버스와 셀 인라인 편집 입력을 그린다. 지정한 폰트의 등록이 끝나기 전이거나 실패하면 준비된 대체 폰트로 그리고, 속성 패널에는 실제로 그리는 데 쓰는 폰트 이름을 표시한다. | ADR-069 |
| `DES-55` | 등록되지 않은 폰트 이름은 지우지 않고 대체 상태를 알려야 한다. | 저장된 `fontName`을 그대로 두고 등록되지 않았음과 실제로 표시 중인 대체 폰트 이름을 속성 패널에 표시한다. 등록된 변형 이름은 미등록으로 표시하지 않는다. | ADR-069 |
| `DES-56` | 굵게·기울임은 등록된 변형 폰트로만 표현해야 한다. | 변형이 있으면 그 폰트로 그리고, 없으면 저장값과 토글 상태를 유지한 채 기본 형태로 그리며 그 사실을 속성 패널에 표시한다. 브라우저의 합성 굵게·기울임은 쓰지 않는다. | ADR-069 |

## 6. 전표 작성 폼

`<slip-form>`은 양식 또는 기존 전표에서 입력 화면을 생성하고 작성 결과를 전표로 전달합니다.

| ID | 요구사항 | 검증 기준 | 근거 |
| --- | --- | --- | --- |
| `FORM-01` | 양식 또는 작성 중 전표를 입력받을 수 있어야 한다. | `kind: "template"` 또는 `kind: "voucher"`인 JSON을 `src`로 전달할 수 있다. | ADR-031, ADR-052 |
| `FORM-02` | 양식의 파라미터 정의에 맞는 입력 항목을 생성해야 한다. | 텍스트, 숫자, 날짜, 논리, 이미지와 목록 값에 맞는 입력 UI가 표시된다. | ADR-031, ADR-047 |
| `FORM-03` | 목록 파라미터의 항목을 추가, 수정과 삭제할 수 있어야 한다. | 정의된 하위 필드에 따라 반복 행을 편집할 수 있다. | ADR-031, ADR-047 |
| `FORM-04` | 값이 변경되면 수식을 다시 계산해야 한다. | 입력 변경 직후 계산 필드와 미리보기 결과가 갱신된다. | ADR-010, ADR-031 |
| `FORM-05` | 작성 중인 전표를 호스트에 전달해야 한다. | 값이 변경될 때 `issued: false`인 전표가 `slip-change` 이벤트로 전달된다. | ADR-031, ADR-052 |
| `FORM-06` | 전표에는 작성 당시의 양식 전체를 스냅샷으로 포함해야 한다. | 작성 결과에 `templateSnapshot`이 포함되고 원본 양식 없이도 렌더링할 수 있다. | ADR-008, ADR-052 |
| `FORM-07` | 숫자 파라미터의 빈 값은 전표를 조립할 때 `0`으로 정규화해야 한다. | 숫자 파라미터에 빈 값을 전달해도 전표의 해당 값이 `0`이 된다. | ADR-044, ADR-052 |
| `FORM-08` | 전표 발행 전에 파일 규칙을 검증해야 한다. | 검증에 실패한 전표는 발행되지 않고 폼도 잠기지 않는다. | ADR-009, ADR-036 |
| `FORM-09` | 발행에 성공하면 `issued: true`인 전표를 호스트에 전달해야 한다. | 발행 결과가 `slip-issue` 이벤트의 `detail.file`로 전달된다. | ADR-009, ADR-053 |
| `FORM-10` | 발행된 전표는 작성 폼에서 수정할 수 없어야 한다. | `issued: true`인 전표를 불러오면 모든 입력과 발행 작업이 잠긴다. | ADR-009, ADR-053 |
| `FORM-11` | 전표 입력 결과를 PDF로 미리 볼 수 있어야 한다. | 현재 입력값과 수식 결과가 적용된 PDF가 폼에 표시된다. | ADR-012, ADR-031 |
| `FORM-12` | 이미지 입력은 파일을 선택하여 base64 데이터로 저장해야 한다. | 사용자가 URL을 직접 입력하는 기능 없이 선택한 이미지가 `data:` 형식으로 전표에 포함된다. | ADR-036 |
| `FORM-13` | 호스트가 이미지 파일의 최대 크기를 제한할 수 있어야 한다. | `maxImageBytes`를 지정하면 제한을 넘는 이미지가 거부된다. 기본값은 2MB다. | ADR-036 |
| `FORM-14` | 전표 값이 변경되면 조건부 서식을 다시 평가해야 한다. | 조건식에 사용된 값이 바뀌면 작성 화면과 PDF 미리보기의 서식이 함께 갱신된다. | ADR-062 |

> [!IMPORTANT]
> `issued: true`는 전표의 값이 확정되어 SlipKit 작성 폼에서 수정할 수 없다는 의미입니다.
> 전자서명이나 위변조 방지를 의미하지 않습니다.

## 9. 수식

| ID | 요구사항 | 검증 기준 | 근거 |

| `CALC-06` | 문자열이 필요한 위치에서는 숫자와 논리를 문자열로 변환할 수 있어야 한다. | 문자열 함수에서 숫자와 논리 값을 정의된 문자열로 처리한다. | ADR-044 |
| `CALC-07` | 명시적인 타입 변환 함수를 제공해야 한다. | `TO_NUMBER`, `TO_STRING`, `TO_DATE`를 사용할 수 있다. | ADR-044 |
| `CALC-08` | 확정된 32개 수식 함수를 제공해야 한다. | 공개 함수 목록과 `FORMULA_FUNCTIONS`가 다음 함수 집합과 일치한다. | ADR-017, ADR-044 |
| `CALC-09` | 조건부 서식의 조건식은 기존 수식 엔진으로 평가해야 한다. | 임의 코드를 실행하지 않고 파라미터, 목록의 현재 항목과 허용된 함수만 사용해 논리값을 계산한다. | ADR-010, ADR-062 |
| `CALC-10` | 함수별 허용 인자 수를 값 없이도 확인할 수 있어야 한다. | `FORMULA_ARITY`가 함수마다 최소·최대 인자 수를 정의하고, `assertFormulaArity`로 값 없이 수식의 인자 수를 검사할 수 있다. 평가기도 같은 표를 사용한다. | ADR-010, ADR-068 |
| `CALC-11` | 평가에 실패한 까닭을 안내에 쓸 수 있게 구분해 알려야 한다. | `FormulaEvalError`가 `reason`(`data`·`value`·`formula`)과 `dataDependent`를 제공한다. `dataDependent`는 안내 문구를 고르기 위한 진단 정보이며 어떤 입력에서도 계산 가능한지를 증명하지 않는다. 판정을 바꾸는 수단은 공개 표면에 두지 않는다. | ADR-068 |
| `CALC-12` | 값이 없어 멈춘 자리 뒤에 남은 오류까지 찾을 수 있어야 한다. | `diagnoseFormula`가 값이 없어 실패한 자리를 빈 값으로 이어 끝까지 계산하고, 현재 계산에서 발견한 오류를 `formulaError`와 `dataError`로 나눠 돌려준다. `evaluateFormula`는 그대로 첫 오류에서 멈춘다. | ADR-068 |

지원 함수는 다음과 같습니다.

| 분류 | 함수 |
| --- | --- |
| 집계 | `SUM`, `AVG`, `COUNT`, `MIN`, `MAX` |
| 조건부 집계 | `SUMIF`, `COUNTIF` |
| 산술 | `ROUND`, `FLOOR`, `CEIL`, `ABS` |
| 문자열 | `CONCAT`, `LEFT`, `RIGHT`, `MID`, `REPLACE`, `TRIM`, `UPPER`, `LOWER` |
| 조건 | `IF`, `AND`, `OR` |
| 표시 형식 | `FORMAT_NUMBER`, `FORMAT_DATE`, `NUMBER_TO_KOREAN` |
| 날짜 | `TODAY`, `DATE_ADD`, `DATE_DIFF` |
| 세무 | `VAT` |
| 타입 변환 | `TO_NUMBER`, `TO_STRING`, `TO_DATE` |

산술 연산자 `+`, `-`, `*`, `/`와 비교 연산자는 함수 수에 포함하지 않지만 수식 문법에서 지원해야 합니다.

`VLOOKUP`과 같은 조회 함수는 현재 요구사항에 포함하지 않습니다.

| `OUT-16` | 동봉 기본 폰트는 PDF와 같은 로케일 기준으로 골라야 한다. | 디자이너 캔버스와 PDF가 모두 `slipkit.locale`을 먼저 보는 렌더 로케일로 대체 폰트를 고른다. | ADR-069 |

| `SEC-13` | 암호화 키나 설정 구조를 변경해도 이전에 저장한 파일을 읽을 수 있어야 한다. | 현재 키로 실패하면 `previousKeys`를 순서대로 시도하며, 공통 설정 도입 전에 데모나 저장소가 사용한 키도 필요한 기간 동안 이전 키로 등록할 수 있다. | ADR-055, ADR-056, ADR-064 |
| `SEC-14` | 저장 시 암호화 여부는 저장 수단별 정책으로 선택할 수 있어야 한다. | `encryptOnSave: true`면 공통 키로 암호화해 저장하고, `false`면 평문으로 저장한다. | ADR-055, ADR-064 |
| `SEC-15` | 저장 정책과 무관하게 암호화 파일과 평문 파일을 모두 불러올 수 있어야 한다. | `encryptOnSave: false`인 저장 수단에서도 암호화 봉투를 감지해 공통 키로 복호화하고, 평문 파일은 그대로 읽는다. | ADR-055, ADR-064 |
| `SEC-16` | 암호화 키가 없으면 묵시적으로 대체 키를 쓰지 않아야 한다. | 키 없이 암호화 저장이나 복호화를 시도하면 오류가 발생하며, 데모의 샘플 키는 데모 코드에서 명시적으로 전달한다. | ADR-064 |
| `SEC-17` | 암호화 키 관리는 호스트 책임이어야 한다. | SlipKit이 운영 키를 생성하거나 외부에 보관하는 서비스를 제공하지 않는다. | ADR-004, ADR-054 |

> [!WARNING]
> 암호화는 파일 내용을 읽기 어렵게 하고 복호화 과정에서 변경을 감지할 수 있게 합니다.
> 사용자 인증, 접근 권한, 감사 기록, 전자서명이나 키 관리 체계를 대신하지 않습니다.

### 14.4 수식과 외부 리소스

| ID | 요구사항 | 검증 기준 | 근거 |

| `SEC-20` | 외부에서 전달된 `.slip` 파일은 사용 전에 검증할 수 있어야 한다. | 손상된 JSON, 지원하지 않는 버전과 의미 규칙 위반 파일이 거부된다. | ADR-007, ADR-022 |

## 15. AI 연동 MCP 서버

`@omdc-slipkit/mcp`는 AI가 MCP 도구로 `.slip` 파일을 다룰 수 있게 하는 로컬 stdio 서버입니다.

| ID | 요구사항 | 검증 기준 | 근거 |
| --- | --- | --- | --- |
| `MCP-01` | MCP 서버는 별도 패키지의 로컬 stdio 서버로 제공해야 한다. | `@omdc-slipkit/mcp`의 `slipkit-mcp` 실행 파일로 서버를 시작할 수 있다. | ADR-061 |
| `MCP-02` | 파일 접근은 서버 설정으로 정한 작업 디렉터리 안으로 제한해야 한다. | 작업 디렉터리를 벗어나는 경로는 오류로 거부된다. | ADR-061 |
| `MCP-03` | 저장 요청은 검증을 통과한 파일만 기록해야 한다. | 검증에 실패하면 아무것도 저장하지 않고 오류 목록을 반환한다. | ADR-061 |
| `MCP-04` | 기존 파일의 수정은 대상을 식별자로 지목하는 부분 수정이어야 한다. | 요소 id, 파라미터 key와 페이지 번호로 지목한 연산 묶음이 원자적으로 적용된다. | ADR-061 |
| `MCP-05` | 도구 응답에 base64 데이터를 포함하지 않아야 한다. | 읽기 응답에서 base64 데이터가 크기 표시로 치환되고, 이미지는 파일 경로로 전달한다. | ADR-061 |
| `MCP-06` | 발행 기능을 제공하지 않아야 한다. | 발행 도구가 없고 발행된 전표의 수정 요청이 거부된다. | ADR-061 |
| `MCP-07` | 파일 시스템 저장소 어댑터를 공개해야 한다. | 호스트가 `FileSystemStorage`로 같은 디렉터리를 같은 규칙(암호화 포함)으로 읽고 쓸 수 있다. | ADR-021, ADR-061 |
| `MCP-08` | MCP 서버는 저장소 경로, 로케일, 폰트와 암호화 키 환경변수 이름을 자체 설정 파일로 관리해야 한다. | `slipkit-mcp.json`을 읽고 항목별 CLI 인자와 환경변수 우선순위를 적용한다. 암호화 키 값은 설정 파일에 저장하지 않는다. | ADR-061 |
| `MCP-09` | MCP 서버는 커스텀 PDF 폰트를 등록할 수 있어야 한다. | 설정 파일의 TTF·OTF 경로를 읽어 렌더링하고, 설정하지 않으면 로케일에 맞는 동봉 폰트를 사용한다. | ADR-061 |
| `MCP-10` | MCP CLI는 서버를 시작하지 않고 사용법과 패키지 버전을 확인할 수 있어야 한다. | `--help`와 `--version`이 설정이나 서버를 시작하지 않고 stdout에 결과를 출력하며 종료 코드 0을 반환한다. | ADR-073 |
| `MCP-11` | MCP CLI는 사용법 오류와 실행 오류를 구분해야 한다. | 잘못된 인자는 stderr와 종료 코드 2, 설정 및 서버 시작 오류는 stderr와 종료 코드 1을 사용한다. | ADR-073 |

## 17. 현재 범위에서 제외하는 기능

다음 기능은 SlipKit이 직접 제공하는 범위에 포함하지 않습니다.

| 제외 항목 | 설명 | 근거 |
| --- | --- | --- |
| 자체 사용자 및 조직 관리 | 사용자 계정, 조직, 역할과 권한은 호스트가 관리합니다. | ADR-004 |
| 자체 REST API 서버 | 서버가 필요하면 호스트가 자신의 API를 구성합니다. | ADR-006 |
| SlipKit 호스팅 SaaS | 전표 데이터를 SlipKit이 운영하는 외부 서비스로 전송하지 않습니다. | ADR-012 |
| 호스트 업무 흐름 | 승인, 결재, 취소, 재발행과 화면 이동은 호스트가 구현합니다. | ADR-004 |
| 자동 영구 저장 | 변경 이벤트가 발생했다는 이유만으로 데이터를 자동 저장하지 않습니다. | ADR-003, ADR-021 |
| 전자서명과 파일 진위 증명 | `issued`와 AES 암호화를 전자서명으로 취급하지 않습니다. | ADR-053, ADR-054 |
| 임의 스크립트 실행 | JavaScript를 직접 실행하는 사용자 수식을 제공하지 않습니다. | ADR-010 |
| 외부 URL 이미지 가져오기 | Core가 URL에 접속하여 이미지를 다운로드하거나 변환하지 않습니다. | ADR-002, ADR-036 |
| PDF 엔진 형식 공개 | pdfme의 템플릿 구조를 SlipKit 공개 파일 형식으로 사용하지 않습니다. | ADR-016 |
| ZIP 기반 `.slip` 컨테이너 | 확장 경로만 확보하며 현재 규범 파일 형식에는 포함하지 않습니다. | ADR-007 |
| 페이지별 소계 | 현재 확정 요구사항에 포함하지 않으며 필요성이 확인될 때 별도로 결정합니다. | ADR-041 |
| 추가 동봉 프리셋 | 호스트 프리셋 주입으로 대체하며 현재 기본 프리셋 확충은 요구하지 않습니다. | ADR-040, ADR-041 |
| 조회형 수식 함수 | `VLOOKUP` 계열 함수는 현재 수식 집합에 포함하지 않습니다. | ADR-039 |
