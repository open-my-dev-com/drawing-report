## 4. 외부 연계

확정된 연계 방식 3가지 (ADR-006):

1. **호스트 데이터 주입**: 호스트 앱이 자기 데이터(거래처, 품목 등)를 넘기면 양식에 바인딩되어 렌더
2. **저장소 어댑터**: 저장/불러오기를 인터페이스로 추상화. 로컬 파일, S3, DB, 자체 서버 등 어디든 붙일 수 있게
3. **표준 교환 파일 포맷**: 전표 파일 자체가 명세화된 포맷이라 다른 시스템이 파일을 읽고 쓸 수 있게

> REST API 서버 제공은 범위에서 **제외** (호스트가 필요 시 직접 구성).

### 저장소 어댑터 상세 (ADR-021)

| 항목 | 내용 |
|---|---|
| 필수 인터페이스 | `save` / `load` / `delete` / `list`(페이징·필터 지원) |
| 버전 이력 | 별도의 **선택 인터페이스** — 구현한 어댑터에서만 이력 UI 노출 |
| 기본 동봉 | ① 로컬 파일 다운로드/업로드 ② IndexedDB |
| 구현 위치 | 인터페이스·타입·오류는 core, 브라우저 구현 2종은 elements (ADR-025). 로컬 파일 어댑터는 delete/list 미지원(`unsupported` 오류) |
| 폰트 저장 | 사용자 업로드 폰트(ADR-012)도 동일 어댑터 계층 경유 |

### 교환 포맷 스펙 공개 (ADR-022)

`.slip` 포맷 명세서(SPEC.md)를 공개 문서로 유지하고, Zod 스키마에서 산출한 **JSON Schema를 패키지에 동봉**한다 — 타 시스템이 언어 무관하게 기계 검증 가능.

## 5. 파일 포맷

| 항목 | 내용 | 근거 |
|---|---|---|
| 포맷 | **JSON 기반 자체 스키마**, 확장자 **`.slip`** (양식·전표 파일 공용 — 내부 `kind` 필드로 구분) | ADR-007, ADR-018 |
| 스키마 버전 | 모든 파일에 `schemaVersion` 내장. 구버전 파일을 열 때 자동 마이그레이션하는 계층을 core에 처음부터 둔다 | ADR-007 |
| 이미지 참조 | `src` 필드로 통일하며 3종 지원: 외부 URL / `data:`(base64 내장) / `asset://`(내부 리소스 참조) | ADR-007 |
| 이미지 정책 | **base64로만 담는다** (2026-08-21 개정): 디자이너는 파일에서 골라 base64로 넣는 것만 지원하고 주소(URL) 입력을 두지 않는다. 전표 데이터로 받는 이미지도 base64만 받는다. 주소로 받아야 하면 **호스트 서버가 중계해 base64로 바꿔 넘긴다** — core는 네트워크를 쓰지 않아 URL을 렌더할 수 없다. 이미지 크기 상한은 `maxImageBytes`(기본 2MB)로 호스트가 조인다. ~~하이브리드(작성 중 URL 허용, 발행 시 내장)~~ | ADR-036 (ADR-014 대체) |
| 컨테이너 확장 | v1은 순수 JSON 단일 파일. 대용량 리소스 필요 시 동일 JSON을 manifest로 하는 ZIP 컨테이너를 **추후** 추가할 수 있는 구조로 스키마를 설계(`asset://` 참조가 이를 위한 장치) | ADR-007 |
| 템플릿-데이터 분리 | 양식(템플릿)과 전표 데이터(기입값)는 별도 구조. 양식 하나로 전표 N장을 생성 | ADR-001 |
| 양식 버저닝 | 전표 파일은 **생성 시점의 양식 전체를 스냅샷으로 내장**한다. 발행된 전표는 이후 양식이 수정되어도 절대 모양이 바뀌지 않으며, 파일 단독으로 열람 가능(자기완결) | ADR-008 |

## 6. 보안

| 항목 | 내용 | 근거 |
|---|---|---|
| 위변조 방지 서명 | 전표 내용의 해시/서명을 파일에 내장하여 "발행 후 수정되지 않았음"을 검증 가능하게 한다. **기본 제공** | ADR-009 |
| 서명 상세 | **SHA-256 내용 해시 필수 내장**(키 없이 훼손 탐지) + 호스트 키 제공 시 **JWS(ES256) 공개키 서명**으로 발행자 증명(옵션). 대상은 양식 스냅샷 포함 전체. JSON 정규화 규칙을 스펙에 명시 | ADR-019 |
| 암호화 | 파일 내용 암호화를 **옵션**으로 제공(필수 아님). 키 관리는 호스트 책임. 암호화된 파일은 표준 교환성이 제한됨을 명시 | ADR-009 |
| 수식 안전성 | 수식은 자체 파서로 해석. 임의 코드 실행(`eval`, `Function` 등) 절대 금지 | ADR-010 |

## 8. 레이아웃 · 페이지 · 출력

| 항목 | 내용 | 근거 |
|---|---|---|
| 레이아웃 기준 | **용지(A4 등) 기준** 절대 좌표계. 화면·인쇄·PDF가 동일 레이아웃 | ADR-011 |
| 복수 페이지 | 페이지는 스키마의 1급 개념(`pages` 배열) | ADR-011 |
| 자동 페이지 분할 | **필수 기능.** 표(품목 리스트)가 페이지를 넘치면 자동으로 다음 페이지로 분할. 헤더 반복, 페이지별 소계 등의 옵션 포함. **분할 계산은 변환 계층이 직접 한다** (2026-08-22 개정 — 하부 엔진의 분할은 스키마 타입 이름으로만 켜지고 확장할 수 없다) | ADR-011, ADR-037 |
| 렌더링 구조 | `양식+데이터 → 변환 계층(core: 우리 포맷 → pdfme 템플릿, 기본값 병합 필수) → pdfme 엔진 → PDF`. 화면 미리보기도 동일 변환 결과를 사용 — 화면과 PDF의 불일치가 구조적으로 불가능하게 | ADR-012, ADR-016 |
| PDF 생성 | **브라우저에서 클라이언트 직접 생성**(pdfme 엔진, 내부적으로 pdfme 유지보수 pdf-lib 포크). 서버 왕복 없음, 전표 데이터가 브라우저 밖으로 나가지 않음. DOM 캡처(스크린샷) 방식 금지 — 벡터 텍스트 유지 | ADR-012, ADR-016 |
| 서버 렌더러 | 추후 확장: 동일 core+PDF 렌더러를 Node 패키지로 재포장하여 **호스트 인프라에서** 일괄 발행 자동화에 사용. 제3자 외부 서버는 어떤 경우에도 개입하지 않음 | ADR-012 |
| 인쇄 | 생성된 PDF를 인쇄하는 방식 — 종이 출력까지 화면과 일치 | ADR-012 |
| 폰트 | PDF에 폰트 내장(한글 폰트는 사용 글자만 서브세팅). 기본 한글 폰트 1종 동봉 + **사용자가 자기 폰트를 업로드/등록해서 쓸 수 있어야 함** | ADR-012 |

비개발자가 드래그앤드롭으로 양식을 설계하는 에디터 (ADR-005). v1 범위 확정 (ADR-020):

| 항목 | 내용 |
|---|---|
| 요소 6종 | 텍스트 · **고정 그리드 표**(행 고정 틀) · **동적 행 표**(자동 페이지 분할 대상) · 이미지 · 선/사각형 · 입력 필드 — 이후 도형이 독립 타입 4종(선·사각형·타원·정다각형)으로 갈라지고(0.2.0, ADR-032) 고정 그리드·동적 표가 그리드 `grid` 하나로 합쳐져 **현재는 8종** (0.4.0, ADR-037) |
| 셀 병합 | **그리드에서 지원**(변환 계층이 선·텍스트로 분해 렌더). 반복 구간 안에서도 되며 구간 경계를 넘는 병합만 막는다 (ADR-037) |
| 색 스타일 | 전 요소에 배경색·글자색·테두리색(두께·스타일) 지정 가능 |
| 편집 편의 | 열 너비 조절, 스냅·정렬 가이드, undo/redo, 복사/붙여넣기 |
| 다중 페이지 | 페이지 전환·추가·삭제 UI (ADR-026 — v1 포함 확정) |
| 기타 | 용지 설정, 수식 입력, 실시간 미리보기, 기본 프리셋 2종(거래명세서·청구서) |
| 이후 배정 | 레이어 패널·그룹화·동적 행 표 셀 병합·표 중첩·프리셋 확충 전부 v2로 (§10-2, ADR-031). v3는 MCP + AI만 |

## 11. 개발 규칙

- 브랜치·커밋 규칙은 [`.claude/rules/branching.md`](../.claude/rules/branching.md)를 따른다 (ADR-023). `main` 직접 커밋 금지, 작업은 `<type>/<scope>-<topic>` 브랜치에서 PR로.
- `main`은 **스쿼시 머지** 전용. 미병합 브랜치 위 PR 스택 금지, 브랜치당 커밋 최소화 (ADR-024).
- 개발 규칙은 리포 루트 **`CLAUDE.md`**로 모든 Claude Code 세션에 자동 적용되며, `.claude/settings.json`이 main 직접 푸시를 기계적으로 차단한다 (ADR-024).
