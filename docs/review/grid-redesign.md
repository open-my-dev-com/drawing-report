# 그리드 재설계안

**상태:** 개발 설계안

**범위:** `.slip` 그리드 모델, 페이지 배치, PDF 변환과 디자이너 편집

**작성일:** 2026-08-29

## 1. 목적

현재 반복 그리드는 `perPage`에 지정한 항목 수만큼 고정된 공간을 만들고, 이를 기준으로 출력 페이지를 나눕니다. 이 구조를 다음 요구를 함께 표현할 수 있는 단일 그리드 모델로 교체합니다.

- 데이터가 적을 때 최소 항목 영역을 빈 상태로 유지하는 양식
- 데이터가 많으면 페이지의 남은 공간까지 자동으로 확장하는 양식
- 페이지마다 정해진 항목 수를 유지하는 양식
- 헤더 없이 데이터만 반복하는 양식
- 첫 페이지 또는 모든 페이지에 헤더를 표시하는 양식
- 그룹별 소계, 페이지별 소계와 전체 합계를 선택적으로 표시하는 양식
- 데이터 한 건을 여러 행으로 표시하는 양식

고정 그리드와 반복 그리드는 별도 요소로 나누지 않습니다. 하나의 `grid` 요소 안에서 필요한 행 구간만 구성합니다.

## 2. 현재 구현의 문제

### 2.1 `perPage`와 요소 높이의 결합

현재 그리드의 `height`는 다음 식으로 검증됩니다.

```text
기본 행 높이 합 + (perPage - 1) × 반복 구간 높이 합
```

따라서 그리드의 편집 크기, 데이터 반복 수와 페이지 분할 수가 하나의 설정에 결합되어 있습니다. 실제 페이지에 공간이 남아 있어도 `perPage`를 넘은 데이터는 다음 페이지로 이동합니다.

### 2.2 출력 페이지마다 일반 요소를 일괄 복제

반복 데이터가 추가 페이지를 만들면 같은 양식 페이지의 일반 요소를 모두 같은 위치에 복제합니다. 첫 페이지 전용 제목, 마지막 페이지 전용 합계, 모든 페이지의 바닥글과 그리드 뒤에서 이동해야 하는 요소를 구분할 수 없습니다.

### 2.3 반복 구간 위·아래 행의 역할 고정

현재는 반복 구간 위쪽을 헤더, 아래쪽을 꼬리 영역으로 간주합니다. 헤더와 합계의 존재 여부, 표시 페이지와 계산 범위를 각각 지정할 수 없습니다.

### 2.4 셀 이름과 편집 대상의 불일치

그리드 셀에는 편집 가능한 이름이 없습니다. 디자이너의 왼쪽 목록은 열 헤더 또는 좌표로 임시 이름을 만들지만 사용자가 수정할 수 없습니다. 셀 선택 중에도 일부 그리드 전체 설정이 노출되어 편집 대상이 분명하지 않습니다.

## 3. 설계 원칙

1. 그리드는 하나의 행·열 좌표계와 하나의 테두리 체계를 유지합니다.
2. 데이터 한 건의 반복 단위는 행 하나가 아니라 연속된 하나 이상의 행으로 구성된 항목 구간입니다.
3. 헤더, 소계와 합계는 필수가 아니며 필요한 행 구간만 정의합니다.
4. 페이지 배치 규칙을 요소 위치로 추측하지 않고 파일에 명시합니다.
5. 최소 표시 항목 수와 페이지당 항목 수를 같은 설정으로 취급하지 않습니다.
6. 페이지 계획과 PDF 도형 생성을 분리합니다.
7. 디자이너, PDF 미리보기와 최종 PDF는 같은 페이지 계획 결과를 사용합니다.
8. 기존 `perPage`의 의미를 새 설정으로 조용히 변경하지 않습니다.

## 4. 용어

| 용어 | 의미 |
| --- | --- |
| 템플릿 행 | 파일의 `rows`에 한 번만 정의된 원본 행 |
| 행 구간 | 같은 출력 시점을 갖는 연속된 템플릿 행 범위 |
| 항목 구간 | 데이터 한 건마다 반복하는 행 구간 |
| 항목 인스턴스 | 실제 데이터 한 건 또는 빈 항목을 적용해 출력하는 항목 구간 사본 |
| 실제 항목 | 목록 파라미터에 포함된 데이터 객체 |
| 빈 항목 | 최소 표시 수 또는 고정 페이지 크기를 채우기 위한 값 없는 항목 인스턴스 |
| 출력 페이지 | 하나의 양식 페이지에서 페이지 분할 결과로 생성된 PDF 페이지 |
| 흐름 영역 | 자동 배치 요소가 사용할 수 있는 페이지의 세로 범위 |

문서와 UI에서는 물리 행 수와 데이터 항목 수를 구분합니다. 데이터 한 건이 여러 행으로 구성될 수 있으므로 `페이지당 행 수`라는 표현은 사용하지 않습니다.

## 5. 제안 파일 모델

다음 JSON은 필드의 역할을 설명하기 위한 제안입니다. 구현 시 같은 의미를 유지해야 하며 단순히 기존 `repeat`에 예외 필드를 계속 추가하는 방식으로 대체하지 않습니다.

### 5.1 페이지 흐름 영역

페이지에 자동으로 확장되는 요소가 있으면 페이지의 흐름 영역을 사용합니다.

```json
{
  "flowArea": {
    "top": 20,
    "bottom": 277
  },
  "elements": []
}
```

- `top`과 `bottom`은 용지 위쪽을 기준으로 한 절대 Y 좌표(mm)입니다.
- 생략하면 용지의 위·아래 여백 경계를 사용합니다.
- 첫 출력 페이지에서 그리드는 자신의 `position.y`에서 시작합니다.
- 이어지는 출력 페이지에서는 `flowArea.top`에서 시작합니다.
- 자동 확장 그리드는 `flowArea.bottom`을 넘지 않습니다.
- 페이지 공통 바닥글은 흐름 영역 밖에 배치할 수 있습니다.

### 5.2 그리드 크기

새 그리드에서는 저장된 `width`와 `height`를 출력 크기의 기준으로 사용하지 않습니다.

- 템플릿 너비는 `columns[].width`의 합입니다.
- 템플릿 높이는 `rows[].height`의 합입니다.
- 실제 출력 높이는 페이지 계획에서 행 구간과 항목 인스턴스를 배치한 결과입니다.
- 새 스키마의 `grid`에서는 중복된 `width`와 `height`를 제거합니다.
- 공통 요소 코드가 크기를 요구하면 `elementBounds()`와 같은 공통 계산 함수를 사용합니다.

기존처럼 `height`를 `perPage`에 맞춰 저장하고 다시 검증하는 구조는 유지하지 않습니다.

### 5.3 셀 이름

`GridCell`에 선택적인 `name`을 추가합니다.

```json
{
  "row": 2,
  "column": 0,
  "name": "품목명",
  "parameter": "name"
}
```

- `name`은 편집기에서 사용하는 이름이며 PDF에 출력하지 않습니다.
- `name`, `content`, `parameter`와 `formula`는 서로 다른 정보입니다.
- 이름이 없으면 디자이너는 `3행 1열`과 같은 좌표를 표시합니다.
- 열 헤더를 셀 이름으로 자동 사용하지 않습니다.
- 셀 이름은 식별 키가 아니므로 중복을 허용합니다.

### 5.4 행 구간

반복 그리드의 모든 템플릿 행은 하나의 행 구간에 속해야 합니다.

```json
{
  "id": "detail",
  "name": "품목 상세",
  "fromRow": 2,
  "toRow": 4,
  "placement": "item"
}
```

`page-start`와 `page-end`에는 선택적인 `pages`를 지정할 수 있습니다.

| 값 | 표시 페이지 |
| --- | --- |
| `all` | 모든 출력 페이지, 기본값 |
| `first` | 첫 출력 페이지 |
| `continuation` | 첫 페이지를 제외한 이어지는 페이지 |
| `non-final` | 마지막 페이지를 제외한 모든 페이지 |
| `last` | 마지막 출력 페이지 |

표시 대상이 아닌 페이지에서는 해당 행 구간의 공간도 만들지 않습니다. 예를 들어 중간 페이지에만 필요한 페이지 소계는 `page-end`와 `pages: "non-final"`로 표현할 수 있습니다.

`placement`는 다음 값을 사용합니다.

| 값 | 출력 시점 |
| --- | --- |
| `before-data` | 데이터 영역 앞에서 한 번 |
| `page-start` | 각 출력 페이지 시작 시 |
| `group-start` | 연속된 데이터 그룹이 시작될 때 |
| `item` | 실제 또는 빈 데이터 항목마다 |
| `group-end` | 연속된 데이터 그룹이 끝날 때 |
| `after-data` | 모든 데이터 항목 뒤에서 한 번 |
| `page-end` | 각 출력 페이지 끝에서 한 번 |

행 구간 규칙은 다음과 같습니다.

- 반복 그리드에는 `item` 구간이 정확히 하나 있어야 합니다.
- `item` 구간은 한 행 이상일 수 있습니다.
- 행 구간은 겹치거나 행을 빠뜨릴 수 없습니다.
- 행 구간은 `fromRow` 순서로 정렬되어야 합니다.
- 템플릿의 세로 순서는 `before-data`, `page-start`, `group-start`, `item`, `group-end`, `after-data`, `page-end` 순서를 따라야 합니다. 사용하지 않는 종류는 생략합니다.
- 셀 병합은 행 구간 경계를 넘을 수 없습니다.
- `group-start`와 `group-end`는 그룹 설정이 있을 때만 사용할 수 있습니다.
- 같은 `placement`의 행 구간을 여러 개 둘 수 있지만 인접한 구간은 디자이너에서 하나로 합치는 것을 기본으로 합니다.

헤더가 필요 없으면 `before-data`나 `page-start` 구간을 만들지 않습니다. 첫 페이지에만 표시하는 헤더는 `before-data`, 모든 페이지에 표시하는 헤더는 `page-start`를 사용합니다.

### 5.5 반복 데이터와 페이지 방식

```json
{
  "repeat": {
    "parameter": "items",
    "bands": [
      {
        "id": "column-header",
        "name": "열 제목",
        "fromRow": 0,
        "toRow": 0,
        "placement": "page-start"
      },
      {
        "id": "detail",
        "name": "품목 상세",
        "fromRow": 1,
        "toRow": 2,
        "placement": "item"
      },
      {
        "id": "grand-total",
        "name": "전체 합계",
        "fromRow": 3,
        "toRow": 3,
        "placement": "after-data"
      }
    ],
    "pagination": {
      "mode": "auto",
      "minItems": 8
    },
    "maxItems": 100
  }
}
```

`parameter`는 현재와 같이 객체 배열을 담는 목록 파라미터를 참조합니다.

`pagination`은 `mode`를 판별값으로 사용하는 배타적 유니온입니다. 자동 확장 설정에 `itemsPerPage`를 넣거나 고정 페이지 설정에 `minItems`를 넣은 파일은 검증에서 거부합니다.

#### 자동 확장 방식

```json
{
  "mode": "auto",
  "minItems": 8
}
```

- 전체 항목 인스턴스 수는 `max(실제 항목 수, minItems)`입니다.
- `minItems`는 0 이상의 정수이며 필수입니다.
- 실제 항목이 부족한 부분은 빈 항목 인스턴스로 출력합니다.
- 항목 인스턴스를 흐름 영역의 남은 공간까지 배치합니다.
- 다음 항목 구간 전체가 들어가지 않으면 다음 출력 페이지로 이동합니다.
- `minItems`는 문서 전체의 최소 항목 수이며 페이지마다 다시 적용하지 않습니다.
- 마지막 출력 페이지의 남은 공간을 자동으로 빈 항목으로 채우지 않습니다.

예를 들어 `minItems: 8`이면 데이터가 5건일 때 실제 항목 5개와 빈 항목 3개를 표시하고, 데이터가 10건이면 실제 항목 10개를 표시합니다.

#### 고정 페이지 방식

```json
{
  "mode": "fixed",
  "itemsPerPage": 8
}
```

- 실제 항목을 `itemsPerPage` 단위로 나눕니다.
- `itemsPerPage`는 1 이상의 정수이며 필수입니다.
- 각 출력 페이지는 정확히 `itemsPerPage`개의 항목 영역을 가집니다.
- 마지막 출력 페이지의 부족한 부분은 빈 항목 인스턴스로 출력합니다.
- 데이터가 없어도 빈 항목으로 구성된 출력 페이지 한 장을 만듭니다.
- 설정된 항목 수와 페이지 행 구간이 흐름 영역에 들어가지 않으면 렌더링하지 않고 명확한 오류를 반환합니다.
- 그룹 행 구간의 수에 따라 필요한 높이가 달라지더라도 `itemsPerPage`를 임의로 줄이지 않습니다. 해당 데이터가 흐름 영역에 들어가지 않으면 오류를 반환합니다.

현재 `perPage`가 필요한 고정 양식은 이 방식으로 표현합니다.

#### 최대 항목 수

`maxItems`는 실제 데이터에 먼저 적용합니다. 제한을 적용한 실제 항목만 페이지 계획과 집계에 사용합니다. `maxItems`는 `minItems` 또는 `itemsPerPage`보다 작을 수 있으며, 부족한 출력 영역은 각 페이지 방식의 빈 항목 규칙에 따릅니다.

### 5.6 그룹

`groupBy`는 항목 객체의 하위 필드 이름 배열입니다.

- 입력 순서는 변경하지 않습니다.
- `groupBy`는 한 개 이상의 서로 다른 하위 필드 이름을 가져야 합니다.
- 지정한 필드 값이 연속해서 같은 항목을 하나의 그룹으로 봅니다.
- 여러 필드를 지정하면 모든 값이 같을 때 같은 그룹입니다.
- 빈 항목은 그룹에 포함하지 않습니다.
- 그룹 시작 구간은 첫 항목과, 그룹 종료 구간은 마지막 항목과 같은 페이지에 배치합니다.
- 두 구간을 포함한 묶음이 빈 페이지의 흐름 영역보다 크면 렌더링 오류를 반환합니다.
- 그룹이 다음 페이지로 이어질 때 그룹 시작 구간을 다시 표시해야 한다면 해당 구간에 `repeatOnPageBreak: true`를 지정합니다.

### 5.7 수식 평가 범위

페이지·그룹 소계를 구현하기 위해 기존 전표 값과 충돌하지 않는 예약 참조를 수식 문법에 추가합니다.

| 참조 | 값 |
| --- | --- |
| `@item` | 현재 실제 항목 객체 |
| `@group` | 현재 그룹의 실제 항목 배열 |
| `@page` | 현재 출력 페이지에 배치한 실제 항목 배열 |
| `@all` | `maxItems` 적용 후의 전체 실제 항목 배열 |

예시는 다음과 같습니다.

```text
FORMAT_NUMBER(SUM(@group.amount))
FORMAT_NUMBER(SUM(@page.amount))
FORMAT_NUMBER(SUM(@all.amount))
```

- 예약 참조는 빈 항목을 포함하지 않습니다.
- `item` 구간의 기존 파라미터 해석은 현재처럼 현재 항목을 우선합니다.
- `group-start`에서는 첫 항목, `group-end`에서는 마지막 항목을 현재 항목으로 제공합니다.
- `page-start`, `page-end`, `before-data`와 `after-data`에서도 `@page` 또는 `@all`을 사용할 수 있습니다.
- `page-start`의 `@page`도 페이지 계획이 끝난 뒤 평가하므로 해당 페이지에 실제 배치된 항목을 참조합니다.
- 빈 항목의 셀 값 수식과 조건부 서식은 평가하지 않고 빈 값으로 출력합니다.
- 기존 `items.amount`와 같은 참조는 전표 전체 값에 대한 참조로 유지합니다.

`@` 참조 추가는 자체 수식 파서와 평가기에 구현하며 문자열 치환으로 처리하지 않습니다.

### 5.8 일반 요소의 출력 페이지 배치

일반 요소와 그리드에는 선택적인 `pagePlacement`를 제공합니다.

```json
{
  "pagePlacement": {
    "mode": "absolute",
    "pages": "all"
  }
}
```

절대 배치의 `pages`는 행 구간과 같은 `all`, `first`, `continuation`, `non-final`, `last` 값을 사용합니다.

| 값 | 동작 |
| --- | --- |
| `all` | 원본 양식 페이지에서 파생된 모든 출력 페이지에 같은 위치로 표시 |
| `first` | 첫 출력 페이지에만 표시 |
| `continuation` | 첫 페이지를 제외한 이어지는 출력 페이지에 표시 |
| `non-final` | 마지막 페이지를 제외한 출력 페이지에 표시 |
| `last` | 마지막 출력 페이지에만 표시 |

생략하면 기존 호환을 위해 `absolute`와 `all`로 처리합니다.

그리드가 늘어난 뒤에 이어서 배치할 요소는 다음 형식을 사용합니다.

```json
{
  "pagePlacement": {
    "mode": "after",
    "target": "items-grid",
    "gap": 2
  }
}
```

- `target` 요소의 마지막 출력 조각 뒤에 한 번 배치합니다.
- 남은 흐름 영역에 들어가지 않으면 다음 출력 페이지로 이동합니다.
- `after` 관계는 같은 원본 양식 페이지 안의 요소만 참조할 수 있습니다.
- 참조 순환은 파일 검증에서 거부합니다.
- 여러 요소를 연속 배치하려면 `after` 관계를 연결합니다.

이 구조로 모든 페이지의 제목·바닥글, 첫 페이지 안내, 마지막 페이지 서명란과 그리드 뒤의 합계를 구분합니다.

## 6. 페이지 계획 알고리즘

페이지 계획은 pdfme 스키마를 만들기 전에 순수 데이터 단계로 수행합니다.

### 6.1 준비

1. `maxItems`를 실제 데이터에 적용합니다.
2. 연속된 `groupBy` 값으로 그룹을 만듭니다.
3. 자동 확장 방식이면 `minItems`까지 빈 항목을 추가합니다.
4. 고정 페이지 방식이면 각 페이지가 `itemsPerPage`를 갖도록 마지막 페이지에 빈 항목을 추가합니다.
5. 행 구간별 높이를 계산합니다.

### 6.2 페이지 구성

각 출력 페이지는 다음 순서로 구성합니다.

1. 첫 페이지라면 `before-data` 구간을 배치합니다.
2. `page-start` 구간을 배치합니다.
3. `page-end` 구간의 높이를 먼저 예약합니다.
4. 그룹 시작, 항목과 그룹 종료 구간을 순서대로 배치합니다.
5. 마지막 데이터 뒤에 `after-data` 구간을 배치합니다.
6. 예약한 `page-end` 구간을 배치합니다.

다음 규칙을 함께 적용합니다.

- 항목 구간은 원자 단위이며 페이지 사이에서 나누지 않습니다.
- 그룹 시작 구간과 첫 항목은 함께 이동합니다.
- 그룹 종료 구간이 들어가지 않으면 마지막 항목과 함께 다음 페이지로 이동합니다.
- 마지막 페이지의 `after-data`가 들어가지 않으면 새 출력 페이지를 만들고 `page-start`, `after-data`, `page-end`를 배치합니다.
- 페이지에는 실제 항목 인덱스 목록을 기록하여 `@page` 평가에 사용합니다.
- 자동 병합은 페이지 경계와 그룹 경계에서 종료합니다.

### 6.3 여러 그리드

같은 원본 페이지에 독립적인 자동 확장 그리드가 여러 개 있을 수 있습니다.

- `after` 관계가 없는 그리드는 각자 페이지 계획을 만들고 같은 출력 페이지 번호에 겹쳐 배치합니다.
- 전체 출력 페이지 수는 가장 긴 독립 흐름의 페이지 수입니다.
- 짧은 흐름은 자신의 마지막 조각 이후 페이지에 빈 그리드를 만들지 않습니다.
- 세로로 이어져야 하는 그리드는 `after` 관계로 연결합니다.
- 계획 결과에서 독립 흐름의 출력 영역이 겹치면 렌더링 오류를 반환합니다.

현재처럼 가장 긴 그리드에 맞춰 다른 그리드를 빈 상태로 계속 복제하지 않습니다.

### 6.4 계획 결과

계획 계층은 최소한 다음 정보를 렌더러와 디자이너에 제공합니다.

- 원본 페이지와 출력 페이지의 대응
- 각 그리드 조각의 위치와 전체 높이
- 배치된 행 구간 인스턴스와 항목 인덱스
- 실제 항목과 빈 항목 구분
- 페이지별 실제 항목 목록
- 일반 요소의 표시 여부와 최종 위치
- 페이지 계획 오류와 관련 요소·행 구간

PDF 변환 코드는 계획 결과를 선, 배경과 텍스트 스키마로 펼치는 역할만 담당합니다.

## 7. 디자이너 설계

### 7.1 기본 동작

- 새 그리드는 반복 설정이 없는 정적 그리드로 만듭니다.
- 사용자가 행을 선택해 데이터 반복 영역을 지정할 때 목록 파라미터와 페이지 방식을 설정합니다.
- 반복을 켜는 즉시 임의의 `perPage`와 헤더 반복을 자동 지정하지 않습니다.

### 7.2 행 구간 편집

그리드 왼쪽에 행 번호 선택 영역을 둡니다. 연속된 행을 선택한 뒤 출력 범위와 시점을 나타내는 다음 표시 방식을 고릅니다.

- 전체 데이터 앞: 첫 출력 페이지에 한 번 표시
- 페이지별 데이터 앞: 표시할 페이지마다 데이터 앞에 표시
- 그룹별 데이터 앞: 각 그룹의 첫 항목 앞에 표시
- 데이터 반복 영역: 데이터 항목마다 반복
- 그룹별 데이터 뒤: 각 그룹의 마지막 항목 뒤에 표시
- 전체 데이터 뒤: 마지막 항목 뒤에 한 번 표시
- 페이지별 데이터 뒤: 표시할 페이지마다 데이터 뒤에 표시
- 행 구간 표시 방식 변경

행 구간은 그리드 캔버스와 속성 패널에서 같은 색상 표식과 이름으로 식별합니다. 색상만으로 표시 방식을 구분하지 않고 명칭, 아이콘과 대표 용도를 함께 사용합니다.

### 7.3 페이지 방식 편집

페이지 방식은 `자동 확장`과 `고정 페이지`의 세그먼트 선택으로 표시합니다.

- 자동 확장에서는 `최소 표시 항목 수`만 표시합니다.
- 고정 페이지에서는 `페이지당 항목 수`만 표시합니다.
- 두 입력을 동시에 표시하거나 동시에 저장하지 않습니다.
- 자동 확장에서는 흐름 영역의 하단을 캔버스 안내선으로 표시합니다.
- 고정 페이지 설정이 흐름 영역을 넘으면 해당 입력과 캔버스에 오류를 표시합니다.

### 7.4 셀과 그리드 편집 분리

- 그리드 선택 상태에서는 이름, 위치, 행·열, 행 구간과 페이지 방식을 편집합니다.
- 셀 선택 상태에서는 셀 이름, 값 소스, 병합, 글자, 색상, 테두리와 조건부 서식만 편집합니다.
- 셀 선택 상태에서 그리드 이름·위치·전체 크기 설정을 표시하지 않습니다.
- `그리드 편집으로 돌아가기`는 속성 패널 상단의 일관된 뒤로 가기 동작으로 제공합니다.
- 왼쪽 요소 목록은 `cell.name`을 우선 사용하고 이름이 없으면 좌표를 표시합니다.
- 파라미터 논리명이나 열 헤더를 셀 이름으로 자동 지정하지 않습니다.

### 7.5 미리보기

- 캔버스는 현재 선택한 출력 페이지의 계획 결과를 표시합니다.
- 페이지 전환 UI에서 자동 생성된 출력 페이지도 확인할 수 있어야 합니다.
- 빈 항목은 데이터가 없는 셀로 표시하며 파라미터 이름을 실제 출력값처럼 표시하지 않습니다.
- 샘플 값 변경 시 페이지 계획과 페이지 수를 다시 계산합니다.
- 계획 오류는 해당 그리드, 행 구간 또는 일반 요소의 설정 위치에 표시합니다.

## 8. 스키마와 마이그레이션

### 8.1 버전

현재 구조와 새 구조는 같은 `repeat` 필드라도 의미와 높이 계산이 다릅니다. 파일을 조용히 재해석하지 않도록 `schemaVersion`을 `0.2.0`으로 올리는 것을 기본안으로 합니다.

### 8.2 `0.1.0` 변환

기존 반복 그리드는 고정 페이지 방식으로 변환합니다.

- `parameter`는 유지합니다.
- `fromRow`~`toRow`는 `item` 구간으로 변환합니다.
- 위쪽 행은 `repeatHeader: true`이면 `page-start` 구간으로 변환합니다.
- 위쪽 행은 `repeatHeader: false`이면 `before-data` 구간으로 변환합니다.
- 아래쪽 행은 `page-end` 구간으로 변환합니다.
- `perPage`는 `pagination.mode: "fixed"`의 `itemsPerPage`로 변환합니다.
- `maxItems`는 유지합니다.
- 기존 `width`와 `height`는 행·열 합계 검증 후 제거합니다.
- 셀 이름은 만들지 않으며 좌표 표시를 사용합니다.

`repeatHeader: false`인 기존 파일은 후속 페이지의 빈 헤더 공간을 제거합니다. 이는 기존의 불필요한 공간 보존을 새 모델에 유지하지 않기 위한 의도적인 변경이며 마이그레이션 테스트와 변경 기록에 명시합니다.

### 8.3 저장된 데모 데이터

IndexedDB에 저장된 `0.1.0` 파일도 일반 파일과 같은 마이그레이션 경로를 사용해야 합니다. 데모 부팅 코드에서 별도 형식 변환을 추가하지 않습니다.

## 9. 구현 구조

### 9.1 Core

페이지 계획을 담당하는 순수 모듈을 새로 둡니다.

```text
format/schema        파일 구조와 의미 검증
layout/grid-plan     그리드 행 구간과 항목 인스턴스 계획
layout/page-plan     일반 요소와 여러 흐름을 출력 페이지로 배치
render/convert       계획 결과를 pdfme 스키마로 변환
```

- 현재 `renderPageCount`, `gridLayout`과 `expandRepeatBand`에 섞인 페이지 계산을 계획 모듈로 이동합니다.
- 렌더러가 다시 페이지 수를 계산하지 않게 합니다.
- 계획 모듈은 pdfme 타입에 의존하지 않습니다.
- 파일 객체와 전표 값을 변경하지 않습니다.
- 같은 입력은 항상 같은 계획 결과를 반환해야 합니다.

### 9.2 Elements

- 디자이너는 Core 계획 API를 사용해 캔버스를 구성합니다.
- PDF 미리보기만 별도로 호출해 페이지 수를 추측하지 않습니다.
- 셀 선택과 그리드 선택 상태를 별도 판별 타입으로 관리합니다.
- 행 구간 편집은 시작·종료 행 숫자 입력만 제공하지 않고 캔버스 행 선택과 연결합니다.

### 9.3 제한과 성능

- 행 구간 수, 페이지당 계획 블록 수와 생성 가능한 출력 페이지 수에 상한을 둡니다.
- 상한은 `SLIP_LIMITS`에서 관리하고 스키마와 런타임 계획에서 모두 검사합니다.
- 실제 항목 수가 많아도 전체 그리기용 셀 배열을 한 번에 복제하지 않고 페이지별 계획을 순차 생성합니다.
- 페이지 수나 계획 블록 상한을 넘으면 일부만 출력하지 않고 오류를 반환합니다.

## 10. 테스트 요구사항

구현 전에 현재 정적 그리드의 테두리, 병합, 서식과 값 계산을 회귀 테스트로 고정합니다. 이후 다음 테스트를 추가합니다.

### 10.1 스키마

- 정적 그리드는 행 구간 없이 유효함
- 반복 그리드에는 `item` 구간이 정확히 하나 필요함
- 여러 행으로 구성된 `item` 구간 허용
- 행 구간의 누락, 겹침과 범위 초과 거부
- 행 구간 경계를 넘는 셀 병합 거부
- 자동 확장과 고정 페이지 설정의 혼용 거부
- 그룹 설정 없는 그룹 행 구간 거부
- `after` 참조 누락과 순환 거부
- 셀 이름 저장과 직렬화

### 10.2 페이지 계획

- 자동 확장 데이터 0건, 최소값 미만, 최소값과 동일, 최소값 초과
- 고정 페이지 데이터 0건, 한 페이지 미만, 한 페이지와 동일, 여러 페이지
- 복수 행 항목이 페이지 사이에서 나뉘지 않음
- 헤더 없음, 첫 페이지만 헤더, 모든 페이지 헤더
- 그룹 시작·종료와 그룹 페이지 이월
- 페이지 소계의 `@page` 범위
- 그룹 소계의 `@group` 범위
- 전체 합계의 `@all` 범위
- 빈 항목이 집계와 조건부 서식에서 제외됨
- `before-data`, `after-data`가 한 번만 배치됨
- `page-start`, `page-end`가 출력 페이지마다 배치됨
- 마지막 합계가 들어가지 않을 때 새 페이지 생성
- 독립된 여러 그리드와 `after`로 연결된 그리드
- 첫 페이지, 모든 페이지와 마지막 페이지 일반 요소

### 10.3 렌더링

- 계획한 좌표와 PDF 스키마 좌표가 일치함
- 페이지별 그리드 선과 셀이 연결된 하나의 그리드로 보임
- 셀 병합, 자동 병합, 조건부 서식과 overflow 유지
- 자동 병합이 그룹·페이지 경계에서 종료됨
- 디자이너와 PDF의 출력 페이지 수와 항목 배치가 일치함

### 10.4 마이그레이션

- 기존 `perPage`가 고정 페이지 방식으로 변환됨
- 기존 복수 행 반복 구간 유지
- `repeatHeader`의 두 값에 따른 행 구간 변환
- 기존 아래쪽 행이 페이지 종료 구간으로 변환됨
- 파일 열기, IndexedDB 복원과 파일 교환이 같은 변환을 사용함

## 11. 구현 순서

1. 기존 정적 그리드와 반복 그리드의 보존할 동작을 회귀 테스트로 고정합니다.
2. 새 스키마 타입, 의미 검증과 `0.1.0` 마이그레이션 테스트를 작성합니다.
3. pdfme에 의존하지 않는 그리드·페이지 계획 모듈과 단위 테스트를 구현합니다.
4. 기존 렌더러를 계획 결과 소비 구조로 변경합니다.
5. 수식 예약 참조와 집계 범위 테스트를 구현합니다.
6. 디자이너의 행 구간, 페이지 방식과 셀 이름 편집을 구현합니다.
7. 캔버스, PDF 미리보기와 최종 PDF의 결과를 대조합니다.
8. 저장된 예제·프리셋과 JSON Schema를 새 버전으로 갱신합니다.
9. 요구사항, ADR과 파일 형식 명세를 실제 구현과 함께 개정합니다.

각 단계는 관련 테스트가 통과한 뒤 다음 단계로 진행합니다. 기존 `perPage` 코드를 남겨 새 계획 코드와 결과를 비교하는 이중 렌더링 구조는 최종 구현에 남기지 않습니다.

## 12. 구현 완료 조건

- 자동 확장 방식과 고정 페이지 방식이 서로 다른 설정으로 동작합니다.
- 최소 표시 항목 수가 부족한 데이터만 빈 항목으로 채웁니다.
- 한 데이터 항목이 여러 행이어도 페이지 사이에서 분리되지 않습니다.
- 헤더, 그룹 소계, 페이지 소계와 전체 합계를 선택적으로 구성할 수 있습니다.
- 고정 그리드와 반복 그리드를 별도 요소로 나누지 않습니다.
- 일반 요소의 첫 페이지·전체 페이지·마지막 페이지와 이어서 배치를 구분할 수 있습니다.
- 셀 이름을 편집할 수 있고 셀 편집과 그리드 편집이 분리됩니다.
- 디자이너와 PDF가 같은 페이지 계획을 사용합니다.
- 기존 `0.1.0` 반복 그리드가 고정 페이지 방식으로 변환됩니다.
- Core와 Elements의 관련 회귀 테스트, 타입 검사, 린트와 빌드가 통과합니다.

## 13. 이번 작업에서 제외할 범위

- 엑셀 파일 가져오기와 내보내기
- 엑셀 수식 전체 호환
- 내용에 따른 자동 행 높이 변경
- 열 방향 페이지 분할
- 중첩 목록과 중첩 그리드
- 데이터를 렌더러가 자동 정렬하는 기능
- 그리드 재설계와 관계없는 전체 화면·기능 설계문서 작성

전체 설계문서는 별도 작업으로 작성합니다. 이번 개발에서는 그리드의 파일 모델, 페이지 계획, 렌더링과 디자이너 동작을 우선합니다.
