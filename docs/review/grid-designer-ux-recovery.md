# 그리드 디자이너 사용성 복구 계획

## 목적

그리드 재설계에서 추가한 기능을 기존 디자이너의 편집 방식에 맞게 정리한다. 기능의 존재 여부가 아니라 사용자가 화면에서 다음 작업을 막힘없이 완료할 수 있는지를 기준으로 검증한다.

1. 그리드를 만들고 반복 데이터를 연결한다.
2. 헤더, 데이터 행, 그룹 소계, 페이지 소계와 최종 합계 행을 구성한다.
3. 셀에 이름을 붙이고 요소 목록에서 다시 찾는다.
4. 페이지별 출력 결과와 오류 위치를 확인한다.

## 작업 원칙

- 내부 스키마 용어를 그대로 나열하지 않고 사용자가 하려는 작업을 먼저 제시한다.
- 캔버스와 속성 패널 중 한쪽에서만 가능한 필수 조작을 만들지 않는다.
- 자동으로 값을 만들거나 행 역할을 바꾸는 경우 변경 결과를 조작 전에 알 수 있게 한다.
- 오류는 원인이 있는 입력 또는 행 가까이에 표시한다.
- 각 단계는 테스트와 실제 데모 확인을 마친 뒤 종료한다.

## 현재 확인한 문제

### 조작 불능

- 행 번호와 행 역할 메뉴가 그리드 요소 바깥에 배치되지만 요소의 `overflow: hidden`에 잘린다.
- 요소의 직계 자식에 적용한 `pointer-events: none` 때문에 행 번호와 역할 메뉴를 포인터로 조작할 수 없다.
- 기존 테스트는 DOM의 `click()`만 호출하므로 실제 화면에서 클릭할 수 없는 문제를 발견하지 못한다.

### 탐색 불일치

- 셀 이름을 입력해도 파라미터나 수식이 없는 셀은 왼쪽 요소 목록에 나타나지 않는다.
- 이는 `cell.name`을 편집기 이름으로 사용한다는 `grid-redesign.md` 7.4절과 맞지 않는다.

### 반복 설정의 작업 흐름 부재

- 페이지 소계는 `page-end`, `pages: non-final`, `@page`를 서로 다른 위치에서 조합해야 한다.
- 그룹 소계는 `group-end`, 그룹 기준과 `@group`을 직접 조합해야 한다.
- 최종 합계는 `after-data`와 `@all`을 직접 조합해야 한다.
- 화면에는 페이지 소계, 그룹 소계와 최종 합계를 만드는 명령이 없어 사용자가 내부 모델을 알아야 한다.
- 행을 추가하면 마지막 행 구간에 자동 편입되므로 합계 행을 추가한 뒤 다시 역할을 바꿔야 한다.

### 패널 구조와 피드백

- 300px 속성 패널에 구조, 반복, 페이지 방식, 그룹 기준, 행 구간과 스타일이 한 흐름으로 이어져 핵심 조작을 찾기 어렵다.
- 행 역할 지정은 캔버스에서 수행하지만 관련 오류는 아래쪽 속성 패널에 표시된다.
- 그룹 기준이 쉼표로 구분한 자유 입력이어서 사용 가능한 필드와 입력 형식을 화면에서 알기 어렵다.
- 행 구간 목록은 상태만 보여 주며 역할과 범위를 직접 수정할 수 없다.

### 1단계: 기본 조작 복구

상태: 완료

- [x] 행 번호와 역할 메뉴가 화면에 보이고 실제 포인터로 조작되는지 확인한다.
- [x] 이름이 있는 셀은 값 종류와 관계없이 요소 목록에 표시한다.
- [x] DOM 존재 여부만 확인하는 테스트를 실제 노출 조건을 검증하도록 보완한다.
- [x] 요소 패키지 테스트와 타입 검사를 통과한다.

종료 조건: 반복 그리드에서 행 역할을 지정할 수 있고, 이름을 붙인 직접 입력 셀을 요소 목록에서 다시 선택할 수 있다.

### 2단계: 반복 설정 패널 재구성

상태: 완료

- [x] 반복 설정을 기본 설정과 고급 설정으로 나눈다.
- [x] 행 구간을 속성 패널에서도 선택하고 역할을 변경할 수 있게 한다.
- [x] 행 추가 시 어느 구간에 추가할지 선택할 수 있게 한다.
- [x] 그룹 기준을 목록 필드 선택 방식으로 바꾼다.

- 그룹 기준은 쉼표 입력이 아니라 반복 파라미터의 필드 목록에서 고른다.
- 기본 설정을 먼저 보여 주고 최대 항목 수와 그룹 설정은 고급 설정에서 편집한다.

종료 조건: 캔버스의 작은 조작 영역을 사용하지 않아도 반복 구조를 완성할 수 있다.

### 3단계: 헤더·소계·합계 작업 흐름

- [x] 명령 실행 전에 추가될 행 역할, 표시 페이지와 계산 범위를 보여 준다.

### 4단계: 오류·미리보기·반응형 정리

## 재개 지점

작업을 다시 시작할 때 이 문서에서 첫 번째로 완료되지 않은 항목부터 진행한다. 단계가 끝나면 상태와 체크 항목을 갱신하고, 검증 결과와 남은 문제를 아래 기록에 추가한다.

## 작업 기록

### 1단계

- 시작 기준: `feat/repo-grid-redesign` 브랜치의 `170e75b`
- 셀 편집 중에는 행 번호와 역할 메뉴를 숨겨 그리드 편집과 셀 편집이 겹치지 않게 했다.
- 역할 메뉴를 선택한 행 옆에 표시하고 그리드 미리보기와 입력 영역의 클리핑을 분리했다.
- 이름이 있는 직접 입력 셀도 왼쪽 요소 목록에 표시하도록 셀 탐색 기준을 수정했다.
- 요소 패키지 테스트: 11개 파일, 296개 테스트 통과
- 요소 패키지 타입 검사 통과
- 변경 파일 ESLint 검사와 `git diff --check` 통과
- 데모 확인: 실제 포인터로 행 번호를 눌러 역할 메뉴가 열리고, 셀을 선택하면 행 도구가 사라지는 것을 확인

### 2단계

- 반복·파라미터·페이지 방식은 기본 설정에 두고 최대 항목 수와 그룹 기준은 접힌 고급 설정으로 옮겼다.
- 행 구간 목록에서 범위와 역할을 바로 수정하고, 새 행은 역할을 고른 뒤 추가하도록 바꾸었다.
- 그룹 기준은 쉼표 문자열이 아니라 목록 파라미터의 실제 필드 목록에서 고르게 했다.
- 캔버스와 패널은 같은 행 역할 명칭, 아이콘과 색상을 사용한다.
- 300px 패널에서 고급 설정, 행 구간 선택과 역할 변경을 실제 포인터로 확인했다.

### 3단계

- 행 구간 상단에 `헤더`, `그룹 소계`, `페이지 소계`, `최종 합계` 명령을 추가했다.
- 적용 전에 위치, 표시 범위와 계산 범위를 보여 주며, 숫자 필드는 사용자가 바꿀 수 있다.
- 헤더는 항목 행의 열 이름과 서식을 기준으로 만들고, 소계·합계는 `@group`, `@page`, `@all` 범위의 `SUM` 수식을 생성한다.
- 페이지 소계는 기본으로 마지막 페이지를 제외하고, 목록에서 표시 페이지·행 범위·역할을 다시 수정할 수 있다.
- 생성한 수식 셀은 선택 편집 화면에서도 현재 출력 페이지의 예약 참조를 계산해 긴 수식 문자열 대신 결과를 표시한다.
- 요소 패키지 테스트 11개 파일, 304개 테스트와 타입 검사를 통과했다.
- 변경 파일 ESLint 검사, 요소 패키지 빌드와 `git diff --check`를 통과했다.
- 데모 확인: 300px 패널에서 명령을 포인터로 선택·적용했고 가로 넘침이 없음을 확인했다. 페이지 소계는 가장 오른쪽 숫자 필드를 기본으로 고르고 `page-end`, `non-final`, `SUM(@page.필드)`를 한 번에 생성했다.

### 4단계

- 페이지 계획 오류에 요소와 행 구간 식별 정보를 연결하고, 캔버스와 해당 행 구간에 오류를 표시했다. <kbd>문제 위치 보기</kbd>로 문제가 있는 그리드와 행 구간을 선택할 수 있다.
- 캔버스 상단에 행 구조와 출력 결과를 전환하는 막대와 출력 페이지 이동 버튼을 추가했다. 출력 결과에서는 편집·삭제를 막고 <kbd>Escape</kbd>로 행 구조 편집에 돌아온다.
- 출력 전환 막대와 계획 오류를 용지의 CSS Grid에서 분리해 전용 캔버스 상단 영역에 배치했다. 버튼이 세로로 눌리거나 용지 아래로 밀리던 배치 문제를 해소했다.
- 속성 패널은 일반 화면에서 300px, 폭 960px 이하에서 280px을 사용한다. 1440px와 900px 화면에서 본문 가로 넘침 없이 패널과 캔버스가 각각 올바르게 스크롤되는 것을 확인했다.
- 행 역할 메뉴를 열면 첫 명령으로 포커스가 이동하며 방향키, <kbd>Home</kbd>, <kbd>End</kbd>와 <kbd>Escape</kbd>로 조작할 수 있다. 메뉴를 닫으면 조작을 시작한 행 번호로 포커스가 돌아간다.
- 실제 데모에서 출력 결과 전환, 읽기 전용 삭제 방지, 행 번호 메뉴의 키보드 조작과 포커스 복귀를 확인했다.

### 5단계

- 디자이너, 수식과 API 가이드의 한국어·영어·일본어 문서 9개를 새 행 구간, 페이지 방식, 계산 범위와 출력 결과 조작에 맞게 갱신했다.
- 세 언어의 그리드 화면 이미지를 현재 디자이너 화면으로 교체하고, UI에 없는 `반복 사용`과 폐기된 `perPage`, `repeatHeader` 용어를 제거했다.
- 변경한 9개 가이드의 로컬 문서·이미지 링크를 검사했다.
- 요소 패키지 테스트 11개 파일, 307개 테스트와 타입 검사를 통과했다.
- 변경 파일 ESLint 검사, 요소 패키지 빌드와 `git diff --check`를 통과했다.

### 다음 재개 지점

그리드 디자이너 사용성 복구 1~5단계는 완료했다. 후속 변경은 이 문서의 종료 조건을 회귀 검증 기준으로 사용한다.
