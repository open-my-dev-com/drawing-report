# 유저 사용 리뷰

> [!IMPORTANT]
> 전체적인 평가는 그럴싸하게 만들어졌으나 전혀 유저의 편의성과 유저의 사용감은 일체 고려하지 않은 개발로 보여집니다.
> 내부의 수정할 내용이 너무 많아 전체적인 내용을 읽고 비슷한 내용끼리 먼저 정리해야할 듯합니다.
> 분명 이전 단계에서 자체평가를 하여 내용을 정리하였음에도 불구하고 본인 스스로의 자체평가가 너무 후한게 아닌지 우려됩니다. 유저의 관점에서 사용했을때를 고려해달라는 요청이 있었음에도 전혀 고려되지 않았습니다.
> 점수는 28/100점입니다.

## 버그
- 1. 행과 열 추가에서 아이콘 버튼으로 바뀌면서 +버튼과 열 라벨이 CSS상으로 붙어져버리는 버그 발생.
- 2. 고정이미지, 변동이미지 버튼 깨짐현상있음. => 이미지 업로드와 파라미터(현재 값이라 불리는 것) 2가지로 나누는게 더 나을것으로 보여짐. 
- 3. 텍스트는 백스페이스로도 잘만 지워지는데 왜 도형은 안지워질까요? (뭔가 버그가 있음, 지워질때는 지워지고 안지워질때는 안지워짐. 버그가 왜 발생하는지 모름. 다시 하니까 또 지워졌음 => 다시 해보니까 만든 시점에서는 제거가 안됨. 다른데를 클릭후에 다시 클릭하여 백스페이스해야 제거되는거 확인.)
- 4. 페이지 설정에 쓰레기 뭐지요? => "썸네일·목록에 번호 대신 나온다"
- 5. 샘플 데이터 편집 모달 : 입력폼 JSON전환시, 서로의 내용이 다른 이슈있음. 입력폼에서 아무 값도 입력 안했으면 적어도 "파라미터명": "" 의 형태로 전환되어야하는게 아닌가 싶음. (placeholder는 사용자로 하여금 혼동의 여지가 올 수 있으니 제거바람 => 실제로 값이 들어있는줄 알았습니다.)
- 6. 버그는 아닐것 같은데 확인차. 그리드에서 배경색 설정하고 설정된 셀의 값을 입력하기 위해서 클릭하면 Input박스가 열리면서 배경색이 순간적으로 사라진 것으로 보이는 데, 기술적으로 이거 해결 못하는지 궁금(Input박스도 배경색을 따라가게 한다던가 하는) 안되면 뭐 어쩔수 없다고 생각함.

## 고쳐야 할 점 (화면계)

### [공통]
- 1. 세로쓰기의 버튼이 혼자 가운데 정렬이 되어있음. 스타일의 일체화가 전혀 이루어지지 않고 있음. 또한, 버튼 크기도 작아서 클릭하기 불편함. 최소한 아이콘버튼 수준의 크기 요구. (다른 버튼 계열도 마찬가지)
- 2. 수식 편집 모달에서 바인딩값을 단순 뱃지로 해서 클릭해서 추가하는 것에 대해서, 이전에 말했던 바인딩 변수의 타입이 지정되어있지 않아 아무거나 막 입력해도 검사 조차 없음. 애초에 분명 이전 대화로 바인딩에 타입을 넣는다고 했었던것 같은데 이 부분이 적용되어 있지 않아 생기는 문제로 보임.
- 3. 고정 문구 => "직접 입력"으로 수정
- 4. 바인딩 => "파라미터"로 수정 요청
- 5. 종류 보기 => "요소 확인"으로 수정 요청

### [선]
- 1. 가로/세로일때는 굵기, 기준점이 마음대로 왔다갔다 하고 있음.(선에 기준점 요소를 넣을거면 오른쪽이냐 왼쪽이냐 하나로 넣는게 나음. 위일 경우 오른쪽, 아래의 경우 왼쪽 이렇게 해도 되고 아니면 차라리 좌표 1,1 좌표 2,2 로 좌표값을 2개를 받아서 좌표 1을 기준점으로 할지 좌표 2를 기준점으로 할지정도가 더 낫지 않나.)
- 2. 사선일 경우 선굵기 설정이 없음.(너비높이로 바뀜. 버그인지 고정된건지 모르겠음.)
- 3. 애초에 선의 경우 방향을 굳이 오른쪽 사이드바에서 설정할 이유를 모르겠음. 그냥 기준점위치, 길이, 선 굵기, 선 색, 형태만 있으면 되는거 아닌가?

### [사각형]
- 1. 사각형 테두리가 없음 상태가 없음상태인건지 없음 상태인것처럼 보이는데, #000000설정으로 보임. 또한, 사각형에서 테두리 굵기 설정 + 테두리색 기본형태로 하면 테두리가 분명 없어야할텐데 미묘한 테두리같은게 생김.(원본색에서 살짝 어두운형태의) => 근데 이 어두운형태의 테두리 자체는 이쁜것 같긴 함. 그래서 그냥 없애고 싶지는 않은 느낌도 드네... 이걸 어떻게할지 고민좀.

### [텍스트와 필드]
- 기본적으로 비슷한 형태고, 내용이 직접 입력이랑, 파라미터 설정, 수식 설정 이렇게 3개로 나뉘는것 같은데 분리할 필요성이 새삼 있을까... 아이콘자체는 지금처럼 분리하는게 좋긴 한데 그리드의 칸 내용이라는걸 놓고 보니 나눌 필요가 있나 싶은 느낌이 듭니다.

### [그리드]
- 1. 넘칠 때 자르기 => 의도 불분명한 표현의 사용. 뭐가 넘친다는건지 뭘 자른다는건지 확실하게 이해가 안됨. 이제 보니까 문자열이 길어져서 넘칠때를 의미하는것 같은데 의도 전달 가능하게 명칭 수정.
- 2. 반복 구간의 명칭의 전체적인 문제가 있음 글자 크기가 길어져서 문제가 될 것 같으니, 차라리 라벨 값을 한 줄에 이어 쓰는 방식보다 2줄에 나누어서 쓰는 방식도 검토해야겠습니다.
```
반복 구간 : 구간 반복이 더 나을것 같네요.
첫 행, 끝 행 : 시작 행 종료 행
페이지당 : 구간의 기본 틀 생성 갯수
헤더 반복 : 페이지 전환시 헤더 반복

=> 추가로 최대 반복 구간 갯수 제한 기능이 없어, 무제한만 허용중인것도 고쳐야함.
```
- 3. 그리드에서 특정 셀을 선택할 경우, 그리드 자체의 옵션은 감춰줘야합니다. (유저 혼동의 여지 있음) 그리드 대신 셀옵션으로 바꿔주고, 그리드 하위의 셀로 별도의 이름을 가지게 하는 편이 더 나을것 같습니다. (그리드와 셀분리, 이전의 요소와 바인딩의 분리하고도 같은 내용)


## 의도와 다른 점

### 바인딩
- 바인딩과 요소를 결국 분리해내지 못함. (그 증거로 하위 바인딩입력시 여전히 요소로 자동연결이 되어버림)
- 입력필드에는 바인딩을 SELECT박스로 유저의 바인딩 실수가 발생하지 않게 유도해주는 부분이 있으나, 다른 화면에는 이러한 조치가 행해져 있지 않음.(위와 동일)
- 바인딩자체가 제대로 설계되어있지 않으니 하위바인딩을 만드는 방법조차 없음.(그리드를 만들어야만 만들어지는 기괴한 구조가 되어있음) 바인딩에 대해서 전체적으로 문제투성이.

### 왼쪽 사이드바의 하위요소
- N행 N열 -> n가 아니고, 셀 이름이 나오면 됨. (요소와 바인딩 분리를 확실히)
