# FNC-015 파일 암호화와 키 교체

최종 갱신: 2026-09-28

## 개요

`.slip` 파일을 AES-256-GCM 봉투로 암호화하고 현재 키와 이전 키를 사용해 안전하게 복호화하는 흐름을
정의합니다.

## 변경 이력

| 날짜 | 구분 | 변경 내용 |
| --- | --- | --- |
| 2026-09-28 | 신규 작성 | 키 검증, 봉투 처리, 키 교체 순서와 오류 경계를 정의했습니다. |

## 호출 조건

호스트, 브라우저 저장소와 파일 교환이 암호화 저장을 선택하거나 암호화 봉투를 읽을 때 호출합니다.

## 입력·출력

| 구분 | 항목 | 조건 |
| --- | --- | --- |
| 입력 | `SlipFile`과 문자열 또는 32바이트 키 | 빈 암호 문구와 길이가 다른 원시 키는 허용하지 않습니다. |
| 출력 | 암호화 JSON 또는 검증된 `SlipFile` | 봉투는 버전 1, A256GCM 형식입니다. |

## 사전·사후 조건

`createSlipKit()` 구성 시 현재 키와 모든 이전 키를 먼저 검증합니다. 문자열 키는 NFC로 정규화해
PBKDF2-SHA256 600,000회로 파생하며 원시 키는 바이트를 그대로 사용합니다.

## 정상 처리 흐름

```mermaid
flowchart LR
    File[SlipFile] --> Serialize[JSON 직렬화]
    Serialize --> Encrypt[AES-GCM 암호화]
    Encrypt --> Envelope[암호화 봉투]
    Envelope --> Parse[봉투 구조 검사]
    Parse --> Keys[현재 키와 이전 키 시도]
    Keys --> Validate[복호화 파일 검증]
```

## 분기와 예외 흐름

문자열 키에는 솔트와 반복 횟수를 기록하고 원시 키에는 `kdf`를 두지 않습니다. 복호화는 키 불일치일
때만 다음 이전 키를 시도합니다. 봉투 손상, 지원하지 않는 버전·알고리즘과 복호화된 파일 검증 오류는
즉시 중단합니다.

## 데이터 조회·변경

키를 저장하거나 반환하지 않습니다. 난수 IV와 솔트를 매번 새로 만들며 평문 파일을 바꾸지 않습니다.

## 하위 기능과 시퀀스

봉투 파싱, 키 파생, 인증 복호화 뒤 FNC-001 파일 검증을 수행합니다.

## 오류·복구

키 없음·형식 오류·불일치·변조를 `SlipEncryptionError`로 구분해 알립니다. 맞지 않는 키로 평문을
추정하거나 일부 내용을 복구하지 않습니다.

## 검증 기준

문자열·원시 키, NFC·NFD, 잘못된 설정, 세 번째 이전 키, 변조, 반복 횟수 상한과 Web Crypto 부재를
시험합니다.
