# FNC-015 파일 암호화와 키 교체

최종 갱신: 2026-09-28

## 개요

`.slip` 파일을 AES-256-GCM 봉투로 암호화하고 현재 키와 이전 키를 사용해 안전하게 복호화하는 흐름을
정의합니다.

## 변경 이력

| 날짜 | 구분 | 변경 내용 |
| --- | --- | --- |
| 2026-09-28 | 신규 작성 | 키 검증, 봉투 처리, 키 교체 순서와 오류 경계를 정의했습니다. |

## 호출 조건

호스트, 브라우저 저장소와 파일 교환이 암호화 저장을 선택하거나 암호화 봉투를 읽을 때 호출합니다.

## 입력·출력

| 구분 | 항목 | 자료형·단위 | 필수 여부·기본값 | 제약과 보장 |
| --- | --- | --- | --- | --- |
| 입력 | 일반 파일 | 검증된 `SlipFile` | 암호화에 필수 | 현재 스키마 파일이며 원본을 바꾸지 않습니다. |
| 입력 | 현재 키 | 비어 있지 않은 문자열 또는 32바이트 배열 | 필수 | 문자열은 NFC 정규화 뒤 PBKDF2로 파생합니다. |
| 입력 | 이전 키 | 키 배열 | 선택·빈 배열 | 복호화에서 현재 키 다음 순서대로 사용합니다. |
| 출력 | 암호화 봉투 또는 일반 파일 | JSON 문자열 또는 `SlipFile` | 성공 시 반환 | 봉투는 v1 A256GCM이며 복호화 결과는 전체 검증을 통과합니다. |

## 사전·사후 조건

`createSlipKit()` 구성 시 현재 키와 모든 이전 키를 먼저 검증합니다. 문자열 키는 NFC로 정규화해
PBKDF2-SHA256 600,000회로 파생하며 원시 키는 바이트를 그대로 사용합니다.

## 정상 처리 흐름

```mermaid
flowchart LR
    File[SlipFile] --> Serialize[JSON 직렬화]
    Serialize --> Encrypt[AES-GCM 암호화]
    Encrypt --> Envelope[암호화 봉투]
    Envelope --> Parse[봉투 구조 검사]
    Parse --> Keys[현재 키와 이전 키 시도]
    Keys --> Validate[복호화 파일 검증]
```

| 순서 | 처리 | 읽는 값 | 만드는 값·변경하는 값 | 다음 단계 |
| --- | --- | --- | --- | --- |
| 1 | 검증된 파일을 현재 JSON 형식으로 직렬화합니다. | Slip 파일 | 평문 바이트 | 암호화 |
| 2 | 무작위 salt와 IV를 만들고 현재 키로 AES-256-GCM 암호화합니다. | 평문 바이트, 현재 키 | 암호문과 인증 태그 | 봉투 생성 |
| 3 | 알고리즘 정보, salt, IV와 암호문을 암호화 봉투로 직렬화합니다. | 암호화 결과 | 저장 가능한 봉투 문자열 | 반환 |
| 4 | 읽을 때 봉투 구조와 Base64 필드를 먼저 검사합니다. | 봉투 문자열 | 복호화 후보 정보 | 키 시도 |
| 5 | 현재 키부터 이전 키 순서로 인증 복호화를 시도합니다. | 복호화 후보, 키 목록 | 평문 후보 또는 키 불일치 | 파일 검증 |
| 6 | 복호화한 JSON을 DAT-001 계약으로 검증한 뒤에만 반환합니다. | 평문 후보 | 검증된 Slip 파일 | 반환 |

## 분기와 예외 흐름

문자열 키에는 솔트와 반복 횟수를 기록하고 원시 키에는 `kdf`를 두지 않습니다. 복호화는 키 불일치일
때만 다음 이전 키를 시도합니다. 봉투 손상, 지원하지 않는 버전·알고리즘과 복호화된 파일 검증 오류는
즉시 중단합니다.

## 데이터 조회·변경

키를 저장하거나 반환하지 않습니다. 난수 IV와 솔트를 매번 새로 만들며 평문 파일을 바꾸지 않습니다.

## 하위 기능과 시퀀스

봉투 파싱, 키 파생, 인증 복호화 뒤 FNC-001 파일 검증을 수행합니다.

## 오류·복구

키 없음·형식 오류·불일치·변조를 `SlipEncryptionError`로 구분해 알립니다. 맞지 않는 키로 평문을
추정하거나 일부 내용을 복구하지 않습니다.

## 동시 실행·반복 호출

각 암호화 호출은 새 IV와 문자열 키용 새 솔트를 사용합니다. 같은 평문과 키를 반복 암호화해도 봉투는
달라야 합니다. 복호화 호출은 키 목록을 읽기만 하며 동시 호출끼리 현재 키, 이전 키 순서와 평문을
공유하지 않습니다.

## 검증 기준

문자열·원시 키, NFC·NFD, 잘못된 설정, 세 번째 이전 키, 변조, 반복 횟수 상한과 Web Crypto 부재를
시험합니다.
