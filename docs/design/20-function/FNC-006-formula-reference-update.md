# FNC-006 수식 참조 변경

최종 갱신: 2026-09-28

## 개요

수식 안의 값 참조를 수집하고 파라미터 키를 바꿀 때 해당 참조만 안전하게 다시 쓰는 흐름을
정의합니다.

## 변경 이력

| 날짜 | 구분 | 변경 내용 |
| --- | --- | --- |
| 2026-09-28 | 신규 작성 | 참조 수집, 예약 참조 구분과 키 변경 규칙을 정의했습니다. |

## 호출 조건

디자이너가 파라미터 이름을 바꾸기 전 영향 범위를 확인하거나, 변경을 수식에 반영할 때 사용합니다.

## 입력·출력

| 구분 | 항목 | 조건 |
| --- | --- | --- |
| 입력 | 수식 문자열 | 유효한 SlipKit 수식이어야 합니다. |
| 입력 | 이전·새 참조 경로 | 값 참조와 예약 참조 여부를 함께 지정할 수 있습니다. |
| 출력 | 참조 목록 또는 변경한 수식 | 문자열 리터럴과 다른 키는 그대로 둡니다. |

## 사전·사후 조건

파서가 기록한 참조 범위만 고칩니다. 텍스트 검색으로 같은 글자를 바꾸지 않으며 `@item`과
`$(@item)`을 서로 다른 참조로 취급합니다.

## 정상 처리 흐름

```mermaid
flowchart LR
    Formula[수식] --> Parse[구문 분석]
    Parse --> Collect[참조와 위치 수집]
    Collect --> Match[대상 경로 비교]
    Match --> Rewrite[뒤쪽부터 치환]
```

## 분기와 예외 흐름

대상 참조가 없으면 원문을 반환합니다. 구문 오류, 빈 경로와 잘못된 예약 참조는 호출자에게 그대로
알립니다.

## 데이터 조회·변경

원본 수식만 읽고 새 문자열을 반환합니다. 양식 안의 여러 수식에 적용하는 순회는 디자이너 기능이
담당합니다.

## 하위 기능과 시퀀스

FNC-004 파서와 `formatReferencePath()`를 사용합니다. 위치가 밀리지 않도록 뒤에 있는 참조부터
바꿉니다.

## 오류·복구

일부만 바꾸고 끝내지 않습니다. 디자이너는 전체 대상 수식의 변경 가능 여부를 먼저 확인한 뒤 하나의
문서 변경으로 적용합니다.

## 검증 기준

중첩 경로, 유니코드·점·괄호·역슬래시 키, 예약 참조, 문자열 리터럴과 같은 이름이 여러 번 나오는
수식을 시험합니다.
