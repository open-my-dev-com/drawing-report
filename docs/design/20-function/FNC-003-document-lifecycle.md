# FNC-003 양식 생성과 전표 발행 생명주기

최종 갱신: 2026-09-28

## 개요

양식과 값에서 독립된 미발행 전표를 만들고 작성 폼에서 변경·발행 상태로 전환하는 생명주기를
정의합니다.

## 변경 이력

| 날짜 | 구분 | 변경 내용 |
| --- | --- | --- |
| 2026-09-28 | 신규 작성 | 전표 조립, 값 변경, 발행과 새 전표 초기화 흐름을 정의했습니다. |

## 호출 조건

호스트나 MCP가 검증된 양식과 초기 값으로 전표를 시작할 때 `buildVoucher()`를 호출합니다. 작성 폼은
양식 또는 기존 전표를 `src`로 받아 같은 흐름을 시작합니다.

## 입력·출력

| 구분 | 항목 | 자료형·단위 | 필수 여부·기본값 | 제약과 보장 |
| --- | --- | --- | --- | --- |
| 입력 | 양식 파일 | `SlipTemplateFile` | 필수 | 현재 스키마 검증을 통과한 양식입니다. |
| 입력 | 초기 값 | `Record<string, JsonValue>` | 선택·빈 객체 | 파라미터 키별 JSON 값이며 원본을 바꾸지 않습니다. |
| 출력 | 미발행 전표 | `SlipVoucherFile` | 생성 성공 시 | 양식과 값을 깊은 복사하고 `issued`를 `false`로 둡니다. |
| 출력 | 발행 전표 | `SlipVoucherFile` | 발행 검증 성공 시 | 같은 스냅샷과 값에 `issued: true`를 적용합니다. |

## 사전·사후 조건

입력 양식과 값은 호출 뒤 바뀌어도 결과에 영향을 주지 않도록 깊은 복사합니다. 성공 결과는 현재
스키마 버전을 사용하며 원본 양식의 이후 변경과 독립적입니다.

## 정상 처리 흐름

```mermaid
stateDiagram-v2
    [*] --> Template
    Template --> Draft: 전표 조립
    Draft --> Draft: 값 변경
    Draft --> Issued: 발행
    Issued --> Draft: reset으로 같은 양식의 새 전표
```

| 순서 | 처리 | 읽는 값 | 만드는 값·변경하는 값 | 다음 단계 |
| --- | --- | --- | --- | --- |
| 1 | 검증된 양식과 초기 값을 각각 깊은 복사합니다. | 양식, 초기 값 | 독립된 양식 스냅샷과 값 | 미발행 전표 생성 |
| 2 | 스냅샷과 값에 미발행 상태를 붙여 전표를 만듭니다. | 복사본 | 미발행 전표 | 값 편집 또는 발행 |
| 3 | 값 변경을 검증해 새 미발행 전표를 만들고 변경 결과를 알립니다. | 현재 전표, 변경 값 | 새 미발행 전표 | 다음 편집 또는 발행 |
| 4 | 발행 직전 전체 파일과 계산 가능한 값을 검사합니다. | 현재 미발행 전표 | 발행 전표 또는 오류 | 결과 알림 |
| 5 | 초기화하면 같은 원본 양식으로 빈 미발행 전표를 새로 만듭니다. | 현재 원본 양식 | 새 미발행 전표 | 값 편집 |

작성 폼은 유효한 값 변경마다 미발행 전표를 `slip-change`로 알리고, 발행 검증이 끝나면
`issued: true` 전표를 `slip-issue`로 알립니다.

## 분기와 예외 흐름

발행 전표 입력은 편집하지 않습니다. 발행 시 수식, 이미지와 값 구조 오류가 남아 있으면 상태를
바꾸지 않고 오류를 표시합니다. MCP는 발행 전표를 생성·교체·수정하지 않습니다.

## 데이터 조회·변경

전표는 `templateSnapshot`, `values`, `issued`만으로 다시 표시할 수 있습니다. 저장 ID, 승인 상태와
감사 정보는 호스트 저장소가 관리합니다.

## 하위 기능과 시퀀스

FNC-002 값 정규화, FNC-005 수식 평가, FNC-011 이미지 확인과 FNC-013 PDF 렌더링을 사용합니다.

## 오류·복구

잘못된 값은 사용자가 고칠 수 있도록 입력 상태에 남깁니다. `reset()`은 현재 원본 양식에서 값을
비우고 발행 잠금을 해제하여 새 전표를 시작합니다.

## 동시 실행·반복 호출

한 작성 폼 안에서는 값 변경을 발생 순서대로 적용합니다. 발행을 시작한 뒤 들어온 값 변경은 해당 발행
결과에 섞지 않으며, 발행 성공 뒤에는 새 전표를 시작하기 전까지 추가 변경을 받지 않습니다. 초기화는
진행 중인 출력 결과를 폐기하고 같은 양식으로 빈 미발행 전표를 한 번만 만듭니다.

## 검증 기준

깊은 복사, 양식·미발행·발행 전표 입력, 변경 이벤트, 발행 실패·성공과 `reset()`을 시험합니다.
