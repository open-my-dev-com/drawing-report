# FNC-019 디자이너 문서 편집

최종 갱신: 2026-09-28

## 개요

`<slip-designer>`가 양식 전체를 불러오고 페이지·요소·용지·메타데이터를 변경한 뒤 검증된 파일을
호스트에 알리는 흐름을 정의합니다.

## 변경 이력

| 날짜 | 구분 | 변경 내용 |
| --- | --- | --- |
| 2026-09-28 | 신규 작성 | 문서 불러오기, 변경 적용, 검증과 변경 이벤트 흐름을 정의했습니다. |

## 호출 조건

호스트가 `src`를 설정하거나 사용자가 도구 모음, 캔버스와 속성 패널에서 양식을 편집할 때 실행합니다.

## 입력·출력

| 구분 | 항목 | 자료형·단위 | 필수 여부·기본값 | 제약과 보장 |
| --- | --- | --- | --- | --- |
| 입력 | 편집 원본 | 양식 `.slip` 문자열 또는 `SlipTemplateFile` | 세션 시작에 필수 | 전표와 손상 파일은 편집 상태로 만들지 않습니다. |
| 입력 | 편집 명령 | 페이지·요소·설정 변경 명령 | 사용자 동작마다 선택 | 현재 문서의 대상을 지정하고 한 명령으로 완결됩니다. |
| 출력 | 현재 양식 | `SlipTemplateFile` | 유효한 변경 뒤 | 입력과 이전 상태를 바꾸지 않은 새 객체입니다. |
| 출력 | 변경 알림 | `slip-change` 이벤트 | 문서가 실제로 바뀐 때 한 번 | 전체 검증을 통과한 양식을 `detail.file`에 담습니다. |

## 사전·사후 조건

새 파일을 불러오면 선택, 대화상자, 미리보기, 저장 대상과 실행 취소 기록을 새 문서 기준으로
초기화합니다. 한 사용자 명령은 하나의 문서 변경으로 처리합니다.

## 정상 처리 흐름

```mermaid
flowchart LR
    Command[편집 명령] --> Snapshot[변경 전 상태 기록]
    Snapshot --> Patch[새 양식 생성]
    Patch --> Validate[전체 검증]
    Validate --> Event[화면 갱신과 slip-change]
```

| 순서 | 처리 | 읽는 값 | 만드는 값·변경하는 값 | 다음 단계 |
| --- | --- | --- | --- | --- |
| 1 | 한 사용자 명령이 시작되면 변경 전 양식과 선택을 기록합니다. | 현재 양식과 선택 | 실행 취소 후보 | 복사본 변경 |
| 2 | 원본을 직접 바꾸지 않고 명령 대상만 반영한 새 양식을 만듭니다. | 현재 양식, 편집 명령 | 양식 후보 | 전체 검증 |
| 3 | 구조, 참조, 범위와 자원 규칙을 전체 양식에서 검사합니다. | 양식 후보 | 검증된 양식 또는 오류 | 상태 반영 |
| 4 | 성공 결과만 현재 양식과 화면에 적용하고 변경 결과를 한 번 알립니다. | 검증된 양식 | 새 편집 상태와 실행 취소 기록 | 다음 명령 |

## 분기와 예외 흐름

발행 전표나 발행 전표 문자열은 편집 원본으로 받지 않습니다. 이미지 크기, 용지 범위, 중복 ID와 참조
무결성을 위반하는 변경은 적용하지 않고 해당 입력에 오류를 표시합니다.

## 데이터 조회·변경

디자이너 내부의 현재 양식을 교체하며 입력 객체를 직접 바꾸지 않습니다. 저장소 변경은 사용자가 저장
명령을 실행할 때만 발생합니다.

## 하위 기능과 시퀀스

패치·기하 계산, FNC-020 실행 취소, FNC-021 구조 편집과 FNC-001 검증을 조합합니다.

## 오류·복구

실패한 변경은 기록과 파일 상태에 남기지 않습니다. 입력 오류를 고치거나 실행 취소로 이전 상태를
복구할 수 있습니다.

## 동시 실행·반복 호출

사용자 편집 명령은 발생 순서대로 한 번씩 적용합니다. 새 양식을 여는 요청은 이전 양식의 미완료 비동기
결과를 무효로 만들며, 늦게 끝난 저장·미리보기 결과가 새 양식 상태를 덮지 못하게 합니다. 호스트가 같은
양식 객체를 다시 전달해도 입력 객체를 내부 편집 상태로 사용하거나 직접 수정하지 않습니다.

## 검증 기준

새 양식·문자열 불러오기, 페이지·요소 추가·수정·삭제, 잘못된 변경 거부, 이벤트 1회와 입력 불변성을
시험합니다.
