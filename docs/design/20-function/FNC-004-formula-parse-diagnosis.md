# FNC-004 수식 파싱과 진단

최종 갱신: 2026-09-28

## 개요

SlipKit 수식 문자열을 자체 구문 트리로 바꾸고, 문법·인자 수·현재 값에 따른 계산 가능 여부를
진단하는 흐름을 정의합니다. JavaScript 표현식은 실행하지 않습니다.

## 변경 이력

| 날짜 | 구분 | 변경 내용 |
| --- | --- | --- |
| 2026-09-28 | 신규 작성 | 수식 파싱, 깊이 제한, 인자 수 검사와 진단 결과를 정의했습니다. |

## 호출 조건

수식 저장 전 검사, 디자이너 경고, 조건부 서식과 렌더링 계산 전에 사용합니다. 공백만 있는 수식은
호출 화면과 PDF에서 빈 값으로 처리하며, 파서에 직접 전달하면 빈 수식 문법 오류가 납니다.

## 입력·출력

| 구분 | 항목 | 조건 |
| --- | --- | --- |
| 입력 | 수식 문자열 | 숫자·문자열·논리값·함수·연산자·`$(키)`·예약 참조를 허용합니다. |
| 출력 | `FormulaAst` 또는 `FormulaDiagnosis` | 진단은 성공 값이나 오류 종류와 데이터 의존 여부를 반환합니다. |

## 사전·사후 조건

참조 키는 `$(...)`로 감싸며 `)`와 역슬래시는 이스케이프합니다. 구문 트리 깊이는 100을 넘지
않습니다. 함수 이름과 인자 수는 공개 함수 목록을 기준으로 검사합니다.

## 정상 처리 흐름

```mermaid
flowchart LR
    Source[수식 문자열] --> Token[토큰 분리]
    Token --> Ast[구문 트리 생성]
    Ast --> Arity[함수 인자 수 검사]
    Arity --> Diagnose[값 문맥 진단]
```

## 분기와 예외 흐름

닫히지 않은 문자열·참조, 알 수 없는 문자·함수, 잘못된 인자 수와 깊이 초과는
`FormulaSyntaxError`입니다. 진단은 데이터가 채워지면 해소될 오류와 수식 자체 오류를 구분하지만,
수식 자체 오류를 정상 결과로 바꾸지는 않습니다.

## 데이터 조회·변경

진단은 전달받은 값과 예약 참조만 읽습니다. 원본 문자열, 값 객체와 양식은 바꾸지 않습니다.

## 하위 기능과 시퀀스

토큰화, 재귀 하강 파싱, 인자 수 검사 뒤 FNC-005 평가기를 사용합니다.

## 오류·복구

오류에는 가능한 위치를 포함합니다. 편집 화면은 사용자가 원문을 고칠 수 있게 유지하며, 저장이나
렌더링 단계가 임의로 수식을 고치지 않습니다.

## 검증 기준

모든 연산자와 함수, 유니코드 키, 예약 참조, 이스케이프, 공백 수식, 깊이·인자 수 제한과 로케일별
오류를 시험합니다.
