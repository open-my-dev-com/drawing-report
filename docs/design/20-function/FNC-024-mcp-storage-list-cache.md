# FNC-024 MCP 파일 접근과 목록 캐시

최종 갱신: 2026-09-28

## 개요

MCP 작업 디렉터리 안에서 안전한 `.slip` 경로를 읽고 쓰며, 목록 조회의 메타데이터 분석 결과를 파일
상태에 맞춰 재사용하는 흐름을 정의합니다.

## 변경 이력

| 날짜 | 구분 | 변경 내용 |
| --- | --- | --- |
| 2026-09-28 | 신규 작성 | 경로 경계, 원자적 저장, 경로별 큐와 목록 캐시 계약을 정의했습니다. |

## 호출 조건

MCP의 목록·읽기·저장·수정·전표 생성·PDF 도구가 파일 시스템에 접근할 때 사용합니다.

## 입력·출력

| 구분 | 항목 | 자료형·단위 | 필수 여부·기본값 | 제약과 보장 |
| --- | --- | --- | --- | --- |
| 입력 | 파일 ID | 작업 루트 기준 문자열 | 파일 작업에 필수 | 정규화한 실제 경로가 작업 루트를 벗어나지 않아야 합니다. |
| 입력 | 목록 필터·커서 | 종류·검색어·오프셋 커서 | 선택·전체 첫 페이지 | 정렬된 후보에서 다음 일치 항목 존재 여부까지만 평가합니다. |
| 입력 | 암호화 키 구성 | 현재·이전 키 | 선택·평문 | 캐시 인스턴스 경계에 포함하고 키 자체는 보관하지 않습니다. |
| 출력 | 파일·목록 | 검증된 `SlipFile` 또는 최대 50개 목록 | 성공 시 | 목록은 본문 없이 다음 커서를 포함할 수 있습니다. |

## 사전·사후 조건

심볼릭 링크를 파일로 따르지 않습니다. 같은 경로의 변경은 차례대로 처리하고 서로 다른 경로는 병렬로
처리합니다. 저장은 임시 파일 뒤 원자적 교체를 사용합니다.

## 정상 처리 흐름

```mermaid
flowchart LR
    Names[이름 탐색] --> Stat[최대 32개 lstat]
    Stat --> Cache{상태 식별값 일치}
    Cache -->|예| Reuse[메타데이터 재사용]
    Cache -->|아니요| Parse[본문 읽기·복호화·파싱]
    Parse --> Page[필터·커서 페이지]
    Reuse --> Page
```

| 순서 | 처리 | 읽는 값 | 만드는 값·변경하는 값 | 다음 단계 |
| --- | --- | --- | --- | --- |
| 1 | 호출마다 작업 디렉터리의 후보 파일 이름을 다시 읽고 정렬합니다. | 작업 디렉터리 | 정렬한 후보 경로 | 상태 조회 |
| 2 | 후보마다 최대 32개씩 파일 상태와 심볼릭 링크 여부를 조회합니다. | 후보 경로 | 파일 상태 식별값 또는 제외 결과 | 캐시 비교 |
| 3 | 경로와 상태 식별값이 같으면 저장한 메타데이터 또는 제외 결과를 재사용합니다. | 인스턴스 캐시 | 후보 메타데이터 | 필터·페이지 처리 |
| 4 | 일치하지 않으면 본문을 읽고 복호화·파싱해 메타데이터를 새로 저장합니다. | 파일 본문, 키 설정 | 새 메타데이터 또는 제외 결과 | 필터·페이지 처리 |
| 5 | 정렬 순서대로 조건에 맞는 `offset + 51`번째 항목까지만 평가합니다. | 후보 메타데이터, 필터, 커서 | 최대 50개 결과와 다음 커서 | 반환 |

## 분기와 예외 흐름

캐시는 경로와 `dev·ino·size·mtimeNs·ctimeNs·mode`를 함께 비교합니다. 손상·미지원 파일의 제외 결과도
재사용합니다. 저장·삭제·외부 교체·이름 변경과 키 구성 변화는 다음 조회에서 정확히 무효화됩니다.

## 데이터 조회·변경

캐시는 `FileSystemStorage` 인스턴스 안에만 있고 전체 본문·평문·키를 보관하지 않습니다. 디스크
sidecar, `fs.watch`와 전역 캐시는 사용하지 않습니다.

## 하위 기능과 시퀀스

`PathQueue`, `statCandidates()`, `ListMetadataCache`와 저장소 직렬화가 협력합니다. 같은 파일을 동시에
분석하면 진행 중인 Promise를 공유합니다.

## 오류·복구

파일 하나의 조회 실패는 목록에서 제외할 수 있지만 경로 경계 위반과 저장 실패는 작업 오류로
알립니다. 실패한 저장은 기존 파일과 캐시 결과를 훼손하지 않습니다.

## 동시 실행·반복 호출

같은 경로의 저장·삭제는 경로별 큐에서 호출 순서대로 실행합니다. 같은 파일의 본문 분석이 겹치면
진행 중인 Promise를 공유하고 완료 뒤 지문이 같은 요청만 결과를 재사용합니다. 목록 호출마다 이름과
상태를 다시 조사하며 `lstat` 동시 실행 수는 32를 넘지 않습니다.

## 검증 기준

경로 탈출·심볼릭 링크, 동시 저장, cold·warm 목록, 외부 생성·수정·교체·삭제·이름 변경, 같은 크기와
복원 mtime, 키 격리, 최대 동시 `lstat` 32와 전체 커서 진행을 시험합니다.
