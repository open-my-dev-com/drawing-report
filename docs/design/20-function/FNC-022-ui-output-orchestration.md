# FNC-022 미리보기·작성·보기 출력 조정

최종 갱신: 2026-09-28

## 개요

디자이너, 작성 폼과 뷰어가 같은 SlipKit 설정으로 PDF를 만들고 비동기 결과와 임시 URL을 안전하게
교체하는 흐름을 정의합니다.

## 변경 이력

| 날짜 | 구분 | 변경 내용 |
| --- | --- | --- |
| 2026-09-28 | 신규 작성 | 세 UI의 출력 입력, 비동기 경합 방지와 URL 정리를 정의했습니다. |

## 호출 조건

미리보기 진입, 양식·값·전표·로케일·SlipKit 변경과 컴포넌트 연결 해제 시 실행합니다.

## 입력·출력

| 구분 | 항목 | 자료형·단위 | 필수 여부·기본값 | 제약과 보장 |
| --- | --- | --- | --- | --- |
| 입력 | 출력 파일 | 현재 양식 또는 전표 | 필수 | 작성 폼은 현재 값으로 미발행 전표를 먼저 만듭니다. |
| 입력 | 렌더 설정 | SlipKit·로케일·폰트 | 선택·요소 기본값 | 한 요청 동안 같은 설정을 사용합니다. |
| 입력 | 요청 세대 | 증가하는 정수 | 내부 필수 | 최신 결과인지 판정하는 데 사용합니다. |
| 출력 | PDF 화면 상태 | 로딩·성공·오류와 Blob URL | 요청 완료 시 | 최신 세대만 표시하고 이전 URL은 해제합니다. |

## 사전·사후 조건

가장 최근 렌더링 요청만 화면을 바꿀 수 있습니다. 이전 URL은 새 결과를 적용하기 전 또는 연결 해제
시에 해제합니다.

## 정상 처리 흐름

```mermaid
flowchart LR
    Change[출력 입력 변경] --> Generation[요청 세대 증가]
    Generation --> Render[PDF 비동기 생성]
    Render --> Current{최신 요청인가}
    Current -->|예| Url[기존 URL 해제 후 교체]
    Current -->|아니요| Drop[결과 폐기]
```

| 순서 | 처리 | 읽는 값 | 만드는 값·변경하는 값 | 다음 단계 |
| --- | --- | --- | --- | --- |
| 1 | 출력 입력이 바뀌면 요청 세대를 올리고 로딩 상태를 표시합니다. | 현재 입력과 세대 | 새 세대와 로딩 상태 | PDF 생성 |
| 2 | 시작 시점의 파일, 로케일과 글꼴 설정으로 PDF를 비동기 생성합니다. | 출력 입력 스냅샷 | PDF 바이트 또는 오류 | 최신 여부 확인 |
| 3 | 완료한 요청의 세대와 현재 세대를 비교합니다. | 완료 결과, 현재 세대 | 적용 또는 폐기 판정 | 결과 처리 |
| 4 | 최신 성공이면 기존 주소를 해제하고 새 PDF 주소로 바꿉니다. | 최신 PDF 바이트 | 성공 화면과 새 주소 | 종료 |
| 5 | 오래된 성공은 만든 주소를 즉시 해제하고, 오래된 오류는 표시하지 않습니다. | 오래된 결과 | 정리된 임시 자원 | 종료 |

## 분기와 예외 흐름

디자이너는 미리보기 모드에서만 렌더링합니다. 작성 폼은 빈 값·검증 오류를 입력 화면에 남기며,
뷰어는 읽기 전용 전표만 표시합니다. 렌더 실패는 현재 로케일의 오류 상태로 표시합니다.

## 데이터 조회·변경

현재 UI 상태만 읽고 임시 Blob URL을 관리합니다. 원본 파일과 호스트 저장소는 바꾸지 않습니다.

## 하위 기능과 시퀀스

FNC-003 전표 조립, FNC-013 PDF 생성과 FNC-014 폰트 결정을 사용합니다.

## 오류·복구

오래된 Promise의 성공·실패가 최신 화면을 덮지 못하게 세대 번호를 확인합니다. 입력을 고치거나 설정이
바뀌면 다시 렌더링합니다.

## 동시 실행·반복 호출

출력 입력이 바뀔 때마다 세대 번호를 올립니다. 완료된 결과는 시작 당시 세대가 현재 세대와 같을 때만
표시하며, 오래된 성공 결과의 Blob URL은 즉시 해제하고 오래된 오류는 표시하지 않습니다. 같은 세대에서
중복 렌더 요청을 만들지 않습니다.

## 검증 기준

세 컴포넌트의 로딩·성공·실패, 빠른 연속 변경, 연결 해제, URL 해제, 호스트·기본 폰트와 로케일을
실제 Chromium에서 시험합니다.
