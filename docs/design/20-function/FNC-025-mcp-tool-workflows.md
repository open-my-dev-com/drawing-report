# FNC-025 MCP 읽기·수정·전표·PDF 도구

최종 갱신: 2026-09-28

## 개요

AI 클라이언트가 스키마를 확인하고 `.slip` 파일을 요약 읽기, 저장·부분 수정, 전표 조립과 PDF
미리보기까지 수행하는 도구 흐름을 정의합니다.

## 변경 이력

| 날짜 | 구분 | 변경 내용 |
| --- | --- | --- |
| 2026-09-28 | 신규 작성 | 일곱 도구의 권장 순서, 변경 안전장치와 결과 축약을 정의했습니다. |

## 호출 조건

MCP 클라이언트가 `slip_schema`, `slip_list`, `slip_read`, `slip_save`, `slip_edit`,
`slip_build_voucher`, `slip_render_pdf`를 호출할 때 적용합니다.

## 입력·출력

| 구분 | 항목 | 자료형·단위 | 필수 여부·기본값 | 제약과 보장 |
| --- | --- | --- | --- | --- |
| 입력 | 도구 요청 | 도구별 Zod 객체 | 필수 | 파일 ID, 읽기 범위, 저장 옵션과 편집 연산을 명시합니다. |
| 입력 | 현재 저장소 상태 | 검증된 파일·목록 | 도구에 따라 조회 | 호출 시점의 파일을 기준으로 처리합니다. |
| 출력 | 도구 결과 | 텍스트·구조 데이터·선택적 PNG | 성공 또는 오류 한 번 | 실제 이미지 data URL만 본문 대신 형식·크기 표기로 줄입니다. |

## 사전·사후 조건

새 양식은 스키마 확인 뒤 전체 파일로 한 번 저장하고, 기존 파일은 요약 읽기 뒤 필요한 부분만 읽어
`slip_edit`로 바꿉니다. 발행 전표는 생성·교체·수정하지 않습니다.

## 정상 처리 흐름

```mermaid
flowchart LR
    Schema[스키마 확인] --> Read[요약과 대상 읽기]
    Read --> Edit[부분 수정 또는 신규 저장]
    Edit --> Voucher[필요하면 전표 조립]
    Voucher --> Pdf[PDF와 선택적 PNG 미리보기]
```

| 순서 | 처리 | 읽는 값 | 만드는 값·변경하는 값 | 다음 단계 |
| --- | --- | --- | --- | --- |
| 1 | 새 파일이면 필요한 스키마 주제를, 기존 파일이면 목록과 요약을 먼저 읽습니다. | 도구 요청, 현재 저장소 | 작업 대상과 구조 정보 | 상세 읽기 또는 저장 |
| 2 | 기존 파일은 바꿀 페이지·요소만 읽고 새 파일은 완성된 전체 구조를 준비합니다. | 구조 정보 | 편집 연산 또는 새 파일 | 변경 실행 |
| 3 | 전체 저장이나 순서 있는 부분 편집을 검증하고 원자적으로 저장합니다. | 파일 또는 편집 연산 | 저장된 양식 요약 | 전표 또는 PDF 선택 |
| 4 | 값이 필요하면 저장된 양식에서 미발행 전표를 만들어 별도 ID로 저장합니다. | 양식 ID, 값 | 미발행 전표 요약 | PDF 선택 |
| 5 | 선택한 양식·전표를 PDF로 만들고 요청한 경우 지정 페이지의 PNG도 반환합니다. | 파일 ID, 출력 경로, 페이지 | PDF 경로·링크와 선택적 PNG | 종료 |

## 분기와 예외 흐름

`slip_save`는 기존 파일 덮어쓰기를 명시해야 하며, 기존 변경에는 부분 편집을 권장합니다. 편집 연산은
입력 순서대로 하나의 경로 큐에서 적용하고 매 단계 뒤 전체 파일을 검증합니다. PDF는 기존 PDF만
교체하며 미리보기 페이지 범위를 검사합니다.

## 데이터 조회·변경

읽기 범위는 summary·element·page·full로 나눕니다. 일반 문자열과 값은 보존하고 실제 Base64 데이터
URL만 본문 대신 크기 표기로 반환합니다. 고정 이미지는 로컬 파일 경로로 설정합니다.

## 하위 기능과 시퀀스

FNC-001·FNC-003·FNC-013·FNC-024와 편집 연산기를 사용합니다. PDF 링크 서버는 지정 포트를 열 수
없을 때 허용된 범위에서 다음 포트를 시도합니다.

## 오류·복구

대상 없음, 중복 ID, 잘못된 연산·이미지·경로와 불변 전표를 `McpToolError`로 설명합니다. 실패한
연산 묶음은 저장하지 않으며 요약을 다시 읽어 최신 ID를 확인할 수 있습니다.

## 동시 실행·반복 호출

같은 파일에 대한 변경 도구는 FNC-024의 경로별 큐에서 순서대로 실행합니다. 한 편집 요청 안의 연산은
입력 순서를 지키며 하나라도 실패하면 전체 결과를 저장하지 않습니다. 읽기와 PDF 생성은 호출 시점의
검증된 파일을 사용하고, 나중에 끝난 요청이 먼저 끝난 요청의 반환값을 바꾸지 않습니다.

## 검증 기준

일곱 도구의 정상·오류 입력, 부분 읽기, 일반 `data:` 문자열 보존, 이미지 축약, 연산 순서·원자성,
불변 전표, PDF 교체·미리보기와 링크 포트 대체를 시험합니다.
