# FNC-013 PDF 변환과 렌더링

최종 갱신: 2026-09-28

## 개요

검증된 양식 또는 전표를 출력 페이지 계획과 pdfme 스키마로 바꾸고 PDF 바이트를 만드는 전체 흐름을
정의합니다.

## 변경 이력

| 날짜 | 구분 | 변경 내용 |
| --- | --- | --- |
| 2026-09-28 | 신규 작성 | 페이지 계획, 요소 변환, 폰트 조회와 PDF 생성 순서를 정의했습니다. |

## 호출 조건

`renderSlipToPdf()`, `createPdfRenderer()` 또는 `SlipKit.render()`가 양식·전표를 출력할 때 호출합니다.

## 입력·출력

| 구분 | 항목 | 자료형·단위 | 필수 여부·기본값 | 제약과 보장 |
| --- | --- | --- | --- | --- |
| 입력 | 양식 또는 전표 | 검증된 `SlipFile` | 필수 | 현재 스키마이며 발행 이미지 규칙을 따라야 합니다. |
| 입력 | 렌더 설정 | `RenderOptions` | 선택·기본 로케일과 폰트 | 폰트 제공 함수는 Promise를 반환할 수 있습니다. |
| 출력 | PDF | `Uint8Array` 바이트 | 성공 시 반환 | PDF 서명과 계획한 모든 출력 페이지를 포함합니다. |

## 사전·사후 조건

양식은 샘플 값, 전표는 스냅샷과 실제 값을 사용합니다. 같은 입력·폰트·기준 시각은 화면과 같은 내용과
페이지 구성을 만들어야 합니다.

## 정상 처리 흐름

```mermaid
flowchart LR
    File[양식 또는 전표] --> Fonts[폰트 조회]
    Fonts --> Plan[출력 페이지 계획]
    Plan --> Convert[pdfme 스키마 변환]
    Convert --> Generate[PDF 생성]
    Generate --> Bytes[PDF 바이트]
```

| 순서 | 처리 | 읽는 값 | 만드는 값·변경하는 값 | 다음 단계 |
| --- | --- | --- | --- | --- |
| 1 | 입력 파일을 검증하고 양식 본문과 출력 값을 결정합니다. | 양식 또는 전표 | 렌더 입력 | 글꼴 조회 |
| 2 | 필요한 글꼴 이름과 변형을 모아 사용할 바이트를 준비합니다. | 렌더 입력, 글꼴 설정 | 글꼴 사전 | 페이지 계획 |
| 3 | 원본 페이지, 반복 그리드와 이어 배치 요소로 출력 페이지 계획을 만듭니다. | 양식 본문, 출력 값 | 출력 페이지 계획 | 스키마 변환 |
| 4 | 각 출력 조각을 글자, 이미지, 바코드와 도형 출력 명령으로 바꿉니다. | 페이지 계획, 자원 | PDF 생성 스키마 | PDF 생성 |
| 5 | PDF 엔진을 실행하고 완성된 바이트 배열만 반환합니다. | 생성 스키마, 글꼴 사전 | PDF 바이트 | 반환 |

## 분기와 예외 흐름

요소 종류별로 글자·수식·그리드·이미지·도형·선·바코드를 변환합니다. 공백 수식은 빈 값으로
표시합니다. 페이지 계획, 글자, 이미지, 바코드와 PDF 생성 실패는 원인을 포함한 `SlipLayoutError`
또는 `SlipRenderError`입니다.

## 데이터 조회·변경

입력 파일은 바꾸지 않습니다. 렌더 인스턴스는 폰트 조회 Promise를 재사용하고, 변환 한 번 동안
그리드 항목과 이미지 검사 결과를 캐시합니다.

## 하위 기능과 시퀀스

FNC-002·FNC-005, FNC-007~FNC-012와 FNC-014를 사용한 뒤 pdfme 생성기를 호출합니다.

## 오류·복구

일부 페이지만 반환하지 않습니다. 실패 원인을 고친 뒤 전체 PDF를 다시 생성합니다.

## 동시 실행·반복 호출

렌더러 인스턴스는 같은 폰트 제공 호출의 진행 중인 Promise와 성공 결과를 공유할 수 있습니다. PDF
변환의 페이지 계획, 이미지 검사와 그리드 자료는 호출별로 격리합니다. 같은 파일을 동시에 렌더링해도
입력 객체와 다른 호출의 중간 상태를 바꾸지 않으며 각 호출은 완전한 PDF 또는 오류 하나로 끝납니다.

## 검증 기준

모든 요소 종류, 다중 페이지·반복 그리드, 양식·전표, 세 로케일과 폰트, Node.js·Chromium 결과,
PDF 서명과 페이지 수를 시험합니다.
