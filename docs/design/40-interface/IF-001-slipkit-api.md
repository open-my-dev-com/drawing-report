# IF-001 `createSlipKit`과 `SlipKit`

최종 갱신: 2026-09-28

## 개요

폰트, 로케일과 암호화 키를 한 인스턴스에서 공유하는 Core 표준 진입점의 입력·출력과 오류 계약을
정의합니다.

## 변경 이력

| 날짜 | 구분 | 변경 내용 |
| --- | --- | --- |
| 2026-09-28 | 신규 작성 | `createSlipKit` 설정과 `SlipKit` 메서드의 생명주기를 정의했습니다. |

## 제공자와 소비자

`@omdc-slipkit/core`가 제공하고 브라우저·Node.js 호스트, UI 구성 요소와 MCP 서버가 소비합니다.
인스턴스는 애플리케이션이나 작업 단위로 만들어 같은 설정이 필요한 소비자에게 전달합니다.

## 호출 방향과 사용 조건

호스트가 설정을 전달해 인스턴스를 한 번 만들고, UI 구성 요소와 MCP는 같은 인스턴스의 메서드를
호출합니다. 생성 뒤 로케일·키·폰트 제공 함수를 바꾸지 않으며 다른 설정이 필요하면 새 인스턴스를
만듭니다.

## 생성 계약

```ts
createSlipKit(config?: {
  getFonts?: () => readonly SlipFont[] | Promise<readonly SlipFont[]>;
  locale?: string;
  encryption?: { key: string | Uint8Array; previousKeys?: (string | Uint8Array)[] };
}): SlipKit
```

원시 키는 생성 시 32바이트인지 검사합니다. 폰트 제공 함수의 최초 성공 결과는 인스턴스 안에서
공유하며 실패하면 다음 호출에서 다시 시도합니다.

## 메서드 계약

| 메서드 | 입력 | 출력·효과 |
| --- | --- | --- |
| `render` | 검증된 양식 또는 전표 | 설정한 폰트와 로케일로 만든 PDF 바이트 |
| `buildVoucher` | 양식과 값 객체 | 깊은 복사된 `issued: false` 전표 |
| `evaluate` | 수식 문자열·AST와 평가 문맥 | 엄격한 타입 규칙을 적용한 수식 값 |
| `encrypt` | `.slip` 파일과 선택적 호출 키 | 암호화 봉투 JSON 문자열 |
| `decrypt` | 암호화 봉투와 선택적 호출 키 | 복호화하고 검증한 `.slip` 파일 |

호출 키는 인스턴스 키보다 우선합니다. 키를 생략한 복호화는 현재 키와 이전 키를 순서대로 시도하며
키 불일치가 아닌 오류는 즉시 반환합니다.

## 동기·비동기 처리

`buildVoucher`와 `evaluate`는 동기 함수입니다. 폰트, 암호화와 PDF 처리가 포함된 `render`,
`encrypt`, `decrypt`는 Promise를 반환합니다. 인스턴스는 내부 설정을 바꾸는 메서드를 제공하지
않으므로 설정 변경은 새 인스턴스로 처리합니다.

## 생명주기

인스턴스는 별도 종료 메서드가 없습니다. 호스트가 참조를 버리면 폰트 Promise와 키 설정도 함께 수거할
수 있어야 합니다. 반환한 PDF와 암호화 문자열의 보관 기간은 호출자가 정합니다.

## 반복 호출·동시 호출

`render` 동시 호출은 폰트 조회의 진행 중인 Promise와 성공 결과만 공유하고 페이지 계획과 이미지
검사는 호출별로 격리합니다. 실패한 폰트 조회는 캐시하지 않습니다. `buildVoucher`, `evaluate`,
`encrypt`, `decrypt`는 입력 객체를 바꾸지 않으며 각 호출 결과가 다른 호출 상태를 덮지 않습니다.

## 오류 처리

수식, 렌더링, 암호화와 파일 파싱 오류는 각 공개 오류 클래스로 전달합니다. 암호화 키가 없거나
형식이 잘못되면 작업을 시작하지 않습니다. 호출자는 사용자 대면 문구를 만들 때 오류 종류와
인스턴스 로케일을 사용합니다.

## 호환성·보안·확장 경계

`SlipKit` 인스턴스와 공개 타입만 계약입니다. 인스턴스의 렌더러, 폰트 Promise와 키 순회 방식은
내부 구현입니다. 키 값과 폰트 바이트를 직렬화하거나 로그에 기록하지 않습니다.
