# IF-004 Web Component 공통 설정과 이벤트

최종 갱신: 2026-09-28

## 개요

`<slip-designer>`, `<slip-form>`, `<slip-viewer>`가 공유하는 입력, 설정, 이벤트와 호스트 상태 관리
원칙을 정의합니다.

## 변경 이력

| 날짜 | 구분 | 변경 내용 |
| --- | --- | --- |
| 2026-09-28 | 신규 작성 | Web Component의 `src`, 로케일, SlipKit 인스턴스와 이벤트 계약을 정의했습니다. |

## 제공자와 소비자

`@omdc-slipkit/elements`가 세 사용자 정의 요소를 제공하고 브라우저 호스트 또는 React·Vue 래퍼가
프로퍼티를 설정하고 이벤트를 구독합니다. 요소 내부 상태는 호스트가 직접 수정하지 않습니다.

## 호출 방향과 사용 조건

호스트는 요소를 문서에 연결한 뒤 프로퍼티로 객체 설정을 전달합니다. 문자열 HTML 속성은 단순 문자열
입력에만 사용하고 SlipKit 인스턴스와 저장소 같은 객체는 JavaScript 프로퍼티로 전달합니다.

## 입력·출력 또는 이벤트 계약

| 이름 | 방향 | 호출·발생 시점 | 입력·상세 자료형 | 반환·전달값 | 생략·오류 처리 |
| --- | --- | --- | --- | --- | --- |
| `src` | 호스트→요소 | 최초 연결 또는 표시할 파일 변경 | 양식 또는 전표를 직렬화한 `.slip` JSON 문자열 | 새 편집·작성·조회 세션 | 생략하면 빈 상태를 표시하고, 손상 파일이면 오류 상태를 표시 |
| `locale` | 호스트→요소 | 연결 전후의 화면 언어 변경 | 로케일 문자열 | 해당 언어의 UI 문구 | 생략하면 `slipkit.locale`, 둘 다 없으면 요소 기본 로케일 사용 |
| `slipkit` | 호스트→요소 | 연결 전후의 렌더 설정 변경 | `SlipKit` 인스턴스 | 폰트·수식·PDF·암호화 설정 공유 | 생략하면 요소가 만든 기본 인스턴스 사용 |
| 디자이너 변경 | 요소→호스트 | 유효한 양식 변경을 확정한 직후 | 없음 | `detail.file`에 전체 `SlipTemplateFile`을 담은 `slip-change` | 선택만 바뀌거나 편집이 실패하면 발생하지 않음 |
| 작성 값 변경 | 요소→호스트 | 유효한 전표 값 변경을 확정한 직후 | 없음 | `detail.file`에 미발행 `SlipVoucherFile`을 담은 `slip-change` | 읽기 전용 전표이거나 값 검증이 실패하면 발생하지 않음 |
| 전표 발행 | 요소→호스트 | 발행 검증과 상태 변경이 끝난 직후 | 없음 | `detail.file`에 발행 `SlipVoucherFile`을 담은 `slip-issue` | 발행 검증이 실패하면 발생하지 않음 |

`src`는 새 편집·작성·조회 세션을 시작하는 입력입니다. 구성 요소의 변경 이벤트를 받을 때마다 같은
요소의 `src`에 즉시 되돌려 쓰면 선택, 실행 취소와 발행 상태가 초기화될 수 있습니다. 호스트는 최초
입력과 최신 결과 상태를 분리합니다.

이벤트는 Shadow DOM 밖으로 전달되도록 `bubbles: true`, `composed: true`로 발생합니다.
뷰어는 파일을 바꾸는 이벤트를 발생시키지 않습니다.

## 로케일과 렌더링 설정

UI 언어는 구성 요소 `locale`이 우선하고, 수식·PDF 로케일은 SlipKit 인스턴스가 있으면 인스턴스
설정을 따릅니다. `getFonts`가 없으면 UI 패키지의 동봉 기본 폰트를 사용합니다. 설정 조회가 비동기일
때 늦게 끝난 이전 요청이 최신 설정을 덮지 않도록 요청 세대를 구분합니다.

## 동기·비동기 처리

프로퍼티 반영과 사용자 입력 이벤트는 브라우저 작업 순서대로 처리합니다. 파일 읽기, 설정 조회와 PDF
렌더링은 Promise로 수행하며 최신 요청만 화면과 이벤트 상태를 바꿀 수 있습니다.

## 생명주기

요소 연결 시 `src`를 파싱하고 내부 상태를 만듭니다. `src` 또는 핵심 설정이 바뀌면 관련 상태와
미리보기를 갱신합니다. Blob URL, 비동기 미리보기와 이벤트 리스너는 연결 해제나 새 요청 때
정리합니다.

## 반복 호출·동시 호출

새 `src`나 핵심 설정을 받으면 요청 세대를 올리고 이전 비동기 결과를 폐기합니다. 같은 이벤트 결과를
즉시 `src`로 되돌려 쓰지 않습니다. 이벤트 리스너는 연결마다 한 번 등록하고 해제 시 제거하여 재연결
뒤 중복 이벤트가 발생하지 않게 합니다.

## 오류 처리

파싱·렌더링 실패는 구성 요소 안의 로케일화된 상태로 표시하며 잘못된 파일을 성공 이벤트로 내보내지
않습니다. 호스트가 정한 `role`, `aria-*`, `tabIndex` 같은 표준 속성은 래퍼를 거쳐 호스트 요소에
전달할 수 있습니다.

입력 오류는 성공 이벤트를 발생시키지 않고, 렌더링 오류는 값과 문서를 보존한 채 해당 결과 영역에
표시합니다. 키보드 초점과 접근 가능한 이름은 오류 표시 뒤에도 유지합니다.

## 호환성·보안·확장 경계

공개 프로퍼티, 이벤트 이름, 이벤트 전파와 `detail.file` 구조는 호환 계약입니다. Shadow DOM 내부
마크업과 CSS 클래스는 계약이 아닙니다. 외부 JSON, 이미지와 폰트 설정은 신뢰하지 않고 Core 검증을
통과한 결과만 화면 상태로 사용합니다.
