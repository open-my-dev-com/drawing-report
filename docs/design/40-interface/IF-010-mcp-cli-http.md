# IF-010 MCP CLI·설정과 PDF 링크

최종 갱신: 2026-09-28

## 개요

`slipkit-mcp` 명령의 인자·환경변수·설정 우선순위와 로컬 PDF 링크 서버의 네트워크 경계를
정의합니다.

## 변경 이력

| 날짜 | 구분 | 변경 내용 |
| --- | --- | --- |
| 2026-09-28 | 신규 작성 | CLI 실행, 설정 해석, 종료 코드와 PDF 링크 서버 계약을 정의했습니다. |

## 제공자와 소비자

MCP 패키지가 `slipkit-mcp` 실행 파일, 서버 생성 함수와 로컬 PDF 링크를 제공합니다. 셸·편집기와 MCP
클라이언트가 프로세스를 시작하고, 브라우저 또는 클라이언트가 발급된 PDF 링크를 엽니다.

## 호출 방향과 사용 조건

호스트가 명령줄 인자와 환경변수를 정한 뒤 프로세스를 시작합니다. 설정 검증이 끝난 경우에만 stdio
전송과 선택적 PDF 링크 서버를 엽니다. PDF 링크는 같은 기기에서 짧게 확인하는 용도로만 사용합니다.

## CLI 입력

```text
slipkit-mcp [working-directory] [--config path] [--locale locale]
```

`--help`와 `--version`은 설정이나 서버를 읽지 않고 종료합니다. 모르는 옵션, 누락된 옵션 값과 두 개
이상의 위치 인자는 사용법 오류입니다.

| 결과 | 종료 코드 |
| --- | ---: |
| 정상 종료·도움말·버전 | 0 |
| 서버 시작 또는 실행 오류 | 1 |
| 명령줄 사용법 오류 | 2 |

## 설정 우선순위

설정 파일 위치는 `--config`, `SLIPKIT_MCP_CONFIG`, 작업 디렉터리의 `slipkit-mcp.json` 순서로
정합니다. 작업 디렉터리 위치 인자는 설정의 `rootDir`보다 우선하고, 로케일은 `--locale`,
`SLIPKIT_MCP_LOCALE`, 설정 파일 순서입니다.

키는 설정이 지정한 환경변수 또는 `SLIPKIT_MCP_KEY`, `SLIPKIT_MCP_PREVIOUS_KEYS`에서 읽습니다.
설정 파일에는 키 값을 저장하지 않습니다.

## stdio 서버

MCP 프로토콜은 표준 입출력을 사용합니다. 진단과 오류 로그가 프로토콜 출력을 오염시키지 않도록
구분합니다. 서버 생성과 전송 연결을 분리하여 공개 API 사용자는 `createSlipMcpServer()`로 같은 도구
구성을 다른 Node.js 진입점에 연결할 수 있습니다.

## PDF 링크 서버

서버는 `127.0.0.1`에만 바인딩하고 작업 디렉터리 안의 `.pdf`만 GET으로 제공합니다. 프로세스마다
32바이트 난수 토큰을 만들고 URL 첫 경로 조각으로 요구합니다. Host 헤더가 로컬호스트가 아니거나
토큰·확장자·실제 경로 검사가 실패하면 파일 존재를 드러내지 않고 거부합니다.

같은 포트가 사용 중이면 상태 경로로 SlipKit 서버와 작업 루트 해시를 확인합니다. 접근 토큰은
프로세스마다 다르므로 기존 서버를 재사용하지 않습니다. 호출자가 허용한 경우에만 같은 루트의 다른
프로세스와 충돌할 때 빈 포트로 새 서버를 시작합니다.

## 오류 처리

작업 루트, 설정 파일, 폰트와 키 설정을 서버 시작 전에 확인합니다. PDF 링크 응답은 `no-store`와
`nosniff` 헤더를 사용합니다. 링크 토큰은 권한 체계가 아니므로 외부 인터페이스에 바인딩하거나
장기 공유하지 않습니다.

## 동기·비동기 처리

인자와 설정 파일은 서버 연결 전에 순서대로 확인합니다. stdio 연결과 HTTP 서버 시작은 비동기이며 시작
실패 시 준비된 다른 자원을 닫고 종료 코드 1을 반환합니다. PDF 파일 읽기는 요청마다 완료한 파일만
응답합니다.

## 생명주기

프로세스 시작 때 설정, 저장소, MCP 서버와 선택적 HTTP 서버를 이 순서로 준비합니다. 정상 종료와 시작
실패 때 전송, HTTP 리스너와 파일 자원을 닫습니다. 접근 토큰은 프로세스마다 새로 만들고 종료 뒤
재사용하지 않습니다.

## 반복 호출·동시 호출

한 HTTP 서버는 여러 PDF GET을 처리할 수 있지만 각 경로를 요청마다 다시 검증합니다. 포트 충돌 검사로
발견한 기존 서버는 접근 토큰이 다르므로 합류하지 않습니다. 허용된 경우에만 다음 포트 후보로 새 서버를
시작합니다.

## 호환성·보안·확장 경계

명령줄 형식, 설정 우선순위, 종료 코드와 localhost 전용 링크 형식이 공개 계약입니다. 새 옵션은 기존
위치 인자와 우선순위를 바꾸지 않아야 합니다. HTTP 서버는 외부 인터페이스에 바인딩하지 않고 토큰,
Host, 확장자와 실제 경로 검사를 모두 통과한 PDF만 반환합니다.
