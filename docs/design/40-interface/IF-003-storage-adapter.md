# IF-003 `StorageAdapter`

최종 갱신: 2026-09-28

## 개요

SlipKit과 브라우저·서버·파일 시스템 저장 구현 사이의 비동기 CRUD·목록 계약을 정의합니다.

## 변경 이력

| 날짜 | 구분 | 변경 내용 |
| --- | --- | --- |
| 2026-09-28 | 신규 작성 | 저장, 조회, 삭제, 목록, 버전 이력과 오류 계약을 정의했습니다. |

## 제공자와 소비자

Core가 TypeScript 인터페이스와 오류 타입을 제공합니다. `IndexedDbStorage`, MCP
`FileSystemStorage`와 호스트 저장소 구현이 제공자이며 디자이너와 호스트 애플리케이션이 소비자입니다.

## 메서드 계약

| 메서드 | 입력 | 결과 |
| --- | --- | --- |
| `save(id, file)` | 저장 키와 검증된 파일 | 같은 ID가 있으면 덮어쓰고 완료를 기다립니다. |
| `load(id)` | 저장 키 | 파일 본문을 반환합니다. |
| `delete(id)` | 저장 키 | 대상 파일을 삭제합니다. |
| `list(filter?, cursor?)` | 종류·검색어와 이전 커서 | 최대 크기를 구현이 정한 목록 페이지를 반환합니다. |

목록 항목은 `id`, `kind`, `title`과 선택적인 `updatedAt`만 포함하며 본문을 포함하지 않습니다.
`nextCursor`는 저장소가 해석하는 불투명한 문자열입니다.

## 버전 이력

`VersionedStorageAdapter`는 `listVersions(id)`와 `loadVersion(id, version)`을 추가합니다.
`supportsVersions()`로 지원 여부를 확인합니다. 기본 디자이너 흐름은 버전 이력을 요구하지 않습니다.

## 오류 처리

`SlipStorageError.code`는 `not-found`, `unsupported`, `io`, `cancelled` 중 하나입니다. 구현은 사용자
취소를 입출력 실패와 구분하고, 지원하지 않는 기능을 성공처럼 처리하지 않습니다. 인증과 권한 오류를
이 네 범주에 매핑하는 정책은 호스트 구현이 정합니다.

## 동시성과 보안

인터페이스는 낙관적 잠금이나 트랜잭션을 규정하지 않습니다. 여러 사용자의 동시 수정, 인증, 감사,
백업과 보존은 저장소 구현의 책임입니다. 파일을 암호화해 저장하려면 같은 SlipKit 인스턴스의 키
설정을 적용하되 목록 메타데이터와 로그에 평문이나 키를 남기지 않습니다.
