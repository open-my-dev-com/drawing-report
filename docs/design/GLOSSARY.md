# SlipKit 설계 용어 해설

최종 갱신: 2026-09-28

## 개요

이 문서는 SlipKit 설계서에 반복해서 나오는 업무 용어와 기술 용어를 쉬운 말로 설명합니다. 소스 코드의
이름을 외우지 않아도 화면, 데이터와 처리 흐름을 이해할 수 있도록 작성했습니다.

용어의 뜻만으로 동작을 결정하지는 않습니다. 정확한 화면 배치, 처리 순서, 데이터 형식과 오류 복구
방법은 각 용어에 연결된 설계서에서 확인합니다.

## 문서 식별자

| 표기 | 뜻 | 문서에서 확인할 내용 |
| --- | --- | --- |
| `SYS` | 시스템 공통 설계 | 프로그램 구성, 실행 환경, 보안과 공통 제약 |
| `SCR` | 화면 설계 | 화면 배치, 표시 상태, 사용자 동작과 화면 전환 |
| `FNC` | 기능 설계 | 입력을 받아 결과를 만드는 처리 순서와 예외 흐름 |
| `DAT` | 데이터 설계 | 저장하는 값의 구조, 관계, 제약과 생명주기 |
| `IF` | 인터페이스 설계 | 다른 프로그램이나 구성 요소가 SlipKit을 호출하는 방법 |
| `ERR` | 오류 설계 | 오류를 판정하고 전달하며 복구하는 방법 |

`SCR-001`처럼 붙은 숫자는 문서를 구분하는 번호입니다. 화면 이미지 안의 숫자는 화면 영역이나 조작
항목을 가리키며 문서 번호와는 별개입니다.

## 제품과 문서

| 용어 | 쉬운 설명 | 구분하거나 함께 알아둘 내용 |
| --- | --- | --- |
| SlipKit | 전표의 모양을 만들고, 값을 입력하고, PDF로 출력하는 기능 묶음입니다. | 다른 프로그램 안에 넣어 사용하는 구성 요소이며 독립 업무 시스템 전체를 뜻하지 않습니다. |
| 호스트 애플리케이션 | SlipKit을 자기 화면에 넣어 사용하는 웹사이트나 업무 프로그램입니다. | 로그인, 서버 저장, 권한 관리처럼 SlipKit 밖의 기능은 호스트 애플리케이션이 담당합니다. |
| 디자이너 | 전표 양식의 페이지, 요소, 파라미터와 출력 규칙을 편집하는 화면입니다. | `SCR-001`부터 `SCR-013`, `SCR-017`에서 화면을 나누어 설명합니다. |
| 작성 폼 | 완성된 양식에 실제 값을 입력하고 전표를 만드는 화면입니다. | 양식 구조를 바꾸는 디자이너와 구분합니다. `SCR-014`를 참고합니다. |
| 뷰어 | 이미 만들어진 전표를 수정하지 않고 확인하는 화면입니다. | 값 입력과 발행 기능은 제공하지 않습니다. `SCR-015`를 참고합니다. |
| 공개 계약 | SlipKit을 사용하는 다른 프로그램이 의존해도 되는 이름, 입력, 출력과 동작입니다. | 내부 구현은 바꿀 수 있지만 공개 계약은 호환성 검토 없이 바꾸지 않습니다. `IF` 문서를 참고합니다. |
| 생명주기 | 데이터나 화면이 만들어진 뒤 변경되고 사라질 때까지 거치는 단계입니다. | 생성 시점, 변경 주체, 저장 시점과 삭제 조건을 함께 확인합니다. |

## 화면과 편집

| 용어 | 쉬운 설명 | 구분하거나 함께 알아둘 내용 |
| --- | --- | --- |
| 도구 모음 | 추가, 복사, 실행 취소, 미리보기처럼 화면 전체에 적용하는 명령을 모은 영역입니다. | 디자이너의 도구 모음은 `SCR-017`에서 버튼별로 설명합니다. |
| 탐색 패널 | 페이지, 요소와 파라미터의 목록을 보고 편집 대상을 고르는 왼쪽 영역입니다. | 선택한 대상에 따라 속성 패널의 내용이 바뀝니다. |
| 캔버스 | 전표가 출력될 위치와 크기를 보면서 요소를 배치하는 가운데 작업 영역입니다. | 실제 PDF 자체가 아니라 편집 화면입니다. `SCR-002`를 참고합니다. |
| 속성 패널 | 현재 선택한 양식, 페이지, 요소 또는 파라미터의 값을 바꾸는 오른쪽 영역입니다. | 선택 대상별 입력 항목은 각 하위 화면 설계에서 설명합니다. |
| 요소 | 글, 입력값, 이미지, 바코드, 선, 도형, 그리드처럼 페이지 위에 놓는 한 개의 구성물입니다. | 공통 위치와 모양은 `DAT-004`, 종류별 값은 `DAT-005`를 참고합니다. |
| 선택 대상 | 현재 사용자가 고른 양식, 페이지, 요소, 셀 또는 파라미터입니다. | 속성 패널과 사용 가능한 명령은 선택 대상에 맞게 바뀝니다. |
| 모달 | 현재 화면 위에 열려 입력을 마치거나 취소하기 전까지 뒤쪽 작업을 막는 창입니다. | 수식, 조건부 서식, 이미지, 저장·불러오기 창이 해당합니다. |
| 실행 취소 기록 | 사용자가 문서를 바꾼 순서를 저장한 목록입니다. | 실행 취소는 직전 변경 전 상태로, 다시 실행은 취소했던 다음 상태로 이동합니다. |
| 격자 | 캔버스에만 보이는 모눈입니다. 요소의 위치를 맞추는 데 사용합니다. | 파일에 저장하는 표 요소인 **그리드**와 다릅니다. |
| 눈금자 | 캔버스 위쪽과 왼쪽에 표시하는 mm 단위 기준자입니다. | 출력물에 포함되지 않습니다. |
| 미리보기 | 현재 양식과 샘플 값으로 PDF 출력 결과를 미리 확인하는 상태입니다. | 편집 캔버스와 실제 출력 결과가 같은 규칙을 쓰는지 확인하는 용도입니다. |

## 양식과 전표

| 용어 | 쉬운 설명 | 구분하거나 함께 알아둘 내용 |
| --- | --- | --- |
| 양식 | 아직 실제 업무 값이 들어가지 않은 전표의 틀입니다. | 페이지, 요소, 파라미터와 출력 규칙을 포함합니다. `DAT-002`를 참고합니다. |
| 전표 | 양식에 실제 값을 입력한 문서입니다. | 전표에는 사용한 양식의 사본과 입력값이 함께 들어갑니다. `DAT-003`을 참고합니다. |
| 발행 | 입력을 마친 전표에 무결성 정보를 기록하고 더 이상 수정하지 못하게 확정하는 작업입니다. | 단순 저장이나 PDF 출력과 다릅니다. 발행에 실패하면 편집 가능한 상태를 유지합니다. |
| 양식 페이지 | 디자이너에서 사용자가 만드는 원본 페이지 한 장입니다. | 반복 그리드 때문에 한 양식 페이지가 여러 출력 페이지를 만들 수 있습니다. |
| 출력 페이지 | 페이지 배치 계산을 마친 뒤 실제 PDF에 만들어지는 한 장입니다. | 양식 페이지와 항상 일대일로 대응하지 않습니다. |
| 저장 | 양식이나 전표를 나중에 다시 열 수 있도록 보관하는 작업입니다. | 발행과 달리 문서를 확정하거나 잠그지 않습니다. |
| 불러오기 | 저장해 둔 양식이나 전표를 읽어 현재 화면에 여는 작업입니다. | 읽기나 검증에 실패하면 현재 편집 중인 내용을 유지합니다. |
| 내보내기·가져오기 | 문서를 파일로 내려받거나 사용자가 고른 파일에서 읽는 작업입니다. | 브라우저 저장소에 보관하는 저장·불러오기와 구분합니다. |

## 값과 계산

| 용어 | 쉬운 설명 | 구분하거나 함께 알아둘 내용 |
| --- | --- | --- |
| 파라미터 | 전표에 입력할 값 한 종류를 정의한 항목입니다. | 거래처명, 작성일, 품목 목록처럼 양식에서 사용할 값을 정의합니다. `DAT-006`을 참고합니다. |
| 키 | 파라미터나 페이지를 파일과 수식에서 구분하는 변하지 않는 이름입니다. | 화면에 보여 주는 **표시 이름**과 다릅니다. |
| 표시 이름 | 파라미터를 사용자에게 보여 줄 때 쓰는 이름입니다. | 표시 이름이 없으면 키를 대신 표시합니다. |
| 값 | 한 전표에서 파라미터에 실제로 입력한 내용입니다. | 문자, 숫자, 날짜, 참·거짓 또는 목록이 될 수 있습니다. |
| 샘플 값 | 양식을 편집하면서 계산과 반복 출력을 확인하기 위해 넣는 예시 값입니다. | 실제 전표 값이 아니며 양식 편집과 미리보기에 사용합니다. |
| 하위 필드 | 목록 파라미터의 항목 하나가 가지는 세부 값입니다. | 품목 목록의 품명, 수량, 단가처럼 한 항목 안의 열을 정의합니다. |
| 직접 입력 | 요소나 셀에 양식 작성자가 고정해서 적는 글입니다. | 파라미터 값이나 수식 계산 결과와 구분합니다. |
| 수식 | 입력값을 계산하거나 조합해 표시할 값을 만드는 식입니다. | 문법 검사와 값 계산은 별도 단계이며 `FNC-004`, `FNC-005`를 참고합니다. |
| 계산 문맥 | 수식을 계산할 때 사용할 수 있는 현재 값과 예약된 참조의 모음입니다. | 같은 수식이라도 항목이나 출력 페이지에 따라 계산 문맥이 달라질 수 있습니다. |
| 조건식 | 조건부 서식을 적용할지 판단해 참 또는 거짓을 만드는 수식입니다. | 표시할 값을 만드는 일반 수식과 목적이 다릅니다. |
| 조건부 서식 | 값이나 조건식 결과에 따라 글자색이나 배경색을 바꾸는 규칙입니다. | 원래 요소 값은 바꾸지 않고 출력 모양만 바꿉니다. |
| 정규화 | 뜻은 같지만 표기가 다른 입력을 한 가지 저장 형태로 맞추는 처리입니다. | 예를 들어 유니코드 조합 방식이나 생략 가능한 기본값을 일관된 형태로 맞춥니다. |
| 마이그레이션 | 이전 파일 형식의 데이터를 현재 형식으로 바꾸는 처리입니다. | 지원하지 않는 형식까지 임의로 고치는 작업은 아닙니다. |
| 검증 | 값의 형식과 조합이 정해진 규칙을 지키는지 확인하는 처리입니다. | 검증을 통과해야 다음 처리나 저장을 진행합니다. |

## 그리드와 페이지 배치

| 용어 | 쉬운 설명 | 구분하거나 함께 알아둘 내용 |
| --- | --- | --- |
| 그리드 | 여러 행과 열로 값을 배치하는 표 요소입니다. | 캔버스의 모눈인 **격자**와 다릅니다. `SCR-006`, `DAT-005`, `DAT-007`을 참고합니다. |
| 셀 | 그리드 안의 한 칸입니다. | 직접 입력, 파라미터 또는 수식 중 하나로 내용을 정합니다. |
| 병합 | 양식에서 정한 여러 셀을 하나의 셀처럼 만드는 설정입니다. | 데이터 값에 따라 달라지는 **데이터 자동 병합**과 다릅니다. |
| 데이터 자동 병합 | 연속한 항목의 값이 같을 때 출력 결과에서 셀을 이어 보이게 하는 기능입니다. | 양식의 고정 셀 병합을 바꾸지 않습니다. |
| 행 구간 | 반복 그리드에서 같은 출력 역할을 하는 연속한 원본 행의 범위입니다. | 페이지 시작, 항목, 페이지 끝 등의 역할을 가집니다. |
| 항목 구간 | 목록의 항목 하나마다 반복해서 출력하는 행 구간입니다. | 반복 그리드마다 하나만 둡니다. |
| 항목 인스턴스 | 실제 목록 값 하나를 사용해 출력 페이지에 배치한 항목 구간 한 벌입니다. | 양식의 원본 행이 아니라 계산 뒤 만들어진 결과입니다. |
| 빈 항목 | 목록 값은 없지만 최소 표시 개수를 채우기 위해 만든 항목 인스턴스입니다. | 입력값이 없으므로 셀에는 빈 값이나 양식의 고정 내용이 표시됩니다. |
| 흐름 영역 | 반복 항목을 위에서 아래로 채울 수 있는 페이지 안의 세로 범위입니다. | 용지 전체가 아니라 여백과 다른 고정 요소를 고려한 영역입니다. |
| 자동 확장 | 항목 수와 남은 공간에 맞춰 필요한 만큼 출력 페이지를 늘리는 방식입니다. | 한 양식 페이지가 여러 출력 페이지를 만들 수 있습니다. |
| 고정 페이지 | 한 출력 페이지에 넣을 항목 수를 정해 같은 단위로 페이지를 나누는 방식입니다. | 정한 항목이 들어갈 공간이 없으면 배치 오류가 발생할 수 있습니다. |
| 페이지 계획 | 양식 페이지와 반복 항목을 어느 출력 페이지의 어느 위치에 놓을지 미리 계산한 결과입니다. | PDF를 그리기 전에 `FNC-007`, `FNC-008`에서 계산합니다. |

## 출력과 자원

| 용어 | 쉬운 설명 | 구분하거나 함께 알아둘 내용 |
| --- | --- | --- |
| 렌더링 | 양식과 값을 화면 또는 PDF에서 볼 수 있는 모양으로 만드는 처리입니다. | 데이터 검증, 페이지 계획, 글 배치와 이미지 처리를 거쳐 결과를 만듭니다. |
| 글 배치 | 정해진 너비 안에서 글을 줄로 나누고 맞춤과 높이를 계산하는 처리입니다. | 캔버스와 PDF가 같은 규칙을 사용해야 합니다. `FNC-010`을 참고합니다. |
| 자원 | 문서가 사용하는 이미지나 글꼴처럼 본문과 별도로 관리하는 데이터입니다. | 자원 식별자로 참조하며 `DAT-009`를 참고합니다. |
| 포함 이미지 | 이미지 데이터가 문서 안에 직접 들어 있는 상태입니다. | 외부 주소에 의존하지 않아 발행된 전표에서도 사용할 수 있습니다. |

| 대체 글꼴 | 요청한 글꼴을 사용할 수 없을 때 대신 사용하는 글꼴입니다. | 언어와 실행 환경에 따라 선택 결과가 달라지지 않도록 규칙을 둡니다. |

## 코드 표기를 만났을 때

설계서의 화면 설명은 사용자가 이해할 수 있는 이름을 사용합니다. 다만 데이터와 인터페이스 설계에서는
정확한 파일 형식과 호출 방법을 정의해야 하므로 `pages`, `values`, `render` 같은 코드 표기가 나올 수
있습니다. 이 경우 같은 표의 의미 열이나 앞뒤 설명을 먼저 읽고, 코드 표기만으로 동작을 추측하지
않습니다.

이 문서에 없는 용어나 같은 단어가 서로 다른 뜻으로 쓰인 곳을 발견하면, 해당 설계서만 고치지 않고
이 용어 해설과 관련 설계서를 함께 갱신합니다.
