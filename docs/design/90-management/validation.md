# 설계 문서 검증 기준

최종 갱신: 2026-09-28

## 개요

`pnpm verify:design`이 확인하는 구조 규칙과 사람이 검토해야 하는 내용 기준을 정의합니다. 자동 검사는
문서의 형식과 연결을 보장하고, 구현과 설명의 의미가 같은지는 작성·검토 과정에서 별도로 확인합니다.

## 변경 이력

| 날짜 | 구분 | 변경 내용 |
| --- | --- | --- |
| 2026-09-28 | 신규 작성 | 문서 구조, 식별자, 변경 이력, 링크와 Mermaid의 자동·수동 검증 기준을 정의했습니다. |

## 자동 검사

`pnpm verify:design`은 다음 항목을 검사합니다.

- 필수 디렉터리와 유형별 템플릿이 존재합니다.
- 등록부의 설계 대상이 50~80개이고 식별자와 파일 경로가 중복되지 않습니다.
- 식별자 접두어, 디렉터리와 파일명이 문서 유형에 맞습니다.
- 작성 상태가 `예정`이 아닌 대상은 등록한 경로에 파일이 존재합니다.
- 실제 설계서의 제목 식별자와 파일명이 등록부와 일치합니다.
- 모든 Markdown 문서는 제목 뒤 첫 두 절로 `개요`와 `변경 이력`을 둡니다.
- 최종 갱신 날짜가 변경 이력에 있고 같은 날짜의 이력 행이 중복되지 않습니다.
- 상대 링크와 이미지 경로가 실제 파일을 가리킵니다.
- Mermaid 코드 블록이 닫혀 있고 지원하는 다이어그램 선언으로 시작합니다.

## 내용 검토

- 요구사항, 파일 명세, 설계 결정, 아키텍처와 실제 코드의 동작을 함께 대조합니다.
- 정상 흐름뿐 아니라 주요 분기, 실패, 복구와 상태 변경을 설명합니다.
- 화면의 버튼·이벤트가 호출 기능, 사용하는 데이터와 오류 처리에 연결됩니다.
- 공개 API와 이벤트는 입력·출력, 동기·비동기 처리, 생명주기와 호환성 경계를 포함합니다.
- 같은 개념은 용어 사전의 이름으로 일관되게 작성합니다.
- 실제 화면 이미지는 지정한 화면 크기에서 조작 흐름과 상태를 확인한 뒤 추가합니다.

## 실행 명령

corepack pnpm verify:design
