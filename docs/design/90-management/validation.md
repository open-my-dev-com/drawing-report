# 설계 문서 검증 기준

최종 갱신: 2026-09-28

## 개요

`pnpm verify:design`이 확인하는 구조 규칙과 사람이 검토해야 하는 내용 기준을 정의합니다. 자동 검사는
문서의 형식과 연결을 보장하고, 구현과 설명의 의미가 같은지는 작성·검토 과정에서 별도로 확인합니다.

## 자동 검사

`pnpm verify:design`은 다음 항목을 검사합니다.

- 필수 디렉터리와 유형별 템플릿이 존재합니다.
- 등록부의 설계 대상이 50~80개이고 식별자와 파일 경로가 중복되지 않습니다.
- 식별자 접두어, 디렉터리와 파일명이 문서 유형에 맞습니다.
- 작성 상태가 `예정`이 아닌 대상은 등록한 경로에 파일이 존재합니다.
- 실제 설계서의 제목 식별자와 파일명이 등록부와 일치합니다.
- 모든 Markdown 문서는 제목 뒤 첫 두 절로 `개요`와 `변경 이력`을 둡니다.
- 최종 갱신 날짜가 변경 이력에 있고 같은 날짜의 이력 행이 중복되지 않습니다.
- 상대 링크와 이미지 경로가 실제 파일을 가리킵니다.
- Mermaid 코드 블록이 닫혀 있고 지원하는 다이어그램 선언으로 시작합니다.
- 모든 화면 설계서는 설계 범위, 진입·종료 조건, 화면 이미지, 화면 구성, 이벤트, 상태, 오류, 전이,
  관련 계약과 근거 절을 정해진 순서로 둡니다.
- 모든 화면 설계서는 자신의 `SCR-###` 식별자를 포함한 번호 주석 PNG를 사용합니다.
- 화면 구성 번호는 1부터 빠짐없이 이어지며, 각 번호는 문서에 연결한 주석 PNG의 SVG 원본 가운데
  하나에 실제로 표시되어야 합니다.
- 화면 구성, 이벤트, 상태, 오류와 전이 표는 정해진 머리말과 내용 행을 하나 이상 포함합니다.
- 사용자 동작 셀에 가운데점, `~하거나` 또는 이전·다음처럼 결과가 다른 동작을 묶지 않습니다.
- 기능 설계에는 자료형·단위·필수 여부·기본값·보장을 구분한 입력·출력 표, 단계별로 읽는 값·변경값·
  다음 단계를 적은 정상 처리 표와 동시 실행·반복 호출 절이 있어야 합니다.
- 데이터 설계에는 소유 계층, 경로·자료형·필수 여부·기본값·범위·의미를 구분한 구조 표, 연결 키와
  변경·삭제 처리를 적은 관계 표, 불변 조건, 생명주기와 버전·검증 절이 있어야 합니다.
- 인터페이스 설계에는 제공자·소비자, 호출 조건, 입력과 결과를 설명하는 계약 표, 동기·비동기 처리,
  생명주기, 반복·동시 호출, 오류와 호환성 경계가 있어야 합니다.
- 오류 설계에는 판정·검출, 계층 간 전달과 보존·복구를 정의한 표와 각 표의 실제 내용이 있어야 합니다.

## 내용 검토

- 요구사항, 파일 명세, 설계 결정, 아키텍처와 실제 코드의 동작을 함께 대조합니다.
- 정상 흐름뿐 아니라 주요 분기, 실패, 복구와 상태 변경을 설명합니다.
- 화면의 버튼·이벤트가 호출 기능, 사용하는 데이터와 오류 처리에 연결됩니다.
- 화면 구성 표의 각 번호가 이미지의 번호와 같은 실제 영역을 가리키는지 확인합니다.
- 화면에 보이는 모든 조작 항목이 이벤트 표에 하나씩 있고, 결과가 다른 동작을 한 행에 묶지 않았는지
  확인합니다.
- 상위 화면은 영역의 배치와 영역 간 변화를, 하위 화면은 자기 영역의 내부 조작을 맡는지 확인합니다.
  같은 버튼 설명이 상위·하위 문서에 중복되면 하위 문서에만 남깁니다.
- 하위 화면 이미지는 담당 영역을 알아볼 수 있는 크기로 보여 주고 내부 항목마다 독립된 번호를
  붙였는지 확인합니다.
- 각 상태는 진입 조건, 달라지는 표시와 허용 동작을 명시하고, 화면 구조가 달라지면 별도 이미지를
  제공하는지 확인합니다.
- 입력 필드가 아닌 파일, 저장소, 렌더링과 비동기 처리 오류도 표시 위치, 문서 처리와 복구 방법을
  명시하는지 확인합니다.
- `관련 속성`, `현재 상태`, `오류를 표시`처럼 구현자가 대상·조건·위치를 추측해야 하는 표현이 남지
  않았는지 확인합니다.
- 공개 API와 이벤트는 입력·출력, 동기·비동기 처리, 생명주기와 호환성 경계를 포함합니다.
- 화면 설명에 프로퍼티명, JSON 필드명과 이벤트명을 동작 설명 대신 사용하지 않았는지 확인합니다.
- 기능·데이터·인터페이스·오류 설계만 읽고도 처리 순서, 자료형과 범위, 호출 시점, 실패 시 보존값을
  결정할 수 있는지 확인합니다.
- 같은 개념은 용어 사전의 이름으로 일관되게 작성합니다.
- 실제 화면 이미지는 지정한 화면 크기에서 조작 흐름과 상태를 확인한 뒤 추가합니다.
