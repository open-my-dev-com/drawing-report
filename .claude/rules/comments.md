# 주석 규칙 — TSDoc (ADR-029/059)

- 주석은 코드의 **현재 동작**과, 코드만으로 드러나지 않는 **제약·이유**만 설명한다.
  자명한 코드를 다시 설명하지 않는다.
- 설계 결정 번호(`ADR-xxx`), 작업 항목 번호(`G-xx`·`F-xx`·`D-xx`·`Q-xx`), 개발 경위와
  이전 동작은 소스 주석에 적지 않는다 (ADR-059). 결정의 배경이 필요하면
  `docs/DECISIONS.md`에서 찾는다. 규칙 문서·일반 문서에서는 지금처럼 ADR 번호를 표기한다.
- 선언에 붙는 설명 주석(공개 API, 클래스 멤버, 인터페이스·타입 필드, 상수 등)은
  TSDoc 블록(`/** ... */`)으로 쓴다. 한 줄로 충분하면 `/** 설명 */` 형태.
- 코드 중간의 구현 설명(왜 이렇게 처리하는지 등)은 `//` 한 줄 주석을 쓴다 —
  TSDoc은 선언 설명 전용이다.
- 공개(export) 함수·메서드는 `@param`(매개변수마다)과 `@returns`를 기본으로 채운다.
  오류를 던지면 `@throws`로 조건을 명시한다. 반환이 없거나(void) 매개변수가 없으면
  해당 태그는 생략한다.
- `@remarks` `@defaultValue` `@example` 등 나머지 태그는 덧붙일 정보가 있을 때 쓴다.
- 형식은 `pnpm lint`(eslint `tsdoc/syntax`)로 검사한다 (ADR-030). 이 검사는
  오탈자 태그·JSDoc식 타입 중괄호·`@param 이름 - 설명`의 하이픈 누락 등을 잡는다.
  `@param`·`@returns` 누락은 작성·리뷰 때 확인한다.
- 주석 본문은 한국어 (언어 규칙과 동일).
- 새 코드도 동일하게 적용한다. 선언 위에 `//` 설명 주석을 새로 만들지 않는다.
