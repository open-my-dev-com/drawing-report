# 주석 규칙: TSDoc(ADR-029/059)

- 주석은 코드의 **현재 동작**과 코드만으로 알기 어려운 **제약·이유**만 설명합니다.
  코드에서 바로 알 수 있는 내용을 반복하지 않습니다.
- 설계 결정 번호(`ADR-xxx`), 작업 항목 번호(`G-xx`·`F-xx`·`D-xx`·`Q-xx`), 개발 경위와
  이전 동작은 소스 주석에 적지 않습니다(ADR-059). 결정의 배경은 `docs/DECISIONS.md`에서
  확인합니다. 규칙 문서와 일반 문서에서는 ADR 번호를 표기할 수 있습니다.
- 선언에 붙는 설명 주석(공개 API, 클래스 멤버, 인터페이스·타입 필드, 상수 등)은
  TSDoc 블록(`/** ... */`)으로 작성합니다. 한 줄이면 `/** 설명 */` 형태를 사용합니다.
- 코드 중간에서 처리 이유를 설명할 때는 `//` 한 줄 주석을 사용합니다. TSDoc은 선언을 설명할 때만
  사용합니다.
- 공개(export) 함수와 메서드는 각 매개변수의 `@param`과 `@returns`를 기본으로 작성합니다.
  오류를 던지면 `@throws`로 조건을 명시합니다. 반환값이나 매개변수가 없으면 해당 태그를 생략합니다.
- `@remarks`, `@defaultValue`, `@example` 등은 필요한 정보를 추가할 때만 사용합니다.
- `pnpm lint`의 eslint `tsdoc/syntax` 규칙으로 형식을 검사합니다(ADR-030). 이 검사는 잘못된 태그,
  JSDoc 방식의 타입 중괄호, `@param 이름 - 설명`의 하이픈 누락 등을 검출합니다.
  `@param`과 `@returns` 누락은 작성과 검토 단계에서 확인합니다.
- 설명 문장은 자연스러운 한국어의 합니다체로 작성합니다. 문장 일부만 기계적으로 바꾸지 않고
  전체 의미와 흐름을 확인합니다. 구획 제목과 `@param`의 대상 설명처럼 완결된 문장이 아닌 짧은
  항목은 뜻이 분명한 명사구로 작성할 수 있습니다.
- 작업 요청, 수정 전 동작, 방어적 해명, 코드에서 이미 드러나는 설명은 남기지 않습니다.
- 새 코드에도 같은 기준을 적용합니다. 선언 위에 `//` 설명 주석을 새로 만들지 않습니다.
