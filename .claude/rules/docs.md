# 문서 규칙

- **DECISIONS.md**: 새 설계 결정은 다음 ADR 번호로 추가합니다. 기존 결정을 번복할 때는 삭제하지 않고
  후속 ADR에서 변경 내용을 기록하며, 두 ADR에 서로의 번호를 적습니다. ADR 번호는 코드와 문서가
  참조하는 안정적인 식별자이므로 재사용하지 않습니다. **예외**: 릴리스 경계에서 문서를 정리할 때
  완전히 대체되어 참조가 남지 않은 ADR은 제거할 수 있습니다. 제거한 번호는 빈 번호로 남기고 정리
  내용을 변경 기록 머리말에 적습니다. `DECISIONS.md`와 `REQUIREMENTS.md`가 어긋나면
  `DECISIONS.md`를 기준으로 수정합니다.
- **REQUIREMENTS.md**: ADR을 추가하거나 변경할 때 함께 갱신합니다. 확정된 요구사항만 기록하고,
  진행 과정과 날짜별 작업 이력은 `ROADMAP.md`에 기록합니다.
- **OPEN-QUESTIONS.md**: 기존 요구사항과 결정으로 답할 수 없는 공개 API·파일 형식·데이터 보존·제품
  동작에 관한 새 쟁점만 다음 Q 번호로 추가합니다. 사용자 확인 전에는 결정된 내용처럼 작성하지
  않습니다. 해결된 쟁점은 삭제하지 않고 해당 ADR에 연결합니다. 필요한 경우 간결한 색인 표로
  정리할 수 있습니다.
- **SPEC.md**: `.slip` 형식의 공개 명세입니다. 구현(`@omdc-slipkit/core`)과 어긋나면 SPEC을 기준으로
  구현을 수정합니다. 형식을 변경할 때는 Zod 스키마, 마이그레이션, JSON Schema도 함께 갱신합니다.
  자세한 절차는 core 규칙을 따릅니다.
- **ROADMAP.md**: PR에 포함할 때는 병합 후의 현재 상태와 다음 작업을 기록합니다. 작업 브랜치의 상태를
  "진행 중"으로 남기지 않습니다. 이 문서는 다음 세션이 작업 상태를 파악하는 기준입니다.
- 설계 문서는 한국어로 작성하고 상단의 "최종 갱신" 날짜를 유지합니다. 공개 문서인 저장소 `README`와
  `docs/guide/*`는 영어판(`*.md`)을 기준으로 한국어판(`*.ko.md`)과 일본어판(`*.ja.md`)을
  일치시킵니다(ADR-066).
